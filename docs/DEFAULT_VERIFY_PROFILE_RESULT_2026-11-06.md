# 当前默认主验证路径：耗时分析与下一项选择

2026-11-06。完成[冻结计划](DEFAULT_VERIFY_PROFILE_PLAN_2026-11-06.md)，
结论为 **VALID_BOUNDED_OBSERVATION / SELECT_GDN_BF16_INPUT_PROJECTION**。
这是下一项候选的工程选择；没有实现或接受新的性能优化。

## 主要发现

主验证仍是MTP轮次的主要耗时：完整head占75.6–75.8%，subset占
85.6–85.8%。两head主验证均约73.6–77.2ms/轮；subset主要缩短
草稿和extend，主验证已成为更明显的剩余热点。

这里的比例不含prefill和普通尾部decode，也不是全部HTTP耗时比例。
45K的约32秒TTFT没有被主验证分析解释或优化。四个请求的MTP轮数
依次74/71/77/73；每一轮均保留，首次与后续均值另存原始分析。

也不能把整个23ms当成这些准备内核的优化空间。

因此可明确优先级：大投影是当前值得投入的热点族；GDN输入/输出
约21ms，routed MoE两次投影约16.3–16.9ms。GDN状态递推和QSA的
几个前处理小算子没有显示出同等规模的已测空间。

## 选择的下一项及停止边界

下一项建议只制作一个**GDN大输入投影的BF16 small-M候选**，先限
主模型verify的T=4、qkv/z调用点，其他路径保持原实现。该选择结合
耗时、可保持精度及局部改动范围；MoE投影仍是同级热点，并未证明
GDN是唯一硬件瓶颈。

具体假设来自[当前内核](../src/model/small_m_gemm.cu)：每个输出warp
在乘加循环里重复将共享BF16输入转成FP32。可以尝试在线程块加载
输入时只转换一次，将FP32输入放入共享内存，各输出warp复用；
权重仍BF16，保留每行F32x2 FMA顺序、shuffle归约和输出BF16舍入。
这减少重复转换指令，不减少权重字节。共享内存读取量及占用会增大，
可能抵消收益，当前没有硬件计数器证据证明转换是限制因素。

只在GDN调用点选择，不能仅按N/K全局改派：QSA的q/g投影可能拥有
相同形状。也不同时混入out_proj、MoE、HC、FP8或CUDA Graphs。
输入段15.45ms包含不在首候选内的a/b小投影，不能全部算成可节省
时间。若整个输入段能削去20%耗时，约3.1ms/轮只是支持继续投入
的上限式估算；首候选实际覆盖更窄，收益必须由HTTP验证。

下一阶段应先做一次有界HTTP可行性门，达到事前收益条件才进入
独立逐行数值/状态和五档性能质量验收。保持精度与范围内效果均未
证明之前，不改变默认；失败即归档，不因差值小自动扩样或再枚举
大量内核参数。本轮只完成选择，尚未实施这项候选。

其他方向本轮不启动：现有MoE已设备端分组，不重复开发；FP8 shadow
已有实现，但启用会改变权重量化且增加驻留副本；GDN状态重写和QSA
前处理融合可用空间较小；CUDA Graphs缺少当前GPU空闲证据。
静态cuobjdump显示已执行MAXM=4内核REG40、STACK0、LOCAL0，没有
以消除spill为首项任务的依据，也不能据此推导动态occupancy。

## 观察扰动和证据边界

| head / 上下文 | 粗计时解码墙钟变化 | 细计时解码墙钟变化 |
|---|---:|---:|
| full / 1K | +0.818% | +7.682% |

| subset / 1K | +0.657% | +9.275% |
| subset / 45K | +0.430% | +8.443% |

变化均相对同head的本轮普通HTTP，各组只有一次服务启动和每上下文
一次请求，不证明差值全部由计时开关造成，也不提供统计误差界。
粗观察适合阶段占比，细观察用于组别筛选；不将细组数值冒充无插桩
纯kernel时间，不相减制造精确CPU/GPU等待结论。

CUDA event跨越的是流上时间，可能含提交间隙；没有带宽饱和、GPU
idle、逐kernel完整性或GPU硬件瓶颈证明。细计时的Report与事件
销毁另有扰动；本轮未同时开启LAYER_TIMING，避免把它们计入head。
输出打印0.01ms/0.1ms的逐项累计舍入界已记入analysis.json；不同
上下文/head之间的小差值不据此作因果结论。
