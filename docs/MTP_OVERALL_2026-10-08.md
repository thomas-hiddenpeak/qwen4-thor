## Goal 与有界范围

先建立完整循环成本账，再依据每实际输出 token 的成本选择优化。
包含初始化、草稿循环、验证准备/模型/读回、接受/回滚、draft 状态
追赶、调度等待及内容发送。不能只看某个算子变快，忽略接受率、
额外验证计算、最后一步截断、TTFT 或整请求耗时。

诊断阶段不改变数学、张量形状、k、精度、既有同步与状态推进。
诊断完成后最多实施两个候选，每个在改动前另冻结具体合同、输入、
数值和性能验收范围；没有证据支持的方向不强行实施。候选失败
保留原记录，不追加有利采样或放宽门槛。阶段成功可以是有证据的
NO_GO，不承诺所有子阶段都能加速。

## 初始代码审查与待验证方向

HTTP S1 实际走 `MtpSpeculativeStepMulti`。旧 Q4T_MTP_TIMING 仅有
三段低精度 host 日志，没有请求、步号、接受或输出截断绑定，且
正式 runner 清理该环境变量，不能直接承担本阶段分析。

静态发现的候选池尚未按实际耗时排序，也尚未实施：

- 草稿已知 host positions，但 attention 仍读回 positions 并同步；
  可研究传递实际最大位置，保持所有行与候选索引范围不变。
- extend 每步仍为 gather offsets 分配和释放临时 GPU 内存；
  可研究按同 stream 生命周期复用已有缓冲，保留现有 gather kernel。
- B1 验证每步复制整个历史；可研究借用只读 history，保留 n-gram
  读取语义与请求线程所有权。
- B1T4 主验证中，36 个线性 attention 层共调用 216 次临时分配及
  216 次释放；可研究独立小缓冲复用，不能与 GEMM scratch 重叠。

48 个主模型 MoE 层的 counts 读回是现有专家调度的数据依赖，不能
单独删掉。把它改成新的 GPU 调度路径会扩大分组/量化/舍入合同，
不自动纳入上面的小范围编排候选。初始化尾部机会保留为候选池
之外的已有研究结论，本轮先按完整 decode 成本确定优先级。

## 诊断设计

新增默认关闭 `Q4T_MTP_CYCLE_TIMING=1`，仅 S1 文本 HTTP 请求启用。
请求持有有界 collector，每个 speculative step 有固定容量记录；
实际 response_id、位置、k、B、verify/extend 行数、接受 0..k、
引擎返回数与实际 generated/SSE token-piece 写出数分别保存。
超界、失败、不完整不能当有效轨迹；计时失败不改变模型计算。

请求提交、scheduler 取出、模型锁、引擎阶段、完成通知、请求唤醒、
输出和状态推进都用同一 steady_clock 时域。现有同步边界前后
区分清楚：模型调用返回可能仅是提交完成，完成态时间依赖现有
draft/argmax/seed 读回，不能把提交耗时当 GPU 执行耗时。

细节计时通过显式 step scope 激活的线程局部上下文记录，作用域
退出恢复；只读观察 positions/counts 读回、线性临时区分配/释放、
gather 分配/释放及草稿子调用。细节属于父区间内部，不重复相加。
默认无上下文时不采时钟，不调用 CUDA 计时 API；新增 host 调用
仍可能有开销，需与同二进制关闭诊断组比较。

本轮循环诊断不新增 CUDA events 或同步。开启组同时启用已经
验证的初始化计时，补全请求前半段；初始化的 host/stream 时钟
继续分别解释，不与循环 host 时间跨时钟求和。日志集中在请求
结束后输出，准备/收集成本声明范围，不声称观察零开销。

4. 同二进制开启 cycle/init 诊断的五档，各 3 次。

## 主要指标与后续候选门槛

保留全部三次客户端 TTFT、decode 秒数、整请求耗时；汇总 decode
使用 765 / 三次 decode 秒数之和。逐步报告接受 0..3 分布、平均
接受 draft 数、实际交付 token/步、验证行/交付 token，以及每阶段
总 host 成本/实际交付 token。另列引擎 returned 口径与最后一步
截断浪费，不能用 1+a 代替实际交付量。

区分首步、后续步骤及最终截断步。首步可能一次产生多个 token，
客户端 TTFT 后剩余首步输出不是一个完整后续 step；不能直接拿
内部总时间重建客户端 decode。五档输入内容不同，接受率差异也
不能直接归因为上下文长度。只有整个服务第一条请求属于启动后
首请求，其他各档第一条不称冷启动。

每个选中的候选先冻结，再按质量 11 条第一测、受影响直接数值/
状态及旧新完整 k3 对照、关闭诊断五档各三次执行；复用本阶段
关闭组或已接受候选基线。内存/提交编排优化以同形 exact 为目标，
不能只比较候选内部回放而漏掉旧新共同变化。五档 TTFT、decode
秒数和整请求的候选后两次均不超过基线后两次最大值，作为既有
严格筛查；三次仍不足以证明稳定尾延迟或微小差异的因果。

缺陷合同、运行时数值接入、HTTP 质量和性能结论分别记录。普通/
MTP 跨模式数值边界尚未闭合，旧 NO_GO 继续有效；本阶段工具和
局部候选通过不自动批准默认启用。
