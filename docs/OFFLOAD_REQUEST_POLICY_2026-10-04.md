## 当前结论

本候选为 NO_GO：混合请求继承筛查与完整六档均未通过冻结速度门槛。
off/on 两组各 21 请求的输出、路径、容量、身份和清理合同均通过。

## 目标、实现与回退边界

目标是保留已有长请求 prefill 收益，同时避免短请求使用新分区。
阈值来自此前样本和诊断，并非独立验证得到的最优阈值。
完整 tokenized 输入 <=8192 使用 legacy，>8192 使用 min_new_csr_v1。
不可变请求上下文穿过 HTTP 调度、三条 prefill 模型入口、decoder 和 MoE。
所有外层 chunk 及长请求单 token 尾部沿用完整请求的选择。
实际 decode 继续现有全局路径，不把 T=1 一概当作 decode。
HTTP 持有同一请求上下文；直接模型 API 调用方负责各块传递相同身份。
本轮未向 ModelSequence 加持久策略状态，不保证拦截调用方跨块主动换身份。

开关 Q4T_MOE_REQUEST_PARTITION 默认 0。
开启要求 Q4T_MOE_PARTITION=1、Q4T_MOE_CHUNK_ORDER=0、单流文本、MTP 关闭。
正式 off 两开关均为 0，on 两开关均为 1，比较同一新 binary。
无显式请求上下文的非 HTTP 模型调用继续旧全局语义。
GEMM、精度、驱逐规则及缓存预算未改变；不宣称修复 decode 回退根因。
代码回退可关闭新开关；复现本轮 off arm 还必须同时关闭全局分区。
短请求选择 legacy 不会清除之前长请求留下的缓存状态。

## History：固定顺序与判定口径

序列 [16385,8192,8193,1024,45056,4096,8192] 连续三轮，off→on 各 21 发。
每发输出 256；arm 内保留服务和缓存，不在请求之间清缓存。
两个 8192 位点按位置 2 和 7 分别判断，不能混成六次样本。
每位置要求首轮 TTFT 不增、后两轮最大 TTFT 不增、三轮最低 decode 不降。
以下平均 TTFT 仅作描述，实际接受依据仍为上述逐位置冻结门槛。
本轮没有追加有利样本、放宽微小下降或用长档收益抵消短档失败。
TTFT 是客户端首 token 等待时间，包含接入、分词、排队和 prefill，
不是纯 prefill 计算时间。decode 速率按
(实际输出 token 数 - 1) / (请求总耗时 - TTFT) 计算，单独判断。

剩余 prefill 提升百分比。短请求恢复 legacy 仍未通过，说明仅按完整

代码中请求选择只改变分区模式，序列重置只清 KV/SSM/conv/PLE 等
序列状态，继续使用同一层的 MoEResidency。短请求因此继承此前长请求
及 decode 的 GPU/L2/mirror 历史。当前 history 没有保存可量化入口
缓存差异的完整快照；继承机制已知，其速度贡献仍未知。

权重读取、准备及主机/设备搬运是后续应测量的环节，但当前没有互斥
关键路径预算。GPU 补载计数不等于 SSD 读取；镜像写回是到 pinned RAM
的 D2H，不是 SSD 写入。上一已完成全范围分区实验的 200K/目标档，
后两次 GPU 补载约减半，而三次 PID 存储读取均值增加约 3.29%/3.54%。
两列各自比较 off/on，不能跨不同样本口径构造比例，更不是本轮 I/O 结果。
pread/swizzle/stage 计时嵌套、多 worker 并发，下一块准备又与当前 GPU
计算重叠；累计 host 时间不能直接相加成可消除的 prefill 墙钟时间。

后续因果研究建议依次为：

1. 在相同策略和负载下隔离真正 decode 的逐层日志开销，提前固定
   采样与退出规则，保留可审计性；不从本次正式时间中扣除估计成本。
2. 在匹配观测条件下对齐长→短入口缓存、recency 与真实路由需求，
   区分前驱状态影响和请求本身需求；已有 trace 可以优先离线分析。
3. 再用有界同一时间轴拆分未被计算隐藏的读取、H2D、mirror D2H 等待，
   有了可消除时间证据后再讨论单一优化候选。

这些是后续研究建议，未冻结或执行第二优化。本轮不承诺额外 10–20%。
详细来源和局限保留在 bottleneck-interpretation.json；旧诊断数据属于
不同源码、策略和插桩条件，不能代替当前六档或当前资源结论。
