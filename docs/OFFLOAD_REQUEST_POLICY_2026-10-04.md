## 目标与限制

先争取让已有长请求 prefill 收益通过完整验收：完整 tokenized 输入
不超过 8192 时沿用原分区，更长请求使用 `min_new_csr_v1`。
该阈值来自此前已用样本，不是独立验证得到的最优阈值；本候选是
缩小策略适用范围，不宣称修复 decode 回退的根因，也不宣称继续
降低已测长档 TTFT。原全范围策略的完整性能 NO_GO 保留。

请求策略必须作为显式不可变参数穿过调度与模型调用；不能使用当前
forward 长度判断，否则长请求的 8192-token 块和短尾会被错误关闭。
开关默认关闭；限定单流文本、MTP 关闭、真实 residency。
GEMM、精度、驱逐规则与缓存预算均不改变。

具体开关为 `Q4T_MOE_REQUEST_PARTITION=1`，要求
`Q4T_MOE_PARTITION=1` 和 `Q4T_MOE_CHUNK_ORDER=0`。正式 off 组
两个分区开关均 0，on 组均 1，比较同一新 binary 的旧路径与候选。
新开关只在 serve 构造请求上下文；非 HTTP 的默认模型调用继续
保持旧全局语义，不因设置新环境变量自动得到完整请求策略。
新增 layer0 请求记录在两组对称；旧全局分区的 decode 日志保留，
不能宣称所有日志开销完全相同，其成本计入实际端到端结果。
HTTP 路径在请求生命周期中持有同一不可变对象。显式模型 API 的
调用方负责在各块传递同一请求身份；本轮不向 ModelSequence 增加
持久策略状态，因此不承诺能拒绝外部调用方蓄意跨块替换上下文。

短请求会继承此前请求留下的缓存状态，旧分区不能保证恢复原缓存。
除升序六档外，预先冻结 8192/8193 边界、未测中间长度以及连续
长请求后短请求的挑战，分别验收输出、路径与速度。

## 工作阶段

实现包含不可变请求策略与三条 prefill 调用路径的参数传递、对称
layer0 执行记录、严格环境校验、有界冷态准备，以及固定继承序列。
直接验证已写入 8 项 host 合同和第三项真实权重数值合同（8 个
小形状 case）；保留此前两个数值合同不变。小形状携带完整请求标签
仅验证策略接入，不等同完整 8193-token 或整模型数值验证。
工具审计按所有 48 层和输出减一的 decode forwards 核对实际路径，
同一 prompt 跨轮/跨位置比较全文，速度仍按 7 个位置独立判断。

1. 成组完成请求策略、路径证据及验收工具，独立静态审查；冻结完整
   样本、条件、门槛和失败出口，形成可回退提交及干净 Thor 构建。
2. 第一项测试为 tools/evalscope 固定 11 题真实 HTTP。通过后才运行
   受影响的 host 合同、真实权重数值合同及边界/缓存继承挑战。
3. 继承筛查固定 `[16385,8192,8193,1024,45056,4096,8192]` 连续三轮，
   off/on 各 21 发，每发输出 256；同一位置跨三轮比较，两个 8192
   位置不混算。每个位置要求首轮 TTFT 不增、后两轮最大 TTFT 不增、
   三轮最低 decode 不降。有效 NO_GO 停止本候选后续模型请求。
4. 继承筛查全部通过后，同一 binary、16GiB host/cache 设置下完成
   五档加 261887 目标档，
   off/on 每档各三次。延续既有逐档 TTFT 与最低 decode 门槛；
   保留首次失败，不追加有利样本，不以长档改善抵消短档失败。
5. 完整通过才进行必要业务与生命周期交付检查；结论明确为 GO、
   NO_GO 或证据不足，分别记录数值、质量、性能和资源。
6. 只有本候选完整通过后，才冻结第二阶段单一候选：进一步减少
   prefill 权重搬运或镜像写回。此前讨论的额外 10–20% 是探索方向，
   不是性能承诺，也不是用来替代实测的完成标准。
