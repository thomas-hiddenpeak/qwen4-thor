# 真实生命周期与统一文件缓存的VMM对照（2026-10-20）

## 冻结范围与预算

用户授权补齐分配/释放轨迹，统一缓存起点后验证VMM。默认19ea保持。
采用同一已接受foundation构建对象独立链接runtime observer与VMM候选，
不再用全部分配持有至末尾的合成重放。无包装重链SHA必须精确等于
19ea；两个独立binary的身份见.q4t-work/vmm-compare-20261020/build.json。

最多3次模型加载：先一次冷缓存原版完整轨迹与1K HTTP；通过合同和
轨迹核验后，固定原版→VMM两侧各一次相同热文件缓存的真实模型启动
及同1K HTTP。正常退出才接受释放/质量；环境中断保留未闭合轨迹。
不追加样本、不寻找有利chunk/缓存量、不作性能或统计非劣结论。

捕获阶段先运行两侧各一次32MiB+1真实链接合同：跨2MiB边界H2D/D2H、
异步写入后释放、stream-ordered分配/释放及host两种分配/释放。既有
VMM局部失败回滚按未变block.h身份复用。捕获阶段用单NVML lease。
两热侧由一个supervisor持续持有跨会话锁，每侧独立guard完整启动至
清理；原版预期ENV_ABORT也保留，只有其进程清理可确认才允许进入
预先冻结的另一侧，不重复失败侧。监控仍默认NVML/5秒，资源2秒。

## 轨迹合同

包装应用直接调用的cudaMalloc/cudaFree、host alloc/free、mallocAsync/
freeAsync、stream/device synchronize与event record/synchronize；逐行
序号、调用id、线程、指针、bytes、flags、stream、调用点、begin/end、
返回码和monotonic。不串行化CUDA调用，仅串行写日志。包括真实计算、
权重上传与退出，保留临时对象释放时机。CUDA/cuBLAS内部未通过应用
链接符号的分配不在轨迹范围，不能把账本总量当驱动物理占用。
async free成功是提交释放，不冒充物理回收完成，额外保留完成事件。

VMM候选仅替换>=32MiB同步cudaMalloc及对应cudaFree：2MiB物理块
映射连续VA，Free前显式device synchronize确保解除映射前完成使用。
小块/pinned/async分配保持原接口；遇到VMM指针被freeAsync直接拒绝
终止该研究进程，避免未经验证的异步释放路径。候选不是生产通用分配器。

## 统一文件缓存起点

每侧先调用已有最多三次定向prepare_target_cache，要求全部模型payload
零驻留；再只读同一完整expert文件清单（总字节<=64GiB）至EOF。
启动前两次cachestat要求逐文件向量精确匹配：选中文件ceil(size/page)
全驻留，其他.safetensors/.bin零驻留。残留、缺页、未知、额外文件均
拒绝加载，不放宽门。5项纯host门测试通过。

同时记录MemFree/MemAvailable/KReclaimable、vmstat、buddyinfo。
这统一了**模型文件的页驻留起点**，不能重置驱动页池、页阶数、物理
碎片和全部后台内存；一次固定顺序对照不宣称这些因素相等或统计因果。
本任务接受结论限于实测配置及覆盖合同，不自动替换默认程序。

实现：tools/verify/vmm_compare；CUDA语义依据本机13.3头文件及
[CUDA13.3运行时内存接口](https://docs.nvidia.com/cuda/archive/13.3.0/cuda-runtime-api/group__CUDART__MEMORY.html)、
[VMM接口](https://docs.nvidia.com/cuda/archive/13.3.0/cuda-driver-api/group__CUDA__VA.html)。

## 冷捕获门结果

capture-v1 COMPLETED，两侧真实链接短合同通过；原版1K输入/7输出，
精确710003，服务正常退出。84940条记录/42470完整调用，3855分配、
3853释放，所有捕获API返回成功且无未知释放/未闭合调用。
2357次async分配/释放提交成对；host全部显式释放。退出前留下两块
993280 bytes device缓冲，调用点及源码定位ArgmaxBf16Rows进程级static
缓存，不把它们记成显式释放或驱动泄漏；进程退出已核验。

关键修正：启动1496次分配、0次释放。旧合成重放在工作区之前“未模拟
释放”并未实际夸大该区间存活payload，不再把它继续列为已观察到的
额外压力原因。启动ready payload设备54843473680、host3600304144，
不是驱动物理计数。接下来执行原冻结两侧真实模型热启动，不追加重放。

## 第一热侧及准备失败后的唯一补齐

runtime热侧ENV_ABORT；其进程已清理。VMM-v1未进入模型：全量预热后
两个layer0 expert文件的驻留分别为4096/289517568，目标分别
354099200/354103296，严格向量门拒绝。pair监督器停止并释放全阶段锁，
没有将不同缓存起点下的运行当成对照。本轮仍只用掉2次模型加载预算。

确认差异为已选文件的已知缺页后，唯一受影响准备修正：重新建立原
清单与零驻留前置；若缺页只涉及最多2个文件且文件总长<=1GiB，额外
只读这几个完整文件一次，然后仍要求原逐文件精确向量。未知或多余
驻留不修正、不更换缓存量；缺页仍在则拒绝。原版不重跑，VMM-v2仍
最多一次加载，不增加第4次模型预算。该后续准备/模型全过程使用
新独立lease；不得声称与已结束pair-v1连续持锁，驱动页池/物理状态
跨阶段的不确定性仍披露。修正只允许达到同一缓存向量，不是优化变量。

## 全热向量无法保持后的固定对照修订

VMM-v2准备同样拒绝：补读缺页的首文件后，第二文件从目标354103296
降为238448640。两次均0模型加载，不能称VMM效果失败或与runtime
形成成功配对。缺页转移而非读失败，继续补页会成为无界轮询，停止。

为满足统一起点下的实际对照，冻结**唯一较低压力的两侧组**：完整文件
字典序前缀总长<=48GiB，其他模型payload零驻留；沿用相同精确向量门，
不启用缺页补读。固定runtime→VMM，各1次实际加载及同1K HTTP，
整个新组持续持同一外层锁。不再更改缓存量或加重试。总模型预算从
原3次修订为最多4次（已完成cold捕获和full-cache原版各1，新增两侧
各1）；依据是两次可核验的准备失败，新增性能样本仍0。

此组只检验可重复较低缓存压力的配置。若两侧都通过，只能接受该
配置的局部机制/质量及释放观察，不能宣称VMM消除了原完整热缓存故障，
也不能把较低压力结果替换此前63.3GiB失败。固定48GiB上限提供比前组
更多内存余量，不作为搜索得到的最小缓存阈值或性能优化结果。

## 最终结果与工程决定

固定较低压力组完成，同一外层lease约114.99秒，两侧均COMPLETED。
实际选中模型payload驻留51344936960 bytes（47.818699GiB），不是整48GiB；
两个启动前观测与预定逐文件向量精确一致。原版54次NVML查询全OK、
最长0.092413秒；VMM55次全OK、最长0.150921秒。资源monitor两侧exit0。
每侧1K输入/7输出、精确710003；服务exit0、scope清理完成。

两侧完整**逻辑分配/释放序列**在去地址后完全一致，不仅是启动前缀：
各3855分配、3853释放提交；启动各1496分配/0释放。VMM实际替换236笔
同步大分配，对应释放均返回成功；两侧余留均为相同2笔Argmax static
缓存共1986560 bytes，进程退出回收，不宣称这些缓冲显式free。
事件记录/同步调用次数受运行时完成时机影响，未要求逐事件时序相等。
async释放计数仍只是API提交，不等于调用返回时物理页已归还。

总模型加载4次、成功HTTP3条：冷捕获1、完整热原版失败1、较低压力
两侧各1；两次VMM完整热准备失败均0模型。六阶段818份封存文件全部
SHA复核，11项host门/账本检查通过；独立工具构建零告警并重新核对
binary/contract/object SHA完全可复现。默认19ea未改，无残留scope。
