# 快照双缓冲流水线：单候选有界方案

2026-10-29，按用户“推进到合理的状态”执行。任务是性能优化，目标是减少
完整快照的同步保存时间，不继续扩展内核采集。阶段从首次读表时
10:24:50 UTC 计时，硬截止 **11:54:50 UTC（90 分钟）**；实现、必要构建、
条件准备、HTTP、CPU 和进程退出均在预算内，之后仅离线归档与提交。

## 已知问题和唯一候选

旧 full/subset 有效闭合窗口均说明慢增量集中在直接 I/O 完成等待。每份
约 4.16 GB 主快照另有约 3.25 秒 SHA256 串行成本；预分配候选已经 NO_GO。
本候选只用两个 8 MiB 对齐缓冲区，使当前块 D2H/补零/SHA 与上一块 pwrite
重叠。一个保存最多一个写线程、一个在途 pwrite，不扫描块大小或队列深度。
理论只可能隐藏约数秒 CPU 工作，不能声称消除 SSD 自身等待。

候选由 Q4T_SESSION_PIPELINE=1 显式开启；关闭仍走原同步 Transfer。
两侧 Q4T_SESSION_PREALLOCATE=0、SAVE_TIMING=1。首次保存仍写完整状态，
不改模型计算、token 合同、snapshot range、文件布局、摘要或恢复路径。
保存期间继续持模型和缓存锁；返回前排空并 join 写线程，之后才安装 entry，
HTTP 成功后才发布。取消/copy/写入失败必须先收回在途工作，删除临时文件，
不发布半成品，不让缓冲区或 fd 提前销毁。额外 RAM 为每次保存 8 MiB
及一个线程；两个池原 staging 共16 MiB，模型锁限定同一时刻一个保存，
不建立 4 GB 镜像、无延后计费。线程初始化、排空、销毁均计入 Save/HTTP。

计时分别报告主线程关键路径、写线程 pwrite/CPU 和重叠区间；并行段不能
直接相加成总墙钟。全部 write bytes 及保存成功数必须与同步路径相同。
旧 BPF 管理队列过滤尚未经实机验证；本轮不使用它，不把其不完整观测补成
通过。使用已通过的常规 HTTP ownership/资源/退出监控。

## 冻结测试及出口

- 1 候选，最多 4 次服务启动、40 生成 HTTP（含8次覆盖后恢复），0 新 GPU
  数值 fixture，1 个 CPU 存储合同程序。必要编译先做，**第一项测试为
  tools/evalscope 真实 HTTP E2E**；首服务通过后才执行 CPU 合同。
- 每服务四槽 208896,65536,65536,65536，max-prefill4096，greedy k3，suffix、
  私有缓存和公共缓存。同冻结 code/8192 材料：主131071输入，三个子
  33274/49150/59986输入，各256输出；公共OFF/ON各1主＋3子，最后分别
  恢复原主会话，精确命中131323、答案44。复用原完整输出 oracle，数据
  不改写、不另选对候选有利的材料。
- 固定顺序：full 同步 OFF→ON，CPU合同，full 流水 ON→OFF，subset 流水
  OFF→ON，subset 同步 ON→OFF。每次新服务、空池、新 capability。
- 两 head 各原路径/候选一个配对；同程序只变 pipeline 开关。启动前一次
  原64 GiB固定存储预处理，不循环等“稳定”；总应用逻辑写入不超过
  192 GiB，CPU 写入上界256 MiB，两个缓存池既有磁盘预算不变。
- CPU 验证跨块/非对齐/多range逐字节恢复，d0/pending、失败不发布、
  checksum、短读/短写/EINTR、取消、正在写入时的copy失败及排空、线程/
  缓冲区回收。已有未变合同可直接复用，但异步所有权新路径必须覆盖。
- 接受条件：两 head 主保存中位数各至少快1秒，各公共模式完整事务均不
  变慢，候选公共ON/OFF净收益两 head 均为正；两次恢复的聚合HTTP耗时每
  head 不变慢；全部输出、恢复、容量和资源合同通过。TTFT负值逐项保留，
  不用保存计时抵消HTTP负值。只作有界描述性工程决定，不声称统计非劣。
- 首服务、正确性或环境失败即停止；常规监控失败/竞争记 ENV_ABORT，仅
  清理自己的进程。运行期不因某一小差值提前挑样，完成冻结配对后统一
  判定；到截止或不达接受条件就 NO_GO/INCOMPLETE，不补服务、不扩样、不
  改参数重试。允许在构建前修实现错误，受测身份冻结后不替换程序。

完整阶段驱动持 gpu_exclusive 同一把锁；运行时原始记录、命令和环境、
源码/程序/材料/子集身份、资源和退出屏障归档。已通过的 A112 无缓存
五档/质量、S32 suffix重复、评分与数值状态合同按依赖逐项核对复用，
本轮仅重验存储和覆盖后恢复受影响项，不重跑整套。局部通过不自动补齐
原正式 C 缺失项；原 NO_GO 不追改，任何交付须单独核对总门槛。
