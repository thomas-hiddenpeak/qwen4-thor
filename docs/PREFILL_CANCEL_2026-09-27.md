# 长文本分块prefill的连接失败取消

当前候选修复确认失败连接（RST/挂断）的长prefill迟发现问题。
部署和验收终态以STATUS为准；本报告不会将普通FIN等同于取消。

## 行为与所有权

此前在完整prefill后首次写SSE才发现RST。现在调度器在每块前、
完成该块既有GPU同步后用非阻塞poll检查POLLERR/POLLHUP。
确认失败后不重排下一块，通知等待的请求线程；请求线程记一次
aborted、结束序列、释放槽位。不向断开的连接写500，不将取消记为
GPU错误或成功请求。若GPU本身失败，仍沿用不健康设备处理。

fd由等待线程持有，ChunkPrefillReq仅借用；调度器完成后才能清理。
非调度分块路径也在提交下一块前检查，退出前沿用既有GPU同步。
本轮实测为默认MTP关闭的调度路径，未验证MTP回退路径。

TCP写半关闭允许客户端继续读HTTP响应，因此不检测POLLIN/RDHUP
或以recv返回0直接取消。普通FIN不能与合法写半关闭区分，保留
原写响应时检测；未实现立即取消全部TCP关闭方式，也未增加应用层
取消API。单块prefill不抢占，已提交GPU工作不强制中止。

## 缺陷回归

- 提取实际生产连接判定函数，在真实loopback TCP上验证正常连接、
  shutdown(SHUT_WR)后可收响应、RST可识别；零警告、退出0。
- 完整模型1K/44K、max_seq=2、max_prefill=8192、MTP关闭：
  A→B→A、两轮重叠和首响应前/首内容后RST恢复均通过。
- 首响应前RST在8192/45056处结束，证明未算完整prompt；aborted
  增加1，槽位归还、GPU健康、恢复请求相同。9条完整响应的文本、
  usage、stop一致，服务退出0。
- 正常重叠与断连恢复分别验证；本轮没有在两个活动请求同时执行时
  注入RST。也未把局部TCP判定测试当成完整HTTP半关闭测试。
