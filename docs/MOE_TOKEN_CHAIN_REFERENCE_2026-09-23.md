# 同一 token 的路由专家完整支路参考

## 结论

固定原4K请求最后一个prefill token（4095），把48层选中的480个
专家gate/up、SwiGLU量化、down及路由加权边界接通。生产源码及
接受二进制2392f6b1未变，原4K答案仍错。

| 边界 | 元素数 | 本样本结果 |
|---|---:|---|
| gate/up输入FP4 | 1228800 | 实际尺度下独立编码全部相同 |
| gate/up输出BF16 | 614400 | 同独立FP64投影经FP32→BF16舍入 |
| SwiGLU后输入FP4 | 307200 | 同设备重建和独立高精度SwiGLU量化 |
| down输出BF16 | 1228800 | 同独立FP64投影经FP32→BF16舍入 |
| down到合成边界 | 480个专家输出向量 | 逐位相同 |
| 路由加权和FP32 | 122880 | 同CPU逐槽fmaf参考 |

所有量化参考使用实际捕获尺度；一致不代表尺度规则正确。
gate/up尺度仍有此前确认的70次高值错误；本次另确认down输入
19200组中的71组高值错误，涉及32层，均在[248,432)提前饱和区。
不将二者当成全模型发生率，也不据此证明原答案错误的原因。

## HTTP与边界绑定

扩展只读观测库的初次构建发生局部变量名错误，保存原源码与错误
日志，修正后构建零警告；未运行前置测试。第一项测试仍是原4K
无/有/无观测tools/evalscope HTTP，三次全文600440，应为360284；
4096输入、7输出、stop，三服务0、质量驱动1。观测一致性通过，
不把既有质量失败称为通过，也不采用这些时延作性能证据。

从已选专家的实际GU GEMM输出指针绑定下一次SwiGLUQuantKernel，
记录同一compact行的输入及该专家down尺度。随后绑定实际down
GEMM，保存该行FP4、实际激活尺度、完整权重/尺度及BF16输出。
480份GU与480份down记录成功，所有SwiGLU输入均与GU输出位同；
所有down结果与按expert id找到的合成槽位位同。与前轮相比，
480份GU源输入及480份GU输出共960份逐字节相同。

实际down权重、还原swizzle后的尺度逐份匹配checkpoint中对应层/
专家；input_scale与weight_scale_2及实际FP32 alpha一致。未假设
compact行号等于prompt索引，也未假设跨观测的列表排列固定。

## 数值方法与差异

接受版header快照用于设备重建每组SwiGLU、max、除6、除逐专家
尺度及旧E4M3编码，同时记录CUDA原生编码和FP32中间值。
19200组旧编码全部同实际，原生编码全部同独立枚举最近偶数参考；
71组旧编码不同，全部是高值区错误。诊断构建零警告，重放退出0。
这是接受版真实HTTP输入的离线诊断，没有测试已拒绝候选。

独立枚举E2M1最近偶数编码，对设备重建中间值按实际尺度重编码，
307200项全部相同。再用FP64稳定sigmoid独立计算SwiGLU，舍入为
FP32后按相同实际尺度归一化和编码，307200项仍全同。设备中间值
与FP64数学值最大绝对差约1.22614e-6；保留此差异，不宣称__expf
逐位等于高精度exp。这里证明的是本样本量化后的编码一致。

独立解包实际量化输入/权重，FP64矩阵乘再乘实际alpha，经FP32
和BF16舍入，1228800个down输出全部位同。由于GU参考与实际GU
逐位相同，此处中间计算接上了上一阶段参考，而不是另一批专家。

合成核对复现既有结果：480个分组槽位正确，122880路由FP32值
同逐槽fmaf；共享合成同原树形归约CPU重算，FP64合成仍保留1项
差异。共享MLP既有142项投影差异未被本报告消除，详见共享报告。

## 范围及下一步

本轮完成的是单个prefill token在48层的路由专家支路局部参考。
每层入口仍为实际MoE输入，未独立生成上游attention/GDN/PLE/
残差状态，未跨层传播独立结果，也没有覆盖decode或整模型质量。
既有格式修正候选的任务退化仍有效，不以这些局部结果追认。
