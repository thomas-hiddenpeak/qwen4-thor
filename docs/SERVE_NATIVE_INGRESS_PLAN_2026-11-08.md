# 原生服务入口与 nginx 解耦

2026-11-08。用户要求推进目标，并允许在遵守许可、README注明来源的
前提下学习nginx代码。本轮属于服务功能与可靠性推进，不宣称性能优化。
基线工作分支`codex/serve-self-recovery`，父提交`d39f8291`；沿用已有
原生引擎60b1c4c1与Guardian恢复机制，旧恢复包及验收证据保持可核验。

## 冻结范围

1. 新增独立CPU目标`q4t-ingress`，复用项目POSIX HTTP请求解析和有界
   JSON/进程工具；不链接CUDA、NVML或新增第三方网络库。入口与模型
   生命周期分离，模型重载期间返回有鉴权的503/Retry-After。
2. 入口自行验证Bearer API Key、请求方法/路径、Host、请求体与连接
   容量；仅转发白名单字段，公共身份头不能覆盖已认证客户端。RPM/TPM
   与公平准入继续由原生后端执行。新入口代次不清空后端配额。
3. 复用既有Guardian/Controller绑定核验；入口经私有Unix IPC逐请求
   获取当前准入，严格核验对端身份。请求读体前检查、转发前再检查
   同一绑定；模型自检/分钟配额隔离结束前不开放。私有IPC是q4t内部
   协议，外部nginx仅使用标准HTTP，不需要准入子请求或内部凭据。
4. JSON和SSE有界转发、背压与断开传播，不缓存模型输出、不重放POST
   或工具操作，不在新模型代次补接旧SSE；保持控制请求独立容量。
5. 新恢复包默认原生入口，无nginx探测、复制或进程启动；旧封装原样
   保留。显式兼容模式和普通HTTP前置兼容另作验证，TLS继续由可选
   前置提供；本轮原生入口只监听loopback，不隐式开放明文LAN。

既有Python控制器/监控依赖如实保留；本轮不扩展通用Web服务器、
HTTP/2、TLS实现、热更新、视觉恢复、C/D或长稳。默认原生serve的数学
路径不变；入口复用的HTTP解析新增元数据，直接合同另行覆盖。

## 验证与交付出口

- 成组开发后统一CPU验证：合法/错误/重复Bearer、内部身份伪造、
  请求分帧/超限/慢读、并发与控制容量、配额429保留、逐请求准入及
  代次变更、控制面失联、JSON/SSE/取消、不重放、入口退出和清理。
  使用真实原生入口进程及CPU后端/Guardian替身；明确不等于LLM验收。
- 包、启动入口和原生构建来源校验；零警告；原生目标动态依赖核对。
  明确证明默认包不含nginx，PATH没有nginx/systemd也可运行。可选
  nginx前置使用本机现有二进制与CPU后端，不安装或干预系统服务。
- 真实业务上限为本阶段累计4次模型启动、20条Chat、1800秒；包含
  每代自检、失败与中断请求。完整驱动持同一严格GPU租约；竞争或
  观测失败ENV_ABORT，只停止自有进程。覆盖直接入口的JSON/SSE、
  严格工具与真实资料查询、模型/控制器/入口恢复、鉴权/配额和停止。
  复用旧驱动及身份未变的故障策略证据，记录耗时但不声称性能非劣。
- 通过后保留回退包，安装适用新服务入口并同步发布元数据；仅初始化
  STOPPED，不安排常驻业务。更新文档、证据、现有PR并提交推送。
  未通过不替换默认，不覆盖原件或自动增加预算。
