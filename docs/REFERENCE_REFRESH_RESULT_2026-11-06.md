## QSA归因与下一项取舍

两组各6个真实prefill chunk（5×8192+4084），每行12个QSA层、五段
全部有效，未出现checkpoint verify混入。单位毫秒，均为CUDA event
区间，可能包含宿主/观察间隙；不证明纯kernel时间、带宽饱和或idle。

| QSA段 | 完整head合计 | subset合计 | QSA占比约 |
|---|---:|---:|---:|
| 主Q/K准备、RoPE、KV写入 | 238.707 | 237.946 | 2.59% |
| indexer投影 | 32.171 | 32.174 | 0.35% |
| indexer准备 | 20.489 | 20.420 | 0.22% |
| score/select | 1418.436 | 1418.104 | 15.4% |
| sparse attention | 7496.093 | 7497.170 | **81.4%** |
| 五段总计 | 9205.898 | 9205.815 | 100% |

对应full_core为9206.430/9206.330ms；未分配区间仅0.532/0.515ms。
五段嵌套于full_core，不能再与其相加。两head指向同一个主模型
prefill成本中心，改草稿head不能消除它。

因此不继续indexer投影融合：即使理想化消除32ms，也只对应当前约
32秒TTFT的0.1%。优先研究本项目**大T sparse attention**。把该段
耗时压低10%，在其他成本不变假设下约节省0.75秒、对应TTFT约2.3%；
这只是投入预算估计，不是已测收益或保证。

代码已有12:1 GQA复用、cp.async双缓冲、共享内存padding和PV寄存器
累积，不能把这些当作遗漏再实现。下一单一候选优先静态评估
SparseAttentionKernel中每头一个线程串行处理16个score/exp的softmax：
将独立exp分配给lane，同时维持选中token顺序、16位置分块、FP32
最大值/求和顺序、BF16概率落点及门控舍入。不能采用树形求和或扩大
tile来偷换原数值合同。当前五段计时尚不能证明softmax是7.50秒内部
的主因，这仍是有源代码依据的待验假设；寄存器/同步成本可能抵消收益。

本轮未实现或测试该性能候选。下一阶段应先冻结长上下文TTFT目标与
五档保护项，再按HTTP优先决定是否投入独立数值及完整验收；不追加
profile来寻找好看的样本。不直接移植参考项目不适配的架构/张量合同，
其余参考增量继续按[全量矩阵](REFERENCE_REFRESH_2026-11-06.md)暂缓。
