## 改动与边界

真实 HTTP 时间线表明，200K prefill 的 MergeChunkTopkKernel 累计约
63.35 秒，占 kernel 累计 24.59%。本次只替换该 kernel 中的 2048 元素
排序和标准 1024 元素合并排序；其他排序调用保持原实现，非标准
block_topk 的合并也继续使用原函数。

比较网络各级的配对、升降方向与严格比较规则不变。跨 warp 的交换仍
使用共享内存及线程块同步；warp 内的连续比较级先读入寄存器，使用
shuffle 交换分数和 ID，再写回共享内存。等分不交换，不能以另加 ID
排序规则改变边界选择或 attention 累加顺序。实现要求固定 256 线程。
没有减少候选块、top-k 数量，也没有改变索引打分或量化精度。

## E2E 后的排序专项

完整质量和性能通过后，新增并只运行 streaming_topk_exact。CUDA 生产
接口逐块执行，CPU 原网络作为同分顺序兼容性 oracle；另以 std::sort
检查数学 top-k 分数，不能仅用通用排序确定原网络的同分 ID 次序。

1/3/17 行各连续 25 块（每块 2048 候选、保留 512），每一步的全部分数
和 ID 共 268800 对逐位一致。模式覆盖乱序不同分数、逆序、边界重复分数、
正负零、全无效、部分可见和全部胜出者直到最后一块才出现。后者也检查
完整候选覆盖。1/1 专项通过，构建无警告，不运行无关整套测试或 bench。
本轮 E2E 是单流文本，不替代并发、MTP、多模态或全面业务质量验证。
