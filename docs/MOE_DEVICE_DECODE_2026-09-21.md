## 执行边界

独立 CUDA 单元仅覆盖 M=1、top-10、512 专家、hidden=2560、
intermediate=640。GPU 从路由 slot 生成专家权重、scale、alpha 与形状
指针数组；GU/DN 各一次 grouped NVFP4 GEMM，按固定 slot 次序 FP32
合并。其余形状保留原路径。路由器保证专家 ID 有效且互异。

仍使用 NVFP4 权重/激活量化、BF16 GU/DN 输出与原 FP32 合并次序，
保留每专家 input scale/global scale；不是改用 FP8。host 仍负责提交
固定阶段，不是整个模型已经实现 GPU 自主调度。
本机 CUDA 13.3 / cuBLASLt 13.5.1 实际 HTTP 已执行两个 grouped 形状；
无算法或调用失败返回错误，不静默降级。

每层临时 scratch 为 205824 字节：1024 字节描述符区域和十份各
20480 字节 scale。同一 stream 分配、消费、释放，DN 复用 GU 区域。
复用原 workspace 的 packed/GU/DN 输出；原有 scale 空间仍保留，
不能从预算中扣除。缓存只拥有 host cuBLAS 描述符，每次重新绑定设备
指针；GPU 临时存储不由该缓存持有。

## E2E 后数值核对

`tools/verify/compare_moe_device_decode.py` 强制检查完整 HTTP 门禁、
二进制 SHA 与候选源码快照。对照提取 9831e6a 原始量化/合并代码，
运行原 per-expert GEMM 与候选完整公开执行入口。

四种输入族乘三种专家排列共 12 组：随机、正负零、交替正负与小值；
不同专家 scale、含边界专家 ID、非零初始 FP32 输出。
707520 个 active payload/scale、GU/DN BF16 输出与 FP32 合并值
逐位一致，无非有限值。不检查无消费者的 scale padding。
这是合成合法权重与输入专项，不代表所有真实层激活或全面业务精度。

首次数值工具构建因未使用常量警告停止，未运行；移除常量后零警告通过。
`numerical/` 保留失败，最终证据在 `numerical-fixed/`。
没有前置数值测试、能力 probe、单测或 bench。

## 首轮同请求配对 HTTP 时间线

精确旧二进制 q4t-before 与候选分别采集同一 1K 请求，顺序运行。
输出一致，两次服务、采集器均退出 0，SQLite 完整导出。
每条请求均为 255 次 decode 前向，以下计数取 decode 区间。

| 项目 | 旧 | 新 |
|---|---:|---:|
| 专家 counts D2H | 12240 | 0 |
| cudaStreamSynchronize | 12496 | 256 |
| cudaEventRecord | 36720 | 0 |
| cudaStreamWaitEvent | 36720 | 0 |
| cudaMallocAsync / cudaFreeAsync，各自 | 141270 | 141270 |
| kernel 总数 | 908055 | 442935 |
| 专家 GEMM kernel 次数 | 244800 | 24480 |
| 专家 GEMM 累计 ms | 2463.283 | 1522.616 |
| 旧 Gather/SwiGLU 或新 Prepare 累计 ms | 1500.355 | 153.647 |
| 固定 slot 合并累计 ms | 34.340 | 23.543 |
| BF16 GEMV 累计 ms | 9514.760 | 9540.350 |
| decode 窗口 ms | 16434.386 | 14275.820 |

每步减少 48 次 counts 回读、48 次显式 stream 同步、144 对事件
record/wait；kernel 每步 3561→1737。异步分配/释放仍各 554 次/步，
不能把收益归因于减少分配。prefill kernel 次数均 72399、counts 回读
均 48 次，保留原多 token 执行路径。

旧专家 kernel 存在跨流重叠，累计耗时差不能直接求和当作墙钟收益。
API 时长包含等待 GPU 的时间，不是全可消除的 host 开销。profiler
对两个实现的扰动可能不同，采集窗口不替代正式 E2E 速度。
没有采集 DRAM 计数器，不声明物理流量或带宽利用率改变。
