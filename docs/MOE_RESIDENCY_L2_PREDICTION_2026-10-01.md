# 分层驻留：L2 命中率离线预测与 C 容量扫描（2026-10-01）

目的：在第二轮矩阵（L2-128 + C=256）出实测前，用主试验路由轨迹
（main-study-20260929，20 请求，48 层×512 专家×top-k=10）离线模拟
第二轮配置，预判 decode 吞吐，并为第三轮 C 容量决策提供依据。
纯 CPU 离线分析，无模型/HTTP/GPU/NVMe 运行，不污染正在跑的第一轮矩阵。

## 方法

- 数据：`.q4t-work/moe-raw-export-20260929/main-study/routing.csv`
  （逐 forward×层 的 top-k 专家序列，decode 每行 10 专家）。
- 校准→留出：请求 1–10 建每层 top-C 热点名单（token 加权频次，
  模拟 make_hot_list.py 在业务校准集上的口径），请求 11–20 作留出
  验证。名单与验证材料不重叠，贴合真实部署（名单来自业务集、
  矩阵夹具是另一批材料）。
- 模拟：每层 GPU LRU-C（预装 top-C 热点、**不保护**、LRU 可逐出，
  与 serve 路径一致）+ L2 LRU-N（pinned，InitHot 按装载顺序预热，
  命中/缺失都更新 LRU）。缓存跨请求保留（与运行时一致）。
- 脚本：`.q4t-work/moe-residency-20260930/sim/{l2_sim2,l2_sim3,c_sweep}.py`，
  结果 JSON 同目录。

## 关键结果

### 每层 decode 工作集（留出集，全局 distinct）
min=277 max=450 mean=349.4；48/48 层 >256，37/48 层 >324。
（全局 distinct 是上界；稳态局部工作集更小，见下。）

### L2 容量扫描（C=256 固定，留出 decode）
| L2/层 | L2 命中占 GPU miss | 说明 |
|---:|---:|---|
| 64  | 0.2% | 几乎无效 |
| 128 | 5.8% | 第二轮配置，收益有限 |
| 192 | 19.9% | |
| 256 | 36.7% | |

结论：**L2 命中率强依赖容量**；L2-128 只接住 ~6% 的 GPU miss，
单独不足以把 decode 拉到 50% 门槛。miss 流有局部性（L2-512 能接
70%），但 128 槽太小。

### C 容量扫描（每层 top-C 热点，留出 decode，无 L2）
| C/层 | decode miss 率 | miss/步(480 查) | 预估 decode |
|---:|---:|---:|---|
| 256 | 4.63% | 22.2 | ~25–30% 基线 |
| 324 | 2.34% | 11.2 | ~44% 基线 |
| 384 | 1.21% | 5.8 | ~61% 基线 |
| 450 | 0.49% | 2.3 | ~79% 基线 |
| 512 | 0.00% | 0.0 | ~基线 |

（预估 decode = 1000/(55.2ms + miss/步×6.2ms)；55.2ms=基线步时
18.1 tps，6.2ms=第一轮实测单 miss 时延。）

校准核对：C=256 模拟 miss/步=22.2，第一轮 1024 档实测 26.6/步——
同量级，说明留出模拟能复现第一轮行为，预测可信度较高。

## 对第二轮（L2-128 + C=256）的预判

留出 decode：22.2 GPU miss/步，L2 接 ~6% → ~20.9 NVMe miss/步
→ 步时 ≈ 55.2 + 20.9×6.2 ≈ 185 ms → **~5.4 tps ≈ 30% 基线**。
**预计低于 50% 门槛**（与第一轮 22–30% 接近，L2 只小幅改善）。
第二轮矩阵仍值得跑：拿到夹具上真实 L2 命中率与逐档 decode，
确认/修正本预测，并暴露逐层工作集差异。

## 内存账（每专家槽 3,276,816 B，48 层）

| 配置 | 专家槽 GB | 总峰值估算 | 相对 54 GB 预算 |
|---|---:|---:|---|
| C=256（已接受） | 40.26 | 57.71 | +3.7（用户已接受） |
| C=256 + L2-128 | 40.26 + 20.13 pinned | ~77.8 | +23.8 |
| C=324（无 L2） | 51.03 | ~68.4 | +14.4 |
| C=384（无 L2） | 60.52 | ~77.8 | +23.8 |
| C=450（无 L2） | 70.61 | ~88.1 | +34.1 |

**关键洞察**：同等内存下，加 GPU 槽（C）比加 CPU L2 更有效——
C=384（77.8 GB）decode ~61%，而 C=256+L2-128（77.8 GB）仅 ~30%。
GPU 槽免 H2D、免 LRU 管理，单位内存收益更高。L2 只在 C 已接近
工作集、想再抠最后几个 miss 时才有边际价值。

## 夹具 vs 聊天轨迹的工作集差异

第一轮实测夹具 decode miss 率 4.3–7.1%（C=256），反推夹具每层
稳态工作集 W≈267–275，**明显小于**聊天轨迹留出集（mean 349）。
若夹具 W≈270 成立，则 **C=324（68.4 GB）即可让 decode miss→~0，
decode≈90%+ 基线，轻松过 50% 门槛**，且内存超支仅 +14.4 GB。
这是第三轮首选候选；C=384（77.8 GB）为更稳妥的兜底（对聊天轨迹
也过 61%）。

## 决策点（需用户确认）

1. **内存超支幅度**：54 GB 预算与 50% decode 门槛在当前 NVMe 时延
   下结构性冲突——达标需 C≈324–450（68–88 GB）。用户已接受 C=256
   的 +3.7 GB；C=324（+14.4 GB）/C=384（+23.8 GB）属新增超支，
   需明确授权幅度。
2. **第三轮配置**：建议 C=324（无 L2，68.4 GB）为首选，待第二轮
   夹具实测确认 W 后再定 C=324 vs C=384。
3. **NVMe 时延**：6.2ms/2.77MB≈450 MB/s 偏低（Thor NVMe 应可达
   2–3 GB/s）。若第三轮做逐 miss 时延分解 + O_DIRECT/预读/预取，
   可把单 miss 压到 ~2ms，从而允许更小 C（~324）达标，降低内存
   超支。属工程优化，GEMM 仍冻结。

## 边界

- 预测基于聊天轨迹，非夹具本身；夹具路由更集中（W 更小），预测
  对夹具偏保守（实际 C=324 可能比预测更好）。
- 6.2ms/miss 为第一轮 1024 档反推值，未逐 miss 分解；NVMe 实际
  时延待第三轮实测。
- 本文件不改变第二轮冻结配置（L2-128 + C=256），仅作预判与
  第三轮决策输入。

的最小配置是 C=384（无 L2）；对验收夹具（W≈270，见上节）C=324
即可能接近基线。

## NVMe 单 miss 时延分解（2026-10-01 05:05 实测，纯 CPU，矩阵运行中安全）

第一轮反推有效单 miss 成本 6.2 ms，但 NVMe 原始读取远低于此：

- 顺序 4 MB dd：2.3 GB/s（页缓存热）。
- 随机 3.28 MB pread（单专家一次读，layer-47 文件）：页缓存命中
  0.00–0.11 ms；未命中（文件头，页缓存未驻留）**中位 1.44 ms、
  p90 2.07 ms**——NVMe 本身不是 6.2 ms 的来源。
- 加载路径已是单 pread 快路径（3×w 连续 + SF + 6 标量，共 2–3 次
  pread，moe_residency.cpp StageExpert），swizzle 0.210 ms/专家
  （CPU 微基准），8 线程创建/回收 0.173 ms/轮（已改常驻池）。

**结论**：6.2 ms − ~1.9 ms（NVMe+swizzle）≈ 4 ms 管线开销待分解，
候选项：页缓存压力下随机读变慢（工作集 80 GB vs 缓存 ~30 GB 持续
驱逐）、单流（Q4T_MOE_STREAMS=1）逐层 H2D+GEMM 串行的流同步
开销、LoadPhase1/2 逐 chunk 互斥/条件变量往返。第三轮做逐 miss
分阶段计时（仅测试开关，GEMM 冻结）+ 预取/预读调参可定位；若
单 miss 压到 ~2 ms，C=324 即可过 50% 门槛而内存仅 +14.4 GB。
