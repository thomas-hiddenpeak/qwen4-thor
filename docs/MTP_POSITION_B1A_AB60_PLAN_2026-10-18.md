## 决策目的与证据边界

本阶段只回答：相同生产父版本与B1a候选，在同一lease、相同请求组织下，
on/off各五档的输出是否保持合同，TTFT/decode观察差值分别是多少。
“同期”指同一阶段的顺序执行，不代表同时运行或已经消除时间混淆。

| 执行有效时可以补齐 | 不能由这60请求建立 |
|---|---|
| 精确父A的MTP-on五档实测 | MTP-on跨启动分布/噪声界 |
| 两模式各自的新A/B矩阵及20项差值 | 候选效果置信区间、微小收益/持平保证 |
| 相同请求组织、输入输出与环境记录下的对照 | 任意跨日/负载/机器的泛化 |
| 本次60条性能请求的输出/长度/重复确定性合同 | 新的完整语义质量题集、未测数值合同 |

两个模式各一对服务；三次请求是服务内重复，不是三次独立启动。
A-off/B-off/B-on/A-on的外观虽为ABBA，**每个模式都不是ABBA**。
不混合on/off，不从两模式相减估计“公共噪声”，不声称反向顺序抵消漂移。

本阶段不估计分辨带、不拟合漂移、不计算功效/置信区间，不新增测量工具。
20项分辨带与不确定区间继续记NOT_ESTABLISHED。依据EVALUATION，
纯计时结果无论方向如何，本阶段都没有性能GO出口；这是采样前已知边界。
成本的唯一正当用途是补齐同期描述证据，不能以“这次可能通过”为理由执行。

## 固定分析和报告

每模式每档每服务：`T=sum(TTFT)/3`；
`D=sum(output-1)/sum(latency-TTFT)`。保存全部逐请求值、实际usage、
时间戳、finish、响应身份，单列1K首次与后续。主表保留A/B绝对值。

差值始终B相对A，正值表示变慢：`dT=100*(T_B/T_A-1)`，
`dD=100*(1-D_B/D_A)`。on虽然B先跑，公式不倒转。共20项，不能以
短档改善抵消长档下降，也不把on收益抵消off变化。不得按看到的结果
改统计量、阈值、删异常请求、拟合时间修正或加入旧数据增加样本量。

保存各runner/server退出码与guard退出码，独立检查原始DB实际请求账本，
归档源码/工具/参数身份、全部输入输出、日志和raw-manifest。工具成功
只代表本次HTTP与输出合同通过，不把其performance_acceptance改成true。

## 如何影响B1a下一步；冻结的停止与收口表

| 观察/条件 | 可得结论 | B1a动作 |
|---|---|---|
| 全部有效，所有指标方向改善或很接近 | 同期观察支持其后续研究价值，但不证明收益/持平 | 保留简化候选与新证据；性能仍不足，暂停，不合入 |
| 全部有效，部分/全部计时变慢或方向混合 | 保留具体档位、方向和幅度，不能仅凭均值定因果 | 不追收益、不自动诊断；未决归档，暂停 |
| B输出/长度/确定性或运行合同失败 | 本次候选检查失败；不能用速度解释计算/输出差异 | 立即停止后续服务，记录失败及已执行A情况；恢复前需单独界定缺陷/修复身份 |
| A失败或双方失败 | 对照/协议/环境可能无效，按已知事实分类 | 不把无效A对照转为B性能NO_GO；保留现场、停止 |
| 独立证据已确认候选真实退化机制或计算缺陷 | 可按现有规则拒绝候选，不以简化抵消 | 标明确失败及依据，不自动修复/重跑 |
| 身份不符/环境竞争/监控失败 | IDENTITY_MISMATCH或ENV_ABORT | 立即停止，只清理自己进程，不补样 |
| 60请求/4服务/4小时上限触及但未完成 | 阶段INCOMPLETE，保留有效部分 | 停止，无补齐/追加预算 |
| 完整跑完但分辨带/区间仍缺 | 阶段AB_OBSERVATIONS_RECORDED；验收INSUFFICIENT_EVIDENCE | **有界阶段结束，未决归档；不转校准项目** |

“立即停止”指发现后不再启动下一档/服务，不改成每请求重启客户端。
不会为了给计时差异找机制而追加profile、消融、A/A或ABBA。离线收尾
只做一次预定的身份/账本/输出核对和指标复算；分类不明就如实留未决，
不延伸成无界根因调查。

本卡不保证产生GO；正常跑完仍不足是预先接受的阶段出口。归档保留候选
分支、binary及原始路径，保持生产A；不删除独有提交。后续只有新实现
变化、具体可验证机制或独立可用测量依据，并获新的有界阶段授权，才可
