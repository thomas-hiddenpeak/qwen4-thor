# MoE 请求完成边界影子验证

目标：为减少专家常驻内存、尽量保持性能收集进一步证据。
用户确认方向后继续本阶段；真实专家加载、驱逐和预取仍不在范围内。

## 冻结范围

采用独立旁路进程，消费既有采集器原子发布的完整request-N.bin。
这是服务运行期间的**请求完成边界观察**，不是逐层同步回调；可见延迟至少
到该请求结束，再加校验/统计耗时。其因果缓存状态用于逻辑对照，不能证明
本次计算前已经取得路由或专家权重就绪，也不保证跟上每个请求的实时进度。
无需修改已验收runner、kernel、部署身份或采集同步，避免为观察引入新控制路径。

固定每层32/64槽，静态热点/LRU、prefill_reset/continuous，共八套影子状态。
静态排名复用原八条seed1前64次decode，独立于本轮评估；动态为空状态开始。
评估回放全部已提交decode，不再截64步；prefill沿真实块边界按专家并集消费。
超容量prefill保留缓存、不刷新recency、不接纳，缺失专家分组经staging的
假设不变。相同字节预算、对齐scale及10槽staging、静态付费初始填充沿用
[离线合同](MOE_CACHE_REPLAY_2026-09-28.md)，没有真实权重缓存分配。

取消/失败请求的已提交前缀仍影响continuous，终态单列；未提交forward不更新。
采集队列丢失、IO错误、身份变化、源缺口、超限、超时令影子非0停止，记录
incomplete；不向服务发信号、不要求服务等待。因进程终止而无status也不是通过。

观察器最多64请求、单bin256MiB、统计输出128MiB、校准输入1MiB、最长7200秒；
一次一请求、按帧顺序处理，层组频次最多512项；轮询250ms，记录积压峰值、
处理时长及RSS。检查器最长120秒；受限文件解析和普通文件IO不可抢占，
没有故障文件系统的硬截止保证。源码采集仍受既有1GiB配额与四槽队列约束。

## 验收计划

用户最新约定：先完成本阶段工具、采样和分析，再统一做质量/性能验收，
过程中不反复测试。此前已经完成的质量和直接合同保持原证据；正在运行
的对照组自然结束后保留。剩余材料采样/分析先收敛，再完成尚缺的最终
影子开启成本组，不重跑身份未变的已通过项。

1. 有界状态、原子发布、已完成旧run拒绝、损坏/空/缺口/超时拒绝；取消已提交
   前缀与失败forward语义；公开host接入。默认二进制保持3b414633。
2. 真实HTTP固定质量11题，影子开启；另一个故障观察器失败时服务继续完成质量。
3. 真实HTTP五档各三次256输出，顺序为采集on/影子off，再采集on/影子on；
   只报告新增旁路成本，不把两个条件称为默认关闭采集的代价对照。原采集成本
   已接受，不重新解释。使用冻结相同输入/参考，不追加有利采样。
4. 八条固定编写材料，含任务切换、两个短多轮对话对及一个长项目文档对话对；
   完整请求、响应、usage和材料摘要封存。这是探索工作负载，非生产或语义基准。
5. 停机后完整来源复核，独立有序列表算法重算全部prefill/decode、策略/模式、
   填充和字节；在线记录与离线逐项一致才用于结论。
