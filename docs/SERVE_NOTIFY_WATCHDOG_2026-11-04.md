# SRV-12d独立接收端心跳缺失检测

前一阶段02j2已交付默认CUDA额度版本。本批补工业化账中的“接收端
独立发现告警链停止”缺口，限业务可靠性工具，不是性能优化。
正式接收地址仍未配置；先开发适配器和本机短验，不发外部消息。

## 冻结实现范围

新增独立Python接收适配器/观察器，固定源码和私有Bearer，严格只接受
指定deployment的单心跳；原始告警走既有接收方，不吞掉普通告警。
无生产HTTP listener、外部发送或模型控制权限。HTTPS传输使用既有
固定Prometheus3.5.0/Alertmanager0.34.2，本批不改原通知实现及已验包。

180秒无有效投递或首次从未投递记MISSING，resolved立即不健康。
使用BOOTTIME/boot_id保存到达时刻；进程重启不重置等待窗，重启系统
后UNKNOWN，新的有效投递才可恢复。墙钟跳变不延长内部窗口。
相同payload的重复firing须刷新到达时间；已见真实AM的endsAt为零。
更早incident忽略；同incident乱序/已认证重放不能由标准payload分辨。
所以证明的是通知投递链活跃，源采样停止后的缓存/重试延迟单独保留。

状态与凭据0700/0600，单实例flock；持久化失败不确认，损坏未知
不修复、不替换历史目录，残留写中间文件保留。64转换环和累计计数
固定有界；每秒原子指标投影。外部规则单独检查心跳、观察器采样
陈旧与完全缺失；多deployment库存缺失需部署方按清单配置。

生产runner/模型/网关及用户day的全部身份保持。用户仍负责长验。

## 有界验证

先成组CPU合同：输入/认证/重复与错误心跳、边界180秒、首次缺失、
resolved/恢复、迟到旧incident、时钟/boot/进程重启、坏状态/磁盘
失败、读写互斥和持久化、64环上限、固定包/独立入口/模板。
官方固定promtool验证三规则与健康/失联/陈旧/缺失/恢复时序。

之后冻结实际驱动精确预算：本机HTTPS夹具接入真实AM/Prometheus，
初次心跳后同时停止两组件，保持独立观察器到180秒真实边界并确认
MISSING，再显式恢复组件证明PRESENT；观察器自身停止/重启不重置
失联，固定状态保持。零模型/零生成；全HTTP阶段仍在同一GPU租约，
不占GPU计算、不启动vLLM、不自动运行小时/天级长验。

通过后保留完整失败/通过证据、工具入口与运行边界，更新状态和日志，
按既有授权commit/push。正式外部通知、实际LAN部署、物理RAM保护、
用户长验和整套监控所有故障组合仍未完成，不以本批代替工业化总验收。
