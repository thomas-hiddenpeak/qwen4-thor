# SRV-01c：工具与结构化输入的错误路径

2026-11-04。持续工业化目标的输入合同回补，业务可靠性修复，不是
性能优化。上一阶段11g已交付；本阶段不依赖正式LAN地址、证书或
通知渠道，不运行用户负责的小时/天级长验。

## 缺陷与固定范围

`ValidateChatContract`调用`PlanOutputConstraints`时没有传递错误位置；
工具定义、tool_choice、response_format与递归schema的校验器也没有
位置出口。因此HTTP400虽有message/code，param仍可能是null。客户端
必须解析自然语言才能猜到具体字段，嵌套或多工具时尤其难定位。

本组只增加显式位置传递。保持原接受/拒绝条件、校验顺序、错误码、
提示文本、有限schema profile、渲染模板与约束语法。普通auto/raw的
schema仍是建议；none仍不编译工具参数schema。输出值/模型生成错误
和不能归属单一输入字段的运行错误不伪造param。

位置约定：固定字段与ASCII标识符键使用点号，数组使用从0开始的
`[i]`。其他键使用JSON字符串括号，例如
`response_format.json_schema.schema.properties["a.b[0]"].items.type`。
缺少字段定位到应提供的字段；schema总字节/深度/节点、工具个数等
整体限制定位到超限容器/节点；多个无效元素的组合定位到组合字段。
成功调用清空位置，未传位置指针的既有调用保持可用。

## 成组验收

1. 公共host与生产必需host检查、新增精确路径回归；构建零警告。
2. 用旧默认的已测源码和本次源码分别构建CPU探针。同一固定语料
   比较接受/拒绝、错误码/message以及成功请求的完整prompt/grammar；
   新版失败位置与独立预期逐项比较。涵盖工具/控制/schema各拒绝
   分支、字节/深度/节点边界、转义键，以及auto/raw/none正例。
3. 一次短GPU租约内运行实际模型与本机TLS双Key入口。12类错请求
   各经JSON chat、stream=true chat和preflight入口拒绝，保持HTTP400
   JSON错误并带请求关联身份；负例不启动grammar或生成。之后验证
   普通答案、strict JSON、两个客户端真实项目资料工具及引用。
4. 上限1模型、6次成功生成、36次负例、80控制请求、GPU300秒。
   原GPU锁保持；发现竞争/监控失败按ENV_ABORT，仅清理自有进程。
5. 通过后保留前一默认可核验回退包，使用已有发布事务安装完全相同
   的已验ELF并同步sidecar；复用其HTTP证据，不重复推理。旧托管包、
   私有Key及三份day计划保持，不自动升级历史任务的协议身份。

真实结果另记，不把开发/CPU通过写成HTTP或默认交付通过。实际LAN、
正式运维策略、源盘丢失灾备、物理RAM与用户长验仍是独立未完成项。
