# 审计P2第三阶段：验证入口与最终收尾

本阶段只修A8工具和完善已交付修复的回退入口，不改变运行时算法、
程序字节或服务配置，不新增模型启动/HTTP/profile。A1～A7的CPU、
真实GPU和HTTP证据按各阶段源码/二进制身份复用。

## 冻结范围

- guard取得共享锁后、监控和子进程启动前，检查pidfd_open及
  pidfd_send_signal API可调用性，并对自身执行pidfd open＋signal 0
  实际能力探测。失败记录ENV_ABORT/75，child_returncode为空，
  不启动子进程；探测FD必定关闭，不降级到不安全的裸PID信号。
- 取得锁失败/恢复标记的现有优先级保持；借用外部lease时能力失败
  仍保留外部持锁方的锁。已有自有后代清理、setsid后代、PID复用及
  不影响无关进程的合同保持。
- 公共host CMake验证guard解释器，默认Python不支持时选择本机
  支持者；显式指定不支持的Q4T_GPU_GUARD_PYTHON时配置明确失败，
  不跳过guard测试。其他Python/numpy测试的解释器策略保持。
- 通用封条回退入口验证上一版/候选的已知身份；未知默认、损坏包、
  外来恢复标记拒绝覆盖，自有标记支持中断后的部分配对恢复。
  当前guard可以恢复历史封条，不要求旧guard源码继续留在工作树。

## 检查与交付

成组修改后运行完整guard CPU合同（含真实自有后代清理）、回退
fixture合同，以及公共host构建/完整CTest。用实际不支持pidfd的
Python 3.13执行一次guard无子进程拒绝及CMake显式解释器拒绝；
默认公共host配置证明自动选择可用解释器。全部构建零警告。

不重新运行已通过且源码不变的模型验收。封存本阶段代码/工具身份、
CPU原始记录、最终8项状态、阶段回退链；默认程序字节保持第二阶段
已验收身份，发布元数据补记工具阶段接受与全部已修项。元数据仅在
核对当前已知配对后原子替换，另存更新前副本和完整可核验回退对。
最终更新STATUS/日志/结果，提交推送codex/audit-p2-fixes，不自动合main。
