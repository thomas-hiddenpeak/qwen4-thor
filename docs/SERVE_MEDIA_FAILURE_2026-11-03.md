# SRV-02h：媒体所有权与主机内存异常

2026-11-03冻结。长期目标仍active。本批是可靠性/缺陷修复，不是性能优化。
父默认3fd31a21、sidecar3ba0b8d3，完整身份以阶段包冻结为准。

## 已确认缺陷与修复合同

- 显式启用媒体后，视觉加载错误被吞掉并退回文本；改为拒绝启动。
  loader/index和tower有明确所有者，上传完成前不能销毁加载器。
- 视觉部分block、RoPE和请求pixels/output在失败/host异常时失去所有者；
  position缓冲释放后可能保留旧指针。统一一次性回收，失败workspace清空，
  保留已加载权重以允许已知分配OOM后重试。完成状态未知时先排空，排空/
  内部释放失败立即退出，不继续析构。
- 媒体坏输入400；仅已知设备分配OOM为503 device_memory_exhausted；
  其他设备失败503 device_memory_failure并停止服务。锁内错误不能递归
  获取model_mu。任何失败都不能发布视觉输出/伪造成功终态。
- PNG/JPEG解码结果用RAII持有，CPU resize/帧复制抛出异常也能释放。
  C malloc/realloc失败通过thread-local标记观察；待解码器完成自身清理
  返回后转bad_alloc，禁止在C分配回调直接抛出而跳过内部回收。
- std::bad_alloc有固定缓冲503 host_memory_exhausted；已发SSE头后为
  error加一次DONE；已开始但未完成头部、已终态/完成时不追加第二响应。
  未完成响应写入只记录实际结果。持续C++分配拒绝下验证兜底和边界；
  不把单次注入当作真实系统OOM或保证所有请求可恢复。
- 请求诊断对象构造失败仍计入请求/错误计数。后端区域host异常沿用
  保守排空停服，不承诺所有bad_alloc都保持同PID。
