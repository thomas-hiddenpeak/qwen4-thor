# Chat音频输入与剩余音频合同

这组实现A01/A02/A10/A12中的真实Chat音频输入，复用已经交付的
原生Qwen3-ASR和隔离codec，再由主模型处理识别出的用户内容。
不引入外部ASR服务，不声称主模型原生编码声学特征；非语言声音、
语气等超出转录的信息仍需对应后端能力，不能以文本桥接宣称完成。
原重叠语音质量失败及托管资格保持未完，不因切换独立任务消失。

依据2026-11-18实际抓取的[官方Chat音频说明](https://developers.openai.com/api/docs/guides/audio-chat-completions)
与本地Python 2.8.1、JS 7.47.0类型：user内容中的input_audio
含data（标准base64）与format（wav/mp3）。音频输入与输出选择
分开处理；语音输出、assistant非空audio历史、Realtime继续必做。
不把字段放进allowlist当作已经可用。

1. **CA01输入与投影合同**：复用严格base64及音频格式检测，保留
   原消息/part顺序，逐项原路径错误，受限字节/数量、取消与原子性。
   所有音频完成前不发布部分文本；输入身份改变必须拒绝投影。
2. **CA02实际执行与计费**：同一请求、deadline、RPM/TPM租约与
   完成进度执行真实ASR；主模型接收原位置转录。ASR实际输入/输出、
   主模型输入/输出分别可追踪，失败/取消也结算，普通辅助故障隔离。
3. **CA03组合与状态**：统一schema、CLI/能力、JSON/SSE、工具/
   结构化、文件/图像/检索组合、缓存与存储保持来源；Batch/preflight
   的模型准备和实际预算接入，不能静默丢音频或用预估冒充实际tokens。
4. **CA04业务与交付**：双SDK真实中/英文wav/mp3、文本回答、
   多段顺序/静音、取消、容量与辅助恢复；主/轻资格与原生TLS、
   可回退发布。仅针对受影响行为，旧数值和无关业务证据复用。

CA01先冻结8CPU/180秒、0GPU/HTTP：格式与位置、字段/角色、
base64、格式声明一致、请求共享容量、取消/超时原子性、完整投影
与相邻内容、身份变化/重复完成/坏UTF-8。共享源字节默认25MiB、
最多8音频part、转录总UTF-8上限1MiB；属于资源上限，不截断。
codec实际解码、ASR执行和服务计费后续接线，不以本组CPU通过
宣称Chat音频已交付。默认rev296不变，全部master持续推进。

CA01的8CPU与2来源检查已通过。CA02接入共享请求的ASR执行与
实际usage，不单独发送转录SSE，回答沿用Chat JSON/SSE。转录
准备输出独立于用户回答上限，但全部计入TPM与完成usage，附
q4t_audio_preparation明细，audio_tokens仅计真实encoder位置。
多个片段共享配置的音频时长与转录输出上限，ASR普通故障沿用
独立健康状态，设备故障继续共享保护。

本组冻结12CPU/180秒（重构后8输入合同、2规划合同、2用量
组合）及2来源检查，0GPU；必要host/生产构建单列。之后补
Batch/preflight、schema与实际业务，未到业务驱动冻结前不加载
GPU。语音合成/历史/Realtime、原重叠质量与全部master保持必做。

CA02的12CPU已通过（0.008秒）。首次生产构建暴露缺少
RequestDiagnostics完整定义，补显式include后继续必要构建，原记录
保留。CA03固定6针对性检查/180秒：2预算/预检CPU、1真实对象
存储的Batch冻结/计量CPU、1受影响RAM估算CPU、2协议schema与
双客户端保留检查，另2来源检查；0GPU。未改变的12项证据复用。
Batch输入只预留上界，ASR在持久started标记后执行；预检明确未
解码/转录和未完成精确预算，不能把估算计入实际usage。音频检索
在转录完成后形成查询；此后才冻结实际业务短验。

CA03首轮3/6通过，原失败保留：配额夹具漏max_output_tokens；
文件组合夹具应使用Chat合同的PDF；schema客户端追加说明应只核对
原始part未变，不能要求完整消息字节不变。另生产构建修正OutputJson
命名空间。固定仅重验3失败项/180秒与2来源，其他3项直接复用；
0GPU，随后真实业务。

CA04第一组固定1能力声明CPU+2验收器负控/180秒、2来源；必要
构建与既有英文WAV转MP3/静音容量夹具生成单列，0GPU。随后同一
严格租约1主模型启动、13生成请求（含1实际Batch行）/900秒，
双SDK真实中/英文wav/mp3、n=2共享准备量与单RPM、原始存储、
多段音频与真实项目文档工具/JSON闭环、静音、无效base64、总时长、
执行进度后取消、ASR缺资产故障隔离与同PID恢复。默认不改，不
重复重叠质量或性能矩阵；此组后继续托管资格/恢复交付与全部master。

CA04计划首冻在0启动时被2MiB元数据上限拒绝：重复内联base64。
保持上限，改固定clip路径/SHA256及类型化标记，发请求前展开；
http-01原计划保留。仅1新物化/原子性CPU检查/60秒，复用已过
3项与来源；下一组仍1启动/13请求/900秒，无额外GPU预算消耗。
