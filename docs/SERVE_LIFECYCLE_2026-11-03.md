# SRV-13 较长运行、退出重启与发布回退合同

目标仍是工业化serve完整范围。本阶段不改模型或运行时算法，复用已
接受3cd3994d/bb620240、199运行时来源、零警告及数值/模板证据。它要
补的是一小时同进程混合业务、带在途请求的退出、崩溃后新实例、实际
版本回退与恢复；一次通过不等于天级长稳或全部生产部署已接受。

## 实现范围

增加可复用发布身份清单、两份已知pair的冻结/切换/恢复入口。清单
逐项核验ELF、sidecar和构建cache；检测环、缺失和不匹配；遇到明确
previous_release_was_stale必须停止为legacy边界，不能把历史sidecar
当可安装pair。只验证身份，不以文件存在代替业务接受。

切换使用固定当前3cd3994d和上一版84d16983及各自sidecar、v4/v3规则，
完整GPU lease内且停止自有服务后执行。每文件原子替换并保留durable
恢复标记，不声称两个文件跨掉电事务。部分已知状态允许恢复原当前
版本；未知文件/标记/占用拒绝，禁止覆盖其他任务。恢复不重放请求、
不自动启动服务。CPU实际临时文件覆盖四种混合状态和中途故障。

原text-v1 supervisor仍是历史profile，不自动推广到当前MTP/工具服务；
本轮不安装常驻systemd服务、网关或通知接收器。

入口与独立恢复命令见[工具说明](../tools/serve_lifecycle/README.md)。
成组CPU24项首轮通过；SIGALRM按原lease时限保留90秒清理余量。
当前只是开发/CPU通过，尚无本阶段真实业务接受结论。

## 固定实际序列

全部模型/HTTP验证和发布切换同一把GPU锁，loopback固定端口。完整
head、MTP k3、seq1、len8192、prefill2048、inflight8/queued2、默认
2048MiB内存准入；不做人工内存压力、权重缓存清理或性能优化。

1. 当前默认启动，同PID运行240个固定混合周期。每周期三个真实并发
   请求：普通JSON、普通SSE、strict JSON/SSE交替；再真实MODEL资料
   工具调用/结果回填两请求，外加1预检。共1200生成和240预检。
   预定周期起点间隔15秒，完整观察不少于3600秒；处理超过周期时
   顺序继续，不突发追赶或增加请求。阶段最多4500秒，不作吞吐SLO声明。
2. 同实例新增活动普通SSE与已准备/排队strict SSE各1，确认活跃输出/
   worker/等待后SIGTERM。两请求须明确server_shutdown终态，退出≤45秒，
   自有worker/连接/作用域回收；不是正常完成，也不自动重放。
3. 当前版本新实例，普通恢复1＋真实工具2；对上一实例两旧ID取消均
   404，明确重启不保留活跃请求登记、404不证明未执行。再启动普通
   活动SSE＋排队strict SSE各1，用pidfd SIGKILL仅杀自己的模型父进程。
   客户端拒绝截断终态，保留UNKNOWN；观察原worker退出，再清理自有
   scope。未知任务不自动重放。
4. 当前版本再启，普通1＋真实工具2，对崩溃前两旧ID取消404。跨实例
   诊断delta不可用，不能把counter reset当负增量或补零。干净停止。
5. 实际把默认pair切至已接受84d16983/c5203331，用v3规则/配置合同启动，
   普通1＋真实工具2，干净停止；再切回3cd3994d/bb620240，用v4合同
   启动，普通1＋真实工具2，干净停止，最终默认保持本阶段开始身份。

计划1216次生成尝试＝1212成功＋2正常停机中断＋2崩溃未知；4个旧ID
404负响应，240预检，5次模型启动。硬限生成1224、负响应8、预检240、
模型启动7、控制观察5000、总6000秒（首次lease至finalize）。不因失败
自动重试、延长小时段或扩大预算。新请求用新ID；恢复业务不是重放。

## 资源与证据出口

每周期所有业务owner归零、slot1/1free、worker started=reaped；独立
1秒资源观察记录父/子RSS、FD、线程、memcg current/peak/stat/events与
整机MemAvailable，量纲分别保留、不相加成统一物理RAM。采样失效/
身份改变/缺OOM计数为ENV_ABORT，只清理自己的进程并保留现场。

前16周期为固定预热，后224周期相对预热最大值的静止包络：父RSS
最多+64MiB、memcg anon最多+128MiB、FD最多+2、线程最多+2。沿用
SRV-02d工程包络、延长观察时间；不以RSS平稳证明GPU/物理内存无泄漏。
每60周期和实例交接留身份绑定诊断，counter只能同实例/合同比较。
SIGKILL前保留原worker PID/start ticks；清理前区分已退出/僵尸与仍
在运行，不用控制器kill后结果冒充PDEATHSIG自行回收。

先成组CPU验证发布清单、切换恢复和实际驱动的失败判定，冻结提交后
再运行上述单lease。保留全部原始请求/wire/日志、开始和退出身份、
阶段对账与失败，不将缺失采样补零。证据大的原始时序可无损gzip入库，
必须同时核验解压字节与原SHA，不能用摘要冒充完整原始记录。

通过后更新矩阵/STATUS/日志和阶段提交推送；当前默认pair不为测试
报告变更身份。失败停止该阶段，已知默认状态恢复至3cd3994d；检测到
竞争、未知文件或无法清理时保留恢复标记，不干预其他服务。
若已完成切到完整previous、后续环境不允许安全切回，则保留完整
previous及执行记录并报告未恢复；不会伪造partial marker或宣称current。
实际入口/TLS/鉴权/多人配额、原始日志轮转/告警通知、物理RAM与启动
硬保护及通用应用任务恢复仍是独立未完成项。
