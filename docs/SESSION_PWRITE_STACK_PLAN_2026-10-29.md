# 栈采集错误及子集补测冻结方案

2026-10-29 用户授权：先取得 stack helper errno、验证异常收尾，再仅补
子集 10 HTTP/2 恢复。任务为采集工具缺陷修复与诊断，非新推理性能候选。
从 09:00:28 UTC 起总 60 分钟：工具/CPU 截止 09:30:28，条件 HTTP
截止 09:50:28，归档提交截止 10:00:28。不重跑完整 head 或整套验收。

- 先读原记录与 Linux 对应 helper，分别保留原事故未知和新复现 errno，
  不把人为注入的 errno 当成原事故实测值。
- 最多两直接写夹具、合计 64 MiB；最多三次无 GPU 栈探针会话，分别
  用于实机 errno 观察、可控失败收尾、修复后边界。必要编译不算测试。
  CPU 合同统一执行，只有真实失败可修后重验受影响项，不扫描参数。
- 原始 errno 独立于 ring buffer 保存；异常后 detach、drain、尾部落盘、
  栈表及计数保存，核对 emitted=received=persisted、partial/pending=0，
  错误状态不转通过。栈身份不能因哈希碰撞被覆盖/错误复用。
- 未取得可解释 errno 或收尾/关联合同未通过则 TOOL_UNAVAILABLE、0 HTTP。
  有缺失必须明确范围，不能以主链完整冒充栈完整。
- 条件阶段仅一次服务、子集原 ON→OFF 两事务各四请求，再两次覆盖后
  恢复；同 46958b6c 程序及冻结原材料/请求配置，四槽与缓存保持。
  预处理复用已完成记录，不再写 64 GiB，跨时段 SSD 状态不当作相同。
  整阶段同一 GPU 独占锁；环境/监控失败 ENV_ABORT，仅停自有进程。
- 采集限制 2 GiB/1000万事件/256 MiB RAM；缺失与观测 I/O 如实报告。
  对慢 pwrite>=8秒分析分层，未复现/无法归属即停止，不扩样。
- 完整 head 10HTTP/2恢复的闭合文件证据及旧未变 A/S/状态合同直接复用；
  原 ENV_ABORT 和缺尾不追改。默认 6f37/5fdc 不变，不安装推理候选。
