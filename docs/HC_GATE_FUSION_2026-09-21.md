# HC 投影与 gate 收尾融合

日期：2026-09-21。基线 f5ef60e，完整 E2E、数值专项与时间线通过，本次改动接受。

## 数据流边界

原路径：四输出投影 → BF16 注入临时缓冲 → ApplyInjectGateKernel
原地计算 gate → CombineWithGateKernel 读取 gate 与 block_output、
residual → 输出。投影结果在 gate 前没有其他消费者。

候选在 T=1、hc=4、hs=2560、normed/权重均 16 字节对齐时，将 gate
计算放进投影 kernel 的 lane 0；其余形状和多 token 路径保留原调用。
投影仍先舍入为 BF16，再转回 FP32、乘 1/4、计算 2/(1+exp(-v))，
再舍入成 BF16 gate。不能直接用未舍入的 FP32 投影和 gate 融合。

注入缓冲分配/释放、combine 公式与调用不变；不复用其他缓冲，也不
改变其地址布局。新专用调用失败时返回错误，不把错误当作成功继续。
原通用 GEMV 的未融合入口仍可用，默认 apply_gate=false。

从源码与基线时间线预算：普通 decode 每步 96 次 HC combine，
预计减少 96 次独立 gate 启动。每次四个 BF16 gate 原地读取及写入
共 16 字节，即约 1536 字节/步的逻辑读写；这不是 DRAM 计数，更
不是显著的模型权重带宽节省。主要假设是减少启动与依赖开销，
实际次数和耗时必须在完整 E2E 后核对。

## 完整 E2E 后的专项

`tools/verify/compare_hc_gate_fusion.py` 从 f5ef60e 提取旧 HC 投影与
原 ApplyInjectGateKernel，对比候选快照。两条比较路径分别是旧/新
未融合投影，以及“旧投影→旧 gate”/融合投影。覆盖随机、小值、
大值、正负零、抵消、subnormal 与四种 alpha；包括 gate 饱和输入。
2048 组、8192 个 BF16 输出逐位相同，无非有限输出，构建零警告。

这里检验 kernel 数值，固定 HTTP 题检验模型路径；两者不能推广为
完整业务精度、所有并发/MTP/多模态输入的全面证明。

## 真实 HTTP 时间线与净收益

1K HTTP 采集、导出、服务关闭均正常；专项在采集后运行，没有与
profile 并行占用 GPU。256 输出仍对应 255 次 decode 前向。

| decode kernel | 旧调用数 | 新调用数 | 旧累计 ms | 新累计 ms |
|---|---:|---:|---:|---:|
| HC 投影 | 24480 | 24480 | 343.527104 | 346.871904 |
| ApplyInjectGate | 24480 | 0 | 37.143840 | 0 |
| 合计 | 48960 | 24480 | 380.670944 | 346.871904 |

融合使投影本身略慢，但两步合计累计耗时净降约 8.88%，每步少约
0.133 ms。decode kernel 总数 932535→908055，恰少 255×96 次。
多 token prefill 的 ApplyInjectGate 仍 96 次，保持原路径。异步
分配/释放仍各 554 次/步，MoE counts D2H 仍 48 次/步。

profile 的 decode 窗口 16.438→16.406 秒，带采集开销，不能替代
正式 E2E。五档均值相对上一版有升有降，重复范围重叠，按持平理解，
不宣称稳定整体加速。正式性能参考不重置。

## 接受与后续

接受这项小范围融合：保持中间 BF16 舍入和当前精度，完整 E2E 未见
明确回退，消除一个真实执行阶段且有局部净收益。代价是固定形状
分派及投影收尾分支，未将本次范围扩展到多 token 路径。

下一步回到整体时间预算，不连续堆叠缺乏收益证据的细小特化；结合
已经接受的时间线与权重流量，评估更有规模的执行计划改动。任何
新候选仍先 E2E，不能用局部 kernel 改善替代真实请求验收。
