# SRV-12k 原生启动监听所有权

2026-11-04。可靠性业务修复：原生 Start 先加载模型，Run 才绑定端口，
因此双端口冲突会浪费加载资源，托管层 bind/close 预检也不能消除竞争。
高级 TLS、独立 Key、CIDR、host 配额仍按用户需要选择启用。

## 冻结合同

- 选项和客户端策略验证后，在任何 tokenizer、cache、模型或 CUDA
  启动资源之前，实际建立公共和可选运维监听。SO_REUSEADDR 保持快速
  重启；用 listen 持续占有，避免只 bind 时其他 reuse binder 的竞争。
- 两个 socket 由不可复制的 RAII 所有者共同管理；第二端口失败、异常、
  后续启动失败立即关闭。成功时所有权经过 Start → server → Run，
  无 Run 的析构、Run 前停止、发布前异常、正常排空均关闭且不重复关闭。
  Start 是单次操作，失败后的部分模型/调度资源在 server 析构中回收。
- 加载期间保留 backlog=128 的内核 TCP 等待队列，不启动 handler、
  不产生 HTTP ready；TCP connect 成功不表示健康。客户端用有限期限
  及启动完成后的 HTTP 健康检查；本轮不增加启动阶段 503 处理线程。
  SIGINT/SIGTERM 的现有安装时机不变，启动时系统进程退出回收描述符。
- 端口错误包含 public/operations、地址、操作和 errno；未知/未完成
  Start 的 Run 拒绝服务。监听仍 NONBLOCK/CLOEXEC，不继承到 exec 子程序。
  模型数学、模板、请求解析、额度、调度及缓存算法保持。

## 固定验收

生命周期测试与真实 HTTP 全部纳入同一原 GPU flock，有上限短验：
1 个原生测试进程；最多 5 个无模型 CLI 探针（旧版冲突复现、新版主端口/
运维端口冲突、加载前 tokenizer 失败回收、无效选项）；1 个真实模型，
复用 12g 的有限公共慢头/独立运维/取消恢复及双 Key 真实资料工具场景，
至多 6 生成尝试（5 成功、1 取消）、2 次只读工具、100 控制请求。
总驱动上限 300 秒，保留 45 秒清理；不做小时/天级长验。

通过后保留完整旧默认 ELF/sidecar、接受依据和 cache，替换默认程序

仅重验受影响部分。所有权测试不替代实际 startup 的加载前冲突验证。
