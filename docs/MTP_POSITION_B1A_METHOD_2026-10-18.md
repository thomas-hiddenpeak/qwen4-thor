# B1a补验统计方法与停止判定冻结

2026-10-18；覆盖此前384a6a0中的150请求补验建议，不修改已采证据或
原始验收结论。范围仅B1a，新增采样0，无构建、模型运行或profile。

## 冻结结论

**METHOD_INSUFFICIENT：现有证据加原60+90设计，不能为本次五档性能
持平判定提供有依据的分辨带和差值区间。当前停止点为0请求。**
撤回“先运行60，再视结果进入90”作为可执行验收建议；150仅保留为
历史资源提案，不是有效采样计划。本轮冻结的是明确的不可执行结论及
其统计理由，不用任意数值补齐一张表面完整的GO卡。

这不证明任何150请求设计都不可能有价值，也不证明B1a性能回退。
在当前固定完整矩阵、缺少外部校准、未建立随机误差模型的条件下，
无法论证该设计能支持可信接受；重新分配请求也不会自动补上这些前提。

## 身份、估计对象与统计单位

A为保存的父binary
`8685d8bf4068b81df0f5162d6c55924d93eae793d17664a1b465ca7587d6c6ee`
（源码867b8a6），B为已验候选
`44abd8b1a7edaca41620b87b4cf894427f8397c1e3529ef56512940ef1b44e03`。
模型、runner、输入、精度与运行参数沿用[复审记录](MTP_POSITION_B1A_REVIEW_2026-10-18.md)。
不重编、不换部署；质量、数值证据只按原覆盖复用。

估计对象是该固定HTTP工作负载、相同启动与请求组织下，B相对A的
TTFT和decode差异；不推广到任意生产输入、尾延迟或纯kernel时间。
保护项为on/off × 五档 × 两指标，共20项，不池化或互相抵消。

服务生命周期是最小聚类单位，跨生命周期独立性也不能仅因重启而假定。
每档3次请求是同一服务内、不同请求序号的重复；五档共享该服务状态。
不得把请求、token或SSE chunk当独立重启，也不得把两模式合并增加样本量。
保留1K首请求及后续请求的分列；不删除冷启动观测、不追加热身。

## 固定描述统计；不冒充推断区间

对于服务s、模式m、档位l，三次请求r的TTFT为t，完整延迟为L，输出数为n：

- `T[s,m,l] = sum(t[r]) / 3`。
- `D[s,m,l] = sum(n[r]-1) / sum(L[r]-t[r])`，不平均单请求吞吐。
- 比较a、b时，`dT(a,b)=100*(T[b]/T[a]-1)`；
  `dD(a,b)=100*(1-D[b]/D[a])`。正值统一表示B变慢。

旧提案若仅用于描述，ABBA应分别列`d(A1,B1)`、`d(A2,B2)`，后者
时间顺序虽反向，符号仍保持B相对A。汇总T为各身份两服务T的等权均值；
汇总D按两服务所有请求的总token/总decode时间算，再用上述差值公式。
逐请求同序号对照另列。A0不混入ABBA汇总，也不选择更有利的配对。
这些运算可确定观察到的差异，不能消除时间混淆或生成因果置信度。

## 分辨带与不确定性：冻结为未建立

| 项目 | 本轮冻结值/方法 | 原因 |
|---|---|---|
| 每项分辨带`[-r_i,+r_i]` | 全20项`r_i=未建立`，不是0或无限大 | 无可比的独立校准依据 |
| 差值不确定区间`[L_i,U_i]` | 全20项未建立，不输出名义置信区间 | 未建立跨启动误差/漂移分布或确定性界 |
| 置信水平、重采样方法 | 不适用；不选择t区间、请求bootstrap或拟合漂移 | 不能先选公式再默认其前提成立 |
| 原三次范围、A/A绝对差 | 仅描述观察范围 | 不能作为完整噪声上界或回退容忍额度 |
| HC/历史跨日数据 | 不用于校准 | 身份、插桩、请求组织或覆盖不符 |

这里不是遗漏统计方法，而是冻结“当前没有可辩护的推断方法”。不能将
未建立项填0.5%/1%，不能由B的观察差值反推r，也不能放宽r来覆盖区间。
时钟精度和工具计时分辨率不能代替服务端与环境的重复测量分辨能力。

可辨识性检查：对任一指标取正值性能量的对数，可写观察式
`z_s = mu + theta * I(s为B) + u_s`。u包含启动状态、时序及环境变化。
在u的分布、漂移形式或幅度界均无依据时，给定任意theta都能选取u
得到同一组观察值。因此目前不能从有限观察给theta一个可信有限界；
这不是计算出了某种置信区间。ABBA仅在附加漂移假设下有帮助，固定
次序和不等间隔不能证明该假设。也不能靠拟合后残差小来验证它。

## 为什么60门禁不能放行90

60请求 = A0/A1 × on/off × 五档 × 3。对每个模式/档位，仅有两个
聚类观测、一个A/A差值。同服务内三次不能增加启动层的样本数。
两次接近只说明这两次接近；两次不接近能揭示问题，却不能据此得出
完整波动界。仅凭这两次无法验证独立性、平稳性、分布尾部或漂移界。

150请求全部用完，每模式也只有3个A服务、2个B服务；用于ABBA的
每身份仅2个服务。最后一个A2只能检出部分失配，不能单凭一次通过
验证分辨带的覆盖能力。通过A/A门禁后再做推断还涉及筛选条件，不能
忽略该条件而沿用无条件区间。小样本并非逻辑上禁止所有参数模型，
但本项目没有支持那些模型的独立证据；因此不能硬套模型宣布持平。

冻结的门禁是以下合取条件，缺任一项即停止：

| 时点/条件 | 放行所需内容 | 当前结果 |
|---|---|---|
| 采样前方法门禁 | 20项可用分辨带依据、区间方法及其适用性，能评估计划的决策能力 | **失败，停在0** |
| 采样前范围门禁 | 身份、完整顺序、请求上限、有效性与停止规则已冻结且获采样授权 | 本轮明确不采样 |
| 60后有效性门禁 | guard/进程正常，身份/输入/输出/请求位置/长度完整一致 | 未执行，不能预填PASS |
| 60后方法适用性门禁 | 使用采样前已确定的校准验证规则；A0/A1未推翻其适用性 | 无该规则的可信依据，无法放行 |
| 进入90 | 上述全部满足；不能用“差很小”“方向一致”替代方法门禁 | **当前不可达** |

所以不存在本方案下“60请求测成什么数就可以进入90”的合法数值条件。
这正是撤回旧提案的原因。即使未来这60请求另获授权作为测量探索，
其性质也只是探索，不自动接续90或追认为验收校准。

## 接受、拒绝及停止出口

1. 本轮立即结束方法设计，新增请求预算为0，B1a性能保持
   `INSUFFICIENT_EVIDENCE`；方法方案记`METHOD_INSUFFICIENT`。
   不将方法失败标作候选性能NO_GO。
2. 若另有可比独立校准证据，须另立有界方法修订，先确定r和区间的
   覆盖解释、适用环境、验证规则及选择门禁的影响，再讨论是否采样。
   当前不自动启动校准研究、不提出未经依据的新样本总数。
3. 有效方法下仍沿用EVALUATION：全部20项区间上界不超过相应回退
   边界且合同通过才能接受；任一项区间整体越过边界，或独立机制证据
   已确认退化，才支持性能拒绝；任一分辨带/区间缺失或跨边界均未决。
   不显著不是持平；已确认真实回退不能用分辨带掩盖。
4. 若以后另行执行，环境竞争/监控失效为ENV_ABORT；输出/身份不符
   则停止并按具体问题分类，不混入性能估计，不删样本或自动补跑。
   任何预算尽而仍未决都停止，不以文档修订恢复同类采样。
