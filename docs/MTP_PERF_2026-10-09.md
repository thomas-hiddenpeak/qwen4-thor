# MTP 性能改善阶段协议（2026-10-09）

用户 2026-10-09 批准磁盘删除并指示推进 MTP 性能改善。本阶段以
main 7f6a69c（合并提交 ff5f495 之后）为基线，工作树
.q4t-work/mtp-perf-20261009/source（分支 codex/mtp-perf-20261009），
干净构建 binary 476743f681dc0df312d78647b2cf5302735284978d3528b8f39a0c88fe6ce19d。

## 目标

降低显式 sequential MTP 相对普通 decode 的 10%–12% decode 开销
（最终五档实测，见下表），在保持精度与质量的前提下取得
"decode 不低于普通生成"或明确的有界改善；不追求 TTFT 或
整请求结论。默认 MTP 保持关闭；快速 T4 保持实验状态。

## 基线（最终候选 eae6949b 五档，同版本普通 vs sequential）

| 上下文 | 普通 decode tok/s | sequential decode tok/s | decode 变化 | 整请求变化 |
|---|---:|---:|---:|---:|
| 1K | 18.566 | 16.599 | −10.594% | +12.163% |
| 4K | 17.852 | 16.030 | −10.206% | +10.754% |
| 8K | 18.068 | 15.894 | −12.032% | +11.555% |
| 44K | 17.855 | 16.059 | −10.057% | +5.876% |
| 200K | 17.055 | 15.303 | −10.271% | +4.472% |

decode 回退幅度各档近似恒定（10%–12%），整请求开销随 prefill
占比增大而缩小；开销主体在 decode 每 token 成本，不在初始化
（初始化成本已由 MTP_INIT_TIMING_2026-10-08 归因，200K 占
TTFT 95.3% 为主 prefill）。

## 阶段顺序

1. 有界小修（已完成）：tools/bench_full_attn.cu:333 预存在
   unused-variable 警告（干净构建口径）。只改 bench 工具，
   q4t binary 身份不变（476743f6 复核），全量重建零警告。
2. 开销归因（本阶段第一项）：定向短档 1K/4K，同一 binary
   普通 decode 与 sequential MTP 各 3 次固定输入；启用现有
   Q4T_MTP_TIMING（draft/verify/extend+accept 分段，stderr
   [mtp-timing] 行）与客户端 TTFT/decode 指标。不改运行时代码、
   不动 GEMM。产出：每档每步分段耗时、接受数 a 分布、按
   "每输出 token 成本"折算的 draft/verify/extend/overhead
   归属表。
3. 依据归因冻结一个有界候选（改动范围与回退开关），走
   五档 E2E（tools/evalscope 真实 HTTP，普通 vs 候选，各档
   3 次、输出 256）+ 固定质量 11 题。
4. 候选接受条件：五档 decode 不低于普通（或回退在基线重复
   波动内且复杂度下降）、质量 11/11、容量与身份保持、
   服务正常退出。不接受条件：任何档 decode 超波动回退、
   质量下降、默认行为改变。

## 约束

  归因运行是只读诊断，不产生接受结论。
- GEMM 冻结；不改数值合同；MTP 默认关闭不变。
- 证据放 .q4t-work/mtp-perf-20261009/attribution-20261009/

  寻找有利结果。
