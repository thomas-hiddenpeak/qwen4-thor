# 已知尺度缺陷的组合传播对照

## 范围与顺序

原4K仍输出600440，预期360284。已知E4M3高区间编码错误到达
实际量化；先前运行时高值修正候选4K改善、1K/44K退化，已拒绝。
本轮从冻结接受版实际输入建立有界传播，不恢复被拒候选、不改
运行时、不新增性能结论。此前HTTP观测不变性证据允许离线复用，
必要参考构建均零警告。模型目录只读。

## 首层输入尺度 → gate/up

保持首层HC mixed输入、实际路由、checkpoint权重、矩阵alpha、
记录算法和行映射。CPU独立E4M3最近偶数舍入，用冻结device ratio
重编码尺度并重算E2M1输入。CPU ratio逐位同设备、独立RNE同
冻结native参考；尺度变化只有[248,432)高区间，其他变化0。
FP4字节变化只出现在尺度变化组；不修正中间量化或其他层。

| 范围 | 结果 |
|---|---:|
| 输入尺度组（含十路专家复制） | 6553600 |
| 改变的尺度组 | 3800 |
| 改变的FP4元素 | 37180 |
| 涉及唯一token | 378 |
| 改变的专家输入行 | 3780 |
| 完整GU BF16输出 | 52428800 |
| 改变的GU输出值 | 4567449 |
| 改变的GU输出行 | 3780 |
| 输入不变但输出改变的行/元素 | 0 / 0 |

该结果证明：给定这次首层实际输入与路由，尺度修正会传播到
对应专家行的GU输出，未变行仍逐位相同。它不证明输出误差改善，
不证明改变值越少越好，也不说明最终答案的变化原因。矩阵仍用
记录cuBLASLt算法，不是独立高精度整模型前向。

全部新尺度/ratio/FP4 payload、完整GU输出、差异索引及逐行分布
保留，实际输入及基线GU通过原manifest绑定。首层所有活跃专家
九段checkpoint重读核对。控制器终态后封存2013项并全量核对，
约277MB，预算1.5GB及20GiB余量。证据：
`.q4t-work/e2e/moe-scale-propagation-l0-20260924/`；工具：
`tools/verify/moe_scale_propagation_l0/`。
