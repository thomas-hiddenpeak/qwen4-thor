# 已知尺度缺陷的组合传播对照

## 范围与顺序

原4K仍输出600440，预期360284。已知E4M3高区间编码错误到达
实际量化；先前运行时高值修正候选4K改善、1K/44K退化，已拒绝。
本轮从冻结接受版实际输入建立有界传播，不恢复被拒候选、不改
运行时、不新增性能结论。此前HTTP观测不变性证据允许离线复用，
必要参考构建均零警告。模型目录只读。

## 首层输入尺度 → gate/up

保持首层HC mixed输入、实际路由、checkpoint权重、矩阵alpha、
记录算法和行映射。CPU独立E4M3最近偶数舍入，用冻结device ratio
重编码尺度并重算E2M1输入。CPU ratio逐位同设备、独立RNE同
冻结native参考；尺度变化只有[248,432)高区间，其他变化0。
FP4字节变化只出现在尺度变化组；不修正中间量化或其他层。

| 范围 | 结果 |
|---|---:|
| 输入尺度组（含十路专家复制） | 6553600 |
| 改变的尺度组 | 3800 |
| 改变的FP4元素 | 37180 |
| 涉及唯一token | 378 |
| 改变的专家输入行 | 3780 |
| 完整GU BF16输出 | 52428800 |
| 改变的GU输出值 | 4567449 |
| 改变的GU输出行 | 3780 |
| 输入不变但输出改变的行/元素 | 0 / 0 |

该结果证明：给定这次首层实际输入与路由，尺度修正会传播到
对应专家行的GU输出，未变行仍逐位相同。它不证明输出误差改善，
不证明改变值越少越好，也不说明最终答案的变化原因。矩阵仍用
记录cuBLASLt算法，不是独立高精度整模型前向。

全部新尺度/ratio/FP4 payload、完整GU输出、差异索引及逐行分布
保留，实际输入及基线GU通过原manifest绑定。首层所有活跃专家
九段checkpoint重读核对。控制器终态后封存2013项并全量核对，
约277MB，预算1.5GB及20GiB余量。证据：
`.q4t-work/e2e/moe-scale-propagation-l0-20260924/`；工具：
`tools/verify/moe_scale_propagation_l0/`。

## 后续：中间量化、down与MoE出口

复用已冻结三侧HTTP输入及上节新GU，不新增观测/HTTP。中间
量化先从原GU开始，用完整BF16设备sigmoid表和CPU指定乘法
顺序重算SwiGLU；独立枚举编码保留原E4M3高区间与次正规规则。
原分支1638400组SF、26214400个FP4元素全部逐位恢复，之后
才换入修正输入尺度的新GU。中间尺度编码本身没有修正。

原始down十路合并与shared最终相加也先从冻结实际输入重建，
10485760个F32路由合并值、10485760个最终BF16值均逐位相同。
随后按实际flat/reorder映射新中间FP4至down行序，读取checkpoint
权重并用记录cuBLASLt算法计算；CPU按十槽FMA顺序加权合并，
使用未变实际shared down与已绑定gate sigmoid，FMA后舍入BF16。

| 输入尺度单项修正的传播位置 | 与原结果不同项 | 不同行/token |
|---|---:|---:|
| 中间SF | 43066 | 3780专家行 / 378 token |
| 中间FP4元素 | 359492 | 与SF合计3780专家行 / 378 token |
| down BF16（共104857600） | 9435366 | 3780专家行 |
| 路由合并F32（共10485760） | 967679 | 378 token |
| 最终MoE BF16（共10485760） | 860418 | 378 token |

量化变化未越出GU变化行；down变化未越出中间量化变化行；两个
合并出口的变化均未越出原378个token。新输出全部有限。这里
“最终MoE”是HC write读取的MLP block，不是完成残差写回后的
trunk，更不是下一层或整模型输出。没有据差异数量声称误差改善。

中间量化保存两分支全部FP32激活/ratio、尺度、FP4 payload、
差异与行分布；down/出口保存完整新down、两分支routed F32、
最终舍入前F32/BF16、全部差异索引和token分布。原输入在冻结
来源中绑定，不覆盖旧文件。终态后封存并全量验证：

- `.q4t-work/e2e/moe-scale-inter-l0-20260924/`：5573项，约256MB。
- `.q4t-work/e2e/moe-scale-exit-l0-20260924/`：1632项，约481MB。

模板为`tools/verify/moe_scale_inter_l0/`及`moe_scale_exit_l0/`。
三个矩阵/合并参考与量化参考均零警告构建；生产二进制未变。
这完成了输入尺度单项修正到首层MLP block的有界传播，不是
独立高精度整层前向，也不是运行时候选验收。

## 后续：输入/中间高区间修正四分支

同一冻结原4K请求、首层输入/路由/权重，新增中间单项及双项分支。
中间修正只改变ratio在[248,432)的编码，次正规旧规则保留；不是
所有编码问题一起修正。baseline/input_fixed先逐字节复现前一阶段
完整激活、ratio、量化和差异文件，再计算两组新分支。中间修正
与对应父分支的激活/ratio相同，量化字节变化只在尺度变化组。

|---|---:|---:|---:|---:|---:|---:|
| 原始 | 0 | 0 | 0 | 0 | 0 | 0 |
| 只修输入 | 43066 | 359492 | 9435366 | 967679 | 860418 | 378 |
| 只修中间 | 1485 | 2588 | 3516199 | 2912104 | 2478211 | 1185 |
| 两处修正 | 44550 | 362068 | 12875098 | 3809990 | 3287910 | 1535 |

¹各项均相对原分支，不能把“双项−输入单项”的计数差当作两组
文件的实际差异数。双项相对输入单项另外改变1484个中间尺度、
2589个FP4元素；新/原GU令部分尺度是否落在高区间发生变化。

两项单独修正的出口token交集28，输入独有350、中间独有1157；

这不是线性叠加证明，更不是误差大小、质量优劣或答案正确性结论。

每个新出口分支先恢复原routed/final逐位一致，再传播新量化数据。
三个出口参考helper复用已封存的零警告构建，摘要逐项核对；未

实际输入为高区间修正结果；后续模板已修正文案，数值结果未改。

- `moe-scale-exit-both_fixed-l0-20260924`：1633项，约516MB。
- `moe-scale-factorial-audit-l0-20260924`：三出口完整对照及影响集合。

## 后续：HC残差写回与PLE输入交接

代码顺序确认：mlp_frame在MoE前ReadImpl准备inject gate并保留
residual，MoE返回后Write只读取新block执行gate*block+residual。
本轮干预没有改变这些前置输入，故保持实际门值/残差；不是为了
获得一致结果而固定本应变化的量。相关源码摘要随计划保存。

CPU显式FP32 FMA后BF16舍入，完整4096×4×2560逐项重建。
原分支41943040项与HC捕获输出全同，完整摘要也与既有PLE的
trunk输入相同，接通跨运行数据边界。三分支结果：

| 修正 | HC主干BF16差异 | 受影响token |
|---|---:|---:|
| 输入单项 | 2118970 | 378 |
| 中间单项 | 5747663 | 1185 |
| 双项 | 7747890 | 1535 |

无非有限输出或仅零符号差异；写回变化不越出对应MoE block变化
token。完整四组BF16主干、全部差异及其舍入前FP32、每token
分布保存，匹配位置未舍入值不保存。终态清单全量核对，约461MB，
预算1GB及20GiB余量。证据：
`.q4t-work/e2e/moe-scale-hc-write-l0-20260924/`；模板：
`tools/verify/moe_scale_hc_write_l0/`。生产未改、无新HTTP/性能验收。

PLE在layer1入口执行。代码中key/value投影仅依赖未改变的token
查表embedding，norm_key可复用实际值；query norm依赖新主干，
随后gate、gated value、norm_conv及卷积必须重算。最终还要把新
主干加入PLE结果，不能复用旧残差。卷积K4/dilation3的前向影响
可到t+3、t+6、t+9；实际影响以新旧数据对照为准，不预先推断
全部位置都会变化。当前终点是PLE输入，不是layer1 attention输入。

## 后续：四分支完整PLE传播至layer1 HC读取入口

复用冻结HTTP，两个参考零警告构建。各分支自身trunk重算query
norm、与未变key norm的点积及gate、未变value的广播、conv norm、
K4/dilation3零初态因果卷积、SiLU及两次相加。SiLU先BF16，
gated相加再BF16，最后自身trunk相加再BF16；没有接回旧主干。
CPU按既有指定归约/FMA顺序，设备只执行rsqrt、gate非线性及SiLU。

原分支query norm/gate/gated/conv norm/最终输出、卷积末状态
均逐位恢复。完整最终输出摘要等于原layer1 HC read的trunk，
因此接通下一层读取入口，不只是某个内部孤立张量。

| 修正分支 | PLE最终BF16差异 | 输出受影响token | 超出输入集合的新token | 因果支持集上界 |
|---|---:|---:|---:|---:|
| 输入单项 | 2155162 | 1285 | 907 | 1286 |
| 中间单项 | 5439036 | 2297 | 1112 | 2299 |
| 双项 | 7438628 | 2884 | 1349 | 2885 |

因果支持集由实际conv norm变化位置向后0/3/6/9移位，加新trunk
变化位置组成。所有输出变化都在该集合内；少数支持位置经舍入
没有最终变化，不能直接把结构上界当实测影响。每支输出41943040
项，均有限。更新的92160个卷积状态值，输入单项与原相同，中间/
双项各7819项不同；这仅描述该PLE末状态，不代表整模型decode
状态相同或最终输出不受影响。

所有四支完整中间/最终BF16及更新状态、差异索引和行分布保留。
完整norm/gate数学参数及设备primitive、差异未舍入值、卷积F32
累加和SiLU均保存；匹配最终未舍入值不另存。20项阶段完整覆盖，
终态192项清单全部复核，3180373631字节，在5GB预算内，另留
20GiB。证据`.q4t-work/e2e/moe-scale-ple-chain-20260924/`；模板
`tools/verify/moe_scale_ple_chain/`。无生产修改，无新HTTP或性能结论。

本阶段是一条指定算术的组合传播，仍使用实际前置输入、未变的
查表分支和设备数学；不是独立整模型前向，更不是最终错答解释。
