## 修复的实际问题

- MTP 独立权重、workspace、scratch、verify checkpoint、请求
  trunk 与 host staging 纳入预算；按实际映射张量尺寸求和，
  修复 index 声明总量误用导致的 208896→129753 缩容。
- 加载/扩容失败清理部分资源，成功后发布容量，保护借用的主
  embedding/lm_head；生成时明确资源失败与 scheduler 回退。
- 普通 pooled decode 写入当前 token 的三行 RoPE 坐标，修复
  prefill 范围外仍读取零位置的问题。该修复影响普通生成输出。
- checkpoint 按实际写入行数而非分配容量定位，检查有效槽位，
  拒绝未写或陈旧状态；修复 cap1/cap3 恢复后的状态与 logits 差异。
- 上下文尾部普通 decode 收尾、输出上限和 EOS 优先级，以及
  逐 HTTP ID 的实际路径记录，避免把静默回退计为 MTP 验收成功。

完整缺陷反例、修复结果与原限制见
[首次准入记录](MTP_ADMISSION_2026-10-07.md)。旧错误普通路径只作
兼容对照，不通过恢复错误 RoPE 来维持旧文本。

## 未随基础修复获得的结论

MTP 与普通 greedy 的生成分叉仍未获得完整数值解释；非 serve
CLI 仍走缺少 PLE checkpoint 的旧入口。多流/媒体、默认启用、
完整长文本任务质量及整体物理 RAM 峰值不在本包接受范围内。
预算估算不代表物理内存上限。

有限范围 MTP 正式支持在原研究分支的下一阶段继续，入口范围、
数值合同、质量和恢复行为分别验收。基础修复合入不解除旧 MTP
NO_GO，也不改变 `serve` 默认关闭 MTP 的行为。
