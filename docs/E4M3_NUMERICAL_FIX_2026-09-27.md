## 当前交付边界

按用户确认的数值责任原则，合入此前完整格式修复：高区间正常编码、
次正规最近偶数舍入及进位。它只修改共用FloatToE4m3，不按题目或
运行阶段特殊处理。语义分数变化保留，不能以恢复错误编码补偿。

当前量化接入测试通过；干净构建的HTTP与五档性能采集中，未作
商用发布或严格无性能回退结论。终态结果将在本报告更新。

## 接入验证

测试工具：[quant_integration](../tools/verify/quant_integration/README.md)。
直接提取生产通用激活量化、MoE prefill输入/中间量化和decode模板，
以CUDA原生E4M3转换与独立FP4码表作参考。130行跨越尺度布局边界，
七档正有限尺度；每次检查341600个量化组。

| 输入/实现 | 尺度字节不一致 | FP4字节不一致 | decode alpha不一致 |
|---|---:|---:|---:|
| 合成输入，旧实现负对照 | 9884 | 71606 | 0 |
| 同合成输入，完整修复 | 0 | 0 | 0 |
| 捕获激活，完整修复 | 0 | 0 | 0 |

捕获输入来自此前4K请求：gather-inputs前130行，以及layer0/expert10
GU输出前130行。仍施加七档受控尺度，不冒称原请求完整重放。
两个来源文件全部BF16值均有限，文件摘要留存。

SwiGLU使用相同设备数学表达式；测试不独立验证非线性、GEMM或
整模型前向。各专家尺度相同，不借此证明不同专家尺度寻址。
仅比较有效尺度布局及FP4字节，不验证填充字节或全部越界行为。

检查点147456个input_scale/weight_scale_2全部为正有限标量F32，
49152对gate/up尺度完全相等。该前提属于当前检查点；无效模型与
运行时NaN/Inf的fail-fast仍是独立待办，不能泛化为已经处理。

初版测试FP4码表参考在大值上使用FP32距离比较，精度不足造成
伪差异；加上明确饱和处理后，同输入重新验证新旧版。初版日志与
编译问题保留，不将工具错误归因于生产kernel。
