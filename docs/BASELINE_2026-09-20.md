# 单流普通 decode：evalscope E2E 初始测量（2026-09-20）

本轮 15/15 HTTP 请求成功，五档实际输入长度均匹配，全部生成 256 token 并以
length 结束。它是受控文本负载的初始性能记录，**不是完整精度验收或性能无回退证明**。
开发顺序遵循 [EVALUATION.md](EVALUATION.md)：必要构建后先 E2E，无前置测试。

## 配置与可复现证据

- 模型：Qwen3.8-Flash-Next-NVFP4-SSD-Stream，原 checkpoint 只读。
- 默认 MTP 关闭，未传 --no-mtp；服务日志明确 MTP disabled。FP8 实验开关关闭。
- serve --port 8000 --max-seq 1 --max-prefill 8192 --max-len 208896 --max-tokens 256。
- evalscope 1.12.0，HTTP /v1/chat/completions，stream=true，temperature=0，
  seed=20260920。使用该接口现有的裸 prompt 兼容字段；没有经过 messages 的
  role 拼接路径，不据此宣称 chat template、多轮或多模态路径通过。
- prepare_inputs.py 生成三份固定技术文本/档，原始 JSONL 随结果保存。
  三份文本不同，不能把它们的离散度完全解释为同输入重复测量噪声。
- 服务新启动，无额外预热请求。仅 1K 第一次是启动后首请求，TTFT=0.948s；
  其余两次分别 0.844/0.842s（文本不同，差异不能全归因于预热）。
- [原始结果目录](../.q4t-work/e2e/20260920-baseline/) 保存 commit、工作区 diff、
  构建配置、二进制 SHA-256、依赖版本、服务命令/日志、请求 JSONL、SQLite、
  evalscope 报告与逐请求 [summary.json](../.q4t-work/e2e/20260920-baseline/summary.json)。
  路径为本机忽略目录；需要跨机器复现时应一并保存该目录。

## 结果

TTFT 是客户端首个有效内容块延迟，包含接入、分词、prefill 等，**不是纯 prefill
时间**。Decode 取 Σ(输出 token 数−1)/Σ(请求耗时−TTFT)，包含输出传输和末尾
usage 的少量开销。全请求输出吞吐包含 prefill，两者分列。

| 实际输入 token | 请求数 | 平均 TTFT (s) | Decode (tok/s) | 全请求输出吞吐 (tok/s) | 内容块间隔 P50/P95 (ms) |
|---:|---:|---:|---:|---:|---:|
| 1024 | 3 | 0.878 | 15.51 | 14.78 | 64.06 / 65.78 |
| 4096 | 3 | 3.238 | 14.19 | 12.07 | 70.11 / 71.95 |
| 8192 | 3 | 6.519 | 14.85 | 10.81 | 66.85 / 68.49 |
| 45056 | 3 | 39.741 | 14.45 | 4.46 | 69.08 / 70.37 |
| 204800 | 3 | 234.937 | 13.98 | 1.01 | 71.37 / 72.31 |

内容块间隔来自 SSE 接收时间，可能受 token 文本解码和传输合并影响，不当作严格
逐 token ITL。没有运行内部阶段 profile，因此纯 prefill 耗时仍未单独测量。

## 正确性与适用范围

- 每条请求检查成功标志、实际 token 数和 length 结束原因；流式 usage 以
  服务端计数为准。evalscope 将 usage 保存到数据库计数列，响应列表不保留
  choices=[] 的 usage chunk。
- 技术文本初轮与重启后最终轮的三条 1K 请求输出文本逐字节一致（3/3），
  摘要保存在 summary.json。它不是相对于旧已接受版本的全量精度比较。
- 输出上限 256 是性能工作量约束，可能截断模型思考或答案，不能用于评价答案
  完整性、模型能力、200K 召回或完整数值保真度。
- 尚无同配置旧版本的五档对照与同输入多轮噪声带，不宣称提速、无回退或设定
  固定百分比容忍阈值。后续对比必须复用本轮原始请求并补足重复测量。

## E2E 暴露的问题

1. 旧流式响应未返回 usage，客户端将一条 256-token 输出重新分词为 253。
   已实现 include_usage 支持，并由本轮五档 E2E 验证计数路径。
2. 随机文本目标 1024 token，服务端实际为 932/921/915。未修改模型分词路径，
   换成受控技术文本不代表差异已解决；需独立 E2E 输入对照。
3. 取消第一轮客户端后，原服务进程消失，未保留退出状态，原因未确认。
   需独立断连 E2E 复现，不把它误写为已修复或已确认根因。
