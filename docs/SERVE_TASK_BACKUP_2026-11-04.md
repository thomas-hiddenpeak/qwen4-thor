# SRV-11e：一致性备份与单活恢复交接

直接复制任务库会改变物理身份，手改身份绕过检查又会产生两份可
执行的同store/key。备份之后源库继续写入时，旧快照还会漏掉新任务
与预算。本批实现可核对的停写快照，以及源库仍可验证时的零丢失
恢复交接；保留原业务身份、原事件与未知状态。

## 冻结边界

- 本机可信操作员显式执行，输出仅在build/.q4t-work且0700/0600。
  启用前停旧版客户端，不承诺跨版本在途热升级、多机协调或源盘
  丢失后的灾备激活。源不可核对时不猜测任务是否执行，不自动恢复。
- backup全程持有store和全部活跃任务锁；忙则拒绝，不停止任务。
  验证账本/完整wire/未知状态、归档键及保留正文、SQLite完整性；
  未完成的归档操作、异常文件或未登记运行格式拒绝。
- 快照是私有目录包，逐文件完整复制、fsync、SHA/字节/原物理身份
  清单，最终seal才可用。不是可执行store；不包含API Key/profile。
  清理过的正文不会重新出现，永久键必须完整复制；不自动删除旧包。
  最大字节数由调用参数事前限制，文件数/清单大小有固定硬上限。
  中断草稿保留；仅在源库仍完全相同时可继续，源变化需新快照。
- plan-restore核对已封存快照和源库当前全部内容/身份一致，绑定
  新目标路径/父目录身份、原store、快照摘要及原因。不覆盖已有
  目标，不接受源库的祖先/后代或快照内部路径。
- apply-restore先在目标旁私有工作目录完整恢复和校验；原store_id、
  task_id、账本meta/历史事件/响应/已用预算不改。目录簿策略仅更新
  物理身份；保留正文的键追加placement事件，原键链与正文保持。
  正文计额、Key轮换和已清理状态保持。最多8次恢复交接，身份映射
  不改变内容SHA、保留期或客户端绑定。
- 目标准备完毕且源仍与快照一致后，持久封住源库；再原子发布目标。
  源库之后拒绝普通submit/resume/归档/迁移，新库发布前不可执行。
  新实现普通入口在拿到store锁后再次核对，防止旧检查结果越过封存。
  老代码看到新增元数据拒绝，仍要求先停旧客户端。
- 中断前若未封源，源库仍可用，恢复需重新证明快照未过时；封源后
  只显式继续原计划，不自动回切。目标发布后重复apply不覆盖已有
  新结果。既有UNKNOWN继续要求明确处置；已知工具结果不重复执行。
- 本批不给RPO>0快照提供自动激活，不把文件损坏/源盘丢失/硬件故障
  的恢复完整性写成已证明；这些需要独立的备份介质、单活证明与
  数据丢失处置合同。容量/访问/保留策略变更仍单独推进。

## 验收顺序

成组CPU覆盖现有69应用合同与备份/恢复：忙锁、源变化、永久键与
未知保留、错摘要/目标、容量/链接/异常文件、旧实现拒绝、恢复后
再次备份交接、正文读取/清理、同client Key轮换、原事件字节保持。
真实进程SIGKILL覆盖备份复制/封条、目标复制/元数据重绑、源已封与
目标已发布；新进程继续，检查至多一份可执行、重复apply不回滚新写。
原411/263/468/402证据直接离线重建，失败保留，定向修正后只补受影响项。

CPU通过后冻结单次真实TLS/模型短验清单：源任务保存真实工具结果
后中断，快照/交接后只生成最终回答；另包含未知请求保持和归档键
清理后重复零执行。具体生成/启动/控制/墙钟预算在驱动完成后冻结，
未冻结不启动模型；全程同一生产guard，不运行用户长稳或改默认包。
