# N07 原生配置、生命周期与发布事务

2026-11-09。属于 Serve 总计划 N07，功能/可靠性开发，不是性能优化。
N07 完成后继续总计划其他任务；本文件不改变 A/R/Q/G 的完成条件。

## 发现的问题

- 管理包 profile、实际启动参数及健康核验使用固定常量，无法完整
  表达部署容量；只修改 manifest 不会改变真实进程。
- build/q4t 的 ELF 没有 service 子命令，必须记住另一入口；现有服务
  入口没有统一 check/reload，跨版本目标选择也依赖手工调用模块。
- 默认 ELF、发行元数据、服务包指针及服务元数据由交付脚本分别
  替换。进程内异常回退不是掉电/中断可恢复的发布事务。

## 实现顺序与出口

1. 容量配置贯通：严格 schema、规范化 profile、不可变包绑定、实际
   argv、有效配置核验及全局/客户端公平准入一致。保持老包格式和
   默认值。MTP 可选择开启/关闭，容量不冒充已验证降级配置；R05
   仍须实际验证。配置错误在创建包/启动前失败。
2. 统一 q4t service：接入自有封装入口，提供 prepare/check/run/
   start/status/reload/stop/deploy/rollback；check 不加载模型，reload
   明确区分可热更新项与需受控切换项。选择其他目标包使用当前
   工具验证当前与目标，避免旧工具无法识别当前版本。
3. 发行事务：保留可核验旧版，持久阶段/身份/CAS，统一默认选择点，
   发布中断可续接；默认程序、服务包和元数据来自同一代。与既有
   STOPPED 部署事务/锁衔接，不重置 Key、限额、用量、核心账本。
   提交前失败不发布半套；未知提交明确阻止新启动并提供恢复入口。
4. 真实业务与交付：同一严格 GPU 租约验证可配置容量、统一命令及
   正常停止，保留已通过的协议业务证据；封装随包 CLI、旧版回退
   及默认发布验收。外部 nginx 不存在时仍能完成整个生命周期。

## 验证边界

先成组实现再运行本组针对性测试。第一组覆盖容量类型/范围/组合、
argv 与观察合同、包身份/历史版本、客户端公平容量和 CLI 参数传递。
在执行前冻结具体用例清单。后续 CLI/发布事务分别覆盖实际子进程、
并发锁、断点续接、未知提交与回退状态保持，不重跑无关全套。
真实短验在驱动完成后冻结固定启动/请求/时间预算；不做完整性能、
全模型正确性和用户负责的长稳实跑。必要构建不算测试。

当前处于开发，尚无本组新测试/模型启动；N05 默认保持 STOPPED。
