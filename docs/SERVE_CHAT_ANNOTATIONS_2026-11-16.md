# Chat引用历史的输入、模板与持久往返

2026-11-16，继续A02/A01/Q01，不结束总计划。当前rev188明确拒绝
assistant非null annotations；即使客户端回填标准Chat消息也会失败。
修复这一实际缺口，并保持其余音频、联网检索生产者和全部master任务。

## 行为合同

- 接受assistant的url_citation数组及已有null；校验类型、结构、标题、
  绝对URI和原content的非负字符偏移，拒绝字段丢失/非法角色或越界。
  URI仅作为历史数据，不据此自动联网或访问文件，不把客户端引用
  冒充服务端已检索结果。复用已有本地URI校验，无新外部依赖。
- 内容、角色、名称、拒绝、工具历史与引用元数据一并进入原生模板；
  引用说明属于原assistant消息，偏移指向原content。元数据中的控制
  token须按数据转义，不能改变消息边界或角色。不修改用户原JSON。
- 统一schema、原生预检、Python/JS输入、持久Chat查询和恢复后的
  消息往返保持引用；无annotations的模板/缓存断点行为保持。
- 本组只解决引用历史，不声称联网搜索输出已实现；A01的实际检索、
  引用生成及响应流仍在总任务中，不能因可回填而关闭这些缺口。
