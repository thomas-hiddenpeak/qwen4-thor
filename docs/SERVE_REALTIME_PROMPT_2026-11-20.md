# Realtime Prompt 原生接入方案

本项属于 Serve master A10/A12/Q01，不另设总任务终点。当前
`PlanRealtimeChat` 对非空 `prompt` 返回处理器未接入；既有
`/v1/prompts`、不可变版本、变量渲染、客户隔离和对象工作线程已经
存在。待解决的是实际会话与执行接线，不能以 schema 接受或文档
说明代替。本文是实施方案，尚未表示 Prompt 对话可用。

## 已核实的依据

固定的 OpenAI JS 7.47.0 在会话和 `response.create` 中均接受
`ResponsePrompt`，包含 ID、可选版本与变量。官方会话示例说明，
直接设置的会话字段覆盖 Prompt 中的同名字段。已有来源保存在
`.q4t-work/serve-realtime-20261119/reference-docs/conversations.md`，
SDK 类型在同阶段 `profile-sdk-01` 中；复用这些已保存身份。

本项目的 `PromptRegistry::Expand` 已实现单次变量替换、确切版本
回显、显式字段（包含 null）优先和实际输入前缀。其权限来自
`StateAccess`，不来自 Prompt ID 或变量。原生对象工作线程负责
有界磁盘 I/O；辅助存储失败不应改变健康 LLM 的 readiness。

## 会话与执行合同

1. 分别保存服务默认值、客户端显式设置和模板展开结果。不能把
   `session.created` 中默认的 instructions/tools/输出预算当成用户
   显式覆盖，否则模板中的这些字段永远不生效。
2. `session.update` 中新 Prompt 先在当前客户权限下解析，再原子
   提交完整设置。未指定版本时选择当时默认版本并回显实际版本；
   普通后续更新复用已固定的内容，不再次追随注册表默认版本。
   解析/渲染/预算失败保留旧设置，并返回关联原 event_id 的错误。
3. `response.create.prompt` 的覆盖只影响这一响应。它不能修改
   会话设置，也不能影响已经排队或执行中的其他响应。显式 null
   清除本轮模板，不能被误认为字段缺省。
4. 实际执行使用不可变展开快照；接受请求后删除模板、切默认版本
   或新增版本不能改变已接受工作的输入。新请求仍执行客户身份和
   权限检查，不能通过长连接或旧快照绕过密钥撤销。
5. 模板输入前缀、会话历史、显式 response.input 分别保留来源。
   模板前缀计入真实模板/tokenizer、上下文和客户配额；不能伪造
   conversation.item 事件，也不能将隐藏前缀的下标错误地用于删除
   客户端历史。自动截断只把实际历史索引回写到默认会话。
6. 共享设置映射与内部模型配置分开保存。Prompt 的有效生成选项
   必须传入实际执行计划，不能只展示 instructions、丢弃其余字段。
   已有 Responses 模板和 Realtime 会话专有配置需明确类型并完整
   校验；补齐所需的定义格式，不以过滤未知字段冒充接入。
7. 模板变量仍是数据，仅渲染一次，不允许把替换结果再解释为模板。
   文件/图像变量继续走实际客户权限和媒体准备；不能把文件路径、
   API Key、MCP 凭证或运行时所有权藏进持久模板。

## 所有权和资源边界

会话线程拥有设置事务；工作线程只持不可变快照。现有 validate
回调是纯校验，不能悄悄增加无限期磁盘读取。为解析单独增加有界
准备路径，沿用对象工作线程的截止时间和取消；消息接收、队列字节
上限、关闭通知和已有请求取消继续生效，失败不确认新设置。

会话和最多四个在途响应的展开 JSON、模板前缀、公共回显及事务副本
均计入现有 2 GiB 会话预留及每计划 64 MiB 上限；按实际容器容量
计量。查库失败返回单次错误，健康普通文本请求继续；无隐式模型
重启、HTTP 回环服务、外部模板服务或新增发行依赖。

## 实施与验证顺序

先完成纯设置覆盖/固定快照组件，再接对象库解析与会话事务，最后
把完整生成计划交给实际执行与历史截断。音频、MCP、追踪等处理器
保持在总计划中继续接通，不因先交付文字 Prompt 而从目标中删除。

成组修改后冻结针对性 CPU 用例：默认与显式覆盖、版本切换/删除、
单轮覆盖/null 清除、跨客户访问、变量非递归替换、并发快照、存储
超时/取消、内存边界及带前缀的历史截断。CPU 夹具须通过原生对象
工作线程，不能仅验证独立 JSON 合并函数。

业务短验使用实际注册模板与真实工具结果，覆盖本机官方 SDK、两个
客户、一次模板版本变更和一次取消后的新请求；不把正确答案预填为
模板常量，也不改原随机回答失败。先明确预算再启动模型，复用未改
身份的证据，不扩成完整性能或全模型质量测试。通过后补主轻/恢复
能力保持及可回退交付，再继续全部 master。
