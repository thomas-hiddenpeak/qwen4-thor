# MTP sequential 有限支持验收记录

2026-10-09。B 达到指定参数/身份下的**有限 sequential 正确性
profile 准入要求**，原失败与定向补件分别保留；不宣称整个快速
MTP 或完整模型质量通过。实现和事前范围见
[严格基线协议](MTP_STRICT_BASELINE_2026-10-09.md)。

本轮目标是交付具有明确数值合同的 MTP 正确性基线。sequential
仍实际产生草稿、验证接受/拒绝并追赶 draft 状态；target 使用普通
scheduler 的 B1 算术，因此不能引用旧快速 T4 的提速结果。

## 支持范围与数值合同

资格只针对本机 Thor SM110a、CUDA 13.3、仓库记录的指定
Qwen3.8-Flash-Next-NVFP4-SSD-Stream checkpoint/metadata、HTTP
`serve`、文本、greedy、S1/slot0、k3、208896/8192 容量。
显式选择为 `--mtp --mtp-verifier sequential`。未指定 verifier 的
`--mtp` 仍选旧 T4；CLI generate、多流、媒体组合明确拒绝。
其他 checkpoint、硬件、容量、采样与并发不随本 profile 获得资格。

启动日志的泛能力类别 `requested=experimental` 按“使用任意MTP”
统一产生，尚不区分 checkpoint 或受测 profile。有限资格以本报告
的参数/身份和实际 `verifier=sequential`、执行路径为准；本阶段保留
该泛类别，避免仅修改标签就扩大支持范围。

生成合同以普通 greedy 为对照：每次 target 读取相同有效 main 状态，
使用同一 B1 forward 与 argmax，只有与该预测相等的草稿才能成为
下一 target 输入；首次拒绝的 correction 留待输出/下步消费。
预测 stop 不再喂入模型；最后输出 token 保持未消费。draft 错误
影响接受率和成本，不能直接决定 main 的输出。正常尾部继续走
普通 scheduler B1。主计算开始后的失败终止请求并排空，不继续
使用部分推进的状态；target 前资源失败才允许普通 B1 回退。

该论证由生产控制 TU、完整有效状态对照和真实 HTTP 接线共同支撑，
有限样本不是所有输入上的形式化证明。状态对照覆盖有效 KV/indexer、
recurrent/PLE、RoPE/page map 与 host 游标/history；未使用的未来
缓存以不可见性检查约束，不要求全部物理存储清零。退出时观察的
清空是生命周期、位置、history 和 pending。HTTP 配对核对完整 UTF8
文本、实际输入/输出计数及 finish；evalscope 原件未保存完整 token
ID 序列，不能称 HTTP token IDs 或原始 total_tokens 均已逐项比较。

质量、持续、边界、取消与五档生产 HTTP 共105条使用同一候选：
`a566faf51975291ec8fcd1fe75d7ddff07760fe13c138f85a066aeffad729563`。
长状态诊断独立构建，运行源码/配置相同但 CUDA archive 不逐字相同；
故障、资源、尾部变体均另有身份，不冒称生产可执行文件本身。

## 已有证据与保留的失败

| 项目 | 观察结论 |

| 长状态定向补件 | 固定首个 8196 持续题面，4 自然 step 与 future 不可见性通过，不重跑短组 |
| 旧 T1/T4 HC 首分叉 | 三次实际 HC、投影与非线性有限包络通过；不能外推整个快速 T4 轨迹获准入 |
| 短 HTTP 质量 | 普通/strict 各 11/11，全文配对一致 |
| 持续 HTTP | 普通/strict 各 8 条，178–512 输出，8 对全文/计数/finish 一致；语义另列 |
| 生成边界 | 每模式原 14 条已完成，14 对一致；两模式末项自然 EOS，原 coverage FAIL 均保留 |
| 取消后恢复 | 9 请求通过；四次恢复与同模式 fresh control 全文/usage/finish 一致 |
| target/extend 中途逻辑错误 | 5 请求通过；实际提交后返回错误，排空/终止，恢复一致 |
| target 前资源回退 | 另冻 3 请求通过；实际 reserve 成功后注入逻辑错误，普通 scheduler 255 次 B1，恢复一致 |
| 上下文尾部控制补件 | 两个固定请求通过，26 prefill/3 B1/最后输出未消费，原 logits 同 SHA 且都是 EOS |
| 正式五档成本 | 普通/strict 各 15 条首次通过 HTTP/配对，strict 成本增加，完整数值见下 |

自然完整 GPU extend 只观察到形状 1/4，2/3 由真实生产 TU 控制与
受控真实 verify 检查覆盖，未宣称完整 GPU extend 四形状全覆盖。
这一区分在首测前已冻结，没有搜索输入补齐有利形状。

原边界末项为 208892 输入、max_tokens=8/nonstream，实际在 prefill
预测 stop，输出计数 1，未到预期四输出的尾部。新增参考准入工具
只让 strict 采集同一失败参考，其自身验收门槛保持；5 项 host
通过。后续强制 selection 补件固定该原题面和 token32，不更换
prompt，不把受控输出作为 greedy 数值、任务质量或性能证据。

资源补件是 reserve 实际成功后注入逻辑 Status 错误，不能称实际
OOM；中途 forward 组也不称硬件致命 CUDA 错误恢复。取消 RST
发生于首个非空内容，实际内容是两个换行，不能称已有可读正文。
这些界限不由通过数或后续恢复文本一致消除。

的正确性参考；泛MTP、快速T4、默认启用与整体任务质量分别保留
