# CUDA 13.4 QMUL4：Thor 隔离编译核验

日期：2026-11-03，23:09 CST。任务是核验指令支持范围，不是性能优化。

## 结论

本机 ARM64 上的官方 CUDA 13.4.92 `ptxas` 明确拒绝为 `sm_110a`
编译 `mul.rn.satfinite.e4m3x4.e2m1x4.e4m3x4`。
相同 PTX 仅替换目标架构后，`sm_100a`、`sm_103a` 均生成真实 `QMUL4`
机器指令；去掉该指令的 `sm_110a` 对照通过。

因此，CUDA 13.4.92 的公开 PTX 编译路径不为 Thor 提供该指令。
这不能证明 Thor 硅片物理上缺少对应执行能力；工具链限制和硬件限制
尚未区分。没有执行 GPU kernel，不产生硬件执行、数值、模型质量或
性能结论，也不否定采用其他转换指令实现 W4A8。

## 冻结探针与实际结果

PTX 版本 9.4。输入 FP4 和 FP8 scale 均来自 kernel 参数，输出写回
global memory，避免常量折叠或死代码删除。三个目标的 PTX 除 `.target`
外逐字相同。对照保留同样的参数、加载和输出，仅将待测指令替换为
`cvt.u32.u16` 与 `xor.b32`，验证工具链能够处理 Thor 和 PTX 9.4。

| 目标及探针 | ptxas 退出码 | cubin | 反汇编结果 |
|---|---:|---|---|
| sm_100a，QMUL4 | 0 | 已生成 | 恰好 1 条 QMUL4 |
| sm_103a，QMUL4 | 0 | 已生成 | 恰好 1 条 QMUL4 |
| sm_110a，QMUL4 | 255 | 未生成 | 明确拒绝指令，不是语法或工具缺失 |
| sm_110a，普通指令对照 | 0 | 已生成 | 无 QMUL4 |

总计一次有界矩阵、4 次汇编、3 次反汇编；无 warning。三个成功目标
均使用 8 registers，无 stack frame 或 spill。Thor 原始失败保持原样：

```text
Instruction 'mul.e4m3x4.e2m1x4.e4m3x4' not supported on .target 'sm_110a'
ptxas fatal   : Ptx assembly aborted due to errors
```

两个支持目标的反汇编均包含：

```text
QMUL4.E4M3x4.E2M1x4.E4M3x4.SATFINITE R5, R4.N3210, R5.B3210 ;
```

本结果与 [PTX ISA 9.4 的 Alternate Floating Point Instructions: mul](https://docs.nvidia.com/cuda/parallel-thread-execution/index.html)
仅列出 `sm_100a`、`sm_103a` 的目标支持范围一致。

## 23:16补充：机器码解码与结论边界纠正

用户指出编译器可能人为限制目标支持。此质疑成立：编译拒绝只回答
公开工具链是否接受，不能据此宣布硬件不存在该能力。此前“支持性问题
已闭合”的表述范围过宽，仅官方 PTX 编译支持已确定，硬件能力仍未知。

从已封存的 sm_100a cubin 的 `.text.Qmul4Probe` 偏移 `0x40` 提取
完整 16 字节指令；不修改原 cubin，也不创建或加载执行用模块。
其两个 little-endian uint64 为：

```text
000000050405727c 001fca000501b800
```

同一个 16 字节文件分别交给隔离 `nvdisasm 13.4.92 --binary`：

| 解码目标 | 退出码 | 结果 |
|---|---:|---|
| SM100a | 0 | QMUL4，与原 cubin 相同 |
| SM103a | 0 | QMUL4，与原 cubin 相同 |
| SM110a | 1 | Unrecognized operation / Illegal instruction found |
| SM120a | 1 | Unrecognized operation / Illegal instruction found |
| SM90a | 1 | Unrecognized operation / Illegal instruction found |
| SM110a，NOP 对照 | 0 | NOP |

这新增的是软件解码器证据，不能当作 Thor GPU 抛出的 illegal-instruction
异常；它和 ptxas 也不能算两个独立的硬件实验证明。
[解码原件](evidence/cuda134-qmul4-20261103/raw-decode-records.json)保存
13 份文本、两个输入的完整十六进制与哈希、源 cubin 身份和全部命令。
本机目录为 `.q4t-work/cuda134-qmul4-20261103/raw-decode/`。

要进一步回答实际硬件是否能执行，需要另做绕过 PTX 的受控机器码
执行探针：以 Thor 原生模块为基础，仅替换已核对编码，区分模块加载
拒绝、实际 GPU 指令异常和数值结果；按项目 GPU 独占约定执行。成功
且数值吻合才能证明所测编码/操作数在该硬件上可用；模块加载拒绝
仍不能证明硅片缺少能力。本次没有进行这一步。
