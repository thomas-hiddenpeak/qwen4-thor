## 当前结论

已将官方 CUDA 13.4.92 为 `sm_100a` 生成的完整 `QMUL4` 指令植入
Thor 原生 `sm_110a` cubin，并在本机 NVIDIA Thor 实际执行。模块加载
和 kernel 提交成功，第一次 `cuCtxSynchronize` 返回
`CUDA_ERROR_ILLEGAL_INSTRUCTION (715)`。同期内核日志明确记录
`Graphics SM Warp Exception ... Illegal Instruction Encoding`，随后
Xid 43 的 PID 与该探针进程一致。

因此，绕过 ptxas 的目标限制后，**所测 QMUL4 编码仍被本机 Thor 的
SM 执行路径拒绝**，不能用“仅工具链限制”解释。原生 XOR、同一位置
植入 OR、故障后新进程原生健康复查各 8/8 数值与 canary 通过。
QMUL4 第一条执行即异常，返回数值为 0 组；计划的 2,097 组数值扫描
没有完成，不能记录为数值通过。

结论范围是这条公开 QMUL4 编码在当前 Thor/驱动组合上不可执行。
它不证明硅片物理上缺少所有类似电路，也不排除未公开的其他编码或
未来使能方式；不能据此否定通过其他转换指令实现 W4A8。
以下按阶段保留证据；23:30 实机结果补齐此前尚未验证的执行层。

## 23:09：冻结探针与编译结果

PTX 版本 9.4。输入 FP4 和 FP8 scale 均来自 kernel 参数，输出写回
global memory，避免常量折叠或死代码删除。三个目标的 PTX 除 `.target`
外逐字相同。对照保留同样的参数、加载和输出，仅将待测指令替换为
`cvt.u32.u16` 与 `xor.b32`，验证工具链能够处理 Thor 和 PTX 9.4。

| 目标及探针 | ptxas 退出码 | cubin | 反汇编结果 |
|---|---:|---|---|
| sm_100a，QMUL4 | 0 | 已生成 | 恰好 1 条 QMUL4 |
| sm_103a，QMUL4 | 0 | 已生成 | 恰好 1 条 QMUL4 |
| sm_110a，QMUL4 | 255 | 未生成 | 明确拒绝指令，不是语法或工具缺失 |
| sm_110a，普通指令对照 | 0 | 已生成 | 无 QMUL4 |

总计一次有界矩阵、4 次汇编、3 次反汇编；无 warning。三个成功目标
均使用 8 registers，无 stack frame 或 spill。Thor 原始失败保持原样：

```text
Instruction 'mul.e4m3x4.e2m1x4.e4m3x4' not supported on .target 'sm_110a'
ptxas fatal   : Ptx assembly aborted due to errors
```

两个支持目标的反汇编均包含：

```text
QMUL4.E4M3x4.E2M1x4.E4M3x4.SATFINITE R5, R4.N3210, R5.B3210 ;
```

本结果与 [PTX ISA 9.4 的 Alternate Floating Point Instructions: mul](https://docs.nvidia.com/cuda/parallel-thread-execution/index.html)
仅列出 `sm_100a`、`sm_103a` 的目标支持范围一致。

### 单条指令补丁与阳性对照

基础文件是先前通过汇编的 Thor 普通指令 cubin，SHA-256 为
`e8279c25c500a75e8995365fd4ec7d07c532c6c4296cfbe2dcea5f4d8e58b5a4`。
其 `.text.Qmul4Probe` 长 256 字节，文件偏移 `0x700`；仅替换函数内
`0x40`、文件内 `0x740` 开始的一个 16 字节指令槽。槽外整个 cubin
逐字节一致，包括 ELF 架构标记和其余元数据。

原指令读取 R4/R5 并写入 R5，分别生成两个补丁：

- OR 阳性对照：从同工具链编译的 Thor OR 探针取出该槽，实际只变化
  1 字节。首组结果由 XOR 的 `0x20303a0a` 变为 OR 的 `0x20307a3a`，
  与 CPU 参考一致。这证明修改后的 SASS 确实参与执行，也排除了由
  cubin 内 `.nv.merc` 重新生成原始 XOR 而使补丁无效的解释。
- QMUL4 候选：取自已封存 sm_100a cubin，实际变化 10 字节；完整槽
  为 `7c7205040500000000b8010500ca1f00`。原生、OR、QMUL4 三个来源的
  其余函数字节及调度控制位一致，操作数仍为 R4/R5，结果仍写 R5。

目标 SASS 为：

```text
QMUL4.E4M3x4.E2M1x4.E4M3x4.SATFINITE R5, R4.N3210, R5.B3210;
```

植入后 cubin SHA-256：
`3047fb0f0bfa9c2f5e5e36256d33e9bf6c2e3285603476d21137a29d47a12b98`。
加载后查询函数 binary version 为 110。仅在实验子进程禁用 PTX JIT
及 CUDA cache，使用 eager module loading；不更改全局环境变量。

### 冻结数值矩阵与实测结果

运行前冻结 `plan.json`，SHA-256：
`e4264ab51fc1b55973b7699ebb93a9d398db033d9d4562e98faea4453e68e22d`。
计划为 4 个独立进程：原生 XOR 8 组、植入 OR 8 组、QMUL4 最多
2,097 组、原生健康复查 8 组；每次 launch 仅 1 block、1 thread，
分配 12 字节，4 字节输出前后各有一个 4 字节 canary。

QMUL4 输入包含一组冒烟向量、全部 16 个 FP4 编码 × 127 个非负有限
E4M3 scale 在四个 packed 位置的覆盖，以及 64 组不同 lane scale。
CPU 参考用可精确表示这些输入乘积的 binary64，枚举 E4M3 输出，执行
nearest-even 和 satfinite；tie、subnormal、符号零、饱和自检通过。
NaN/负 scale 不属于本次 NVFP4 正 scale 合同，未纳入矩阵。

| 阶段 | 加载及提交 | 实际数值结果 | 退出码 |
|---|---|---|---:|
| 原生 Thor XOR | 成功 | 8/8，canary 全通过 | 0 |
| 同槽植入 OR | 成功 | 8/8，输出确实改变，canary 全通过 | 0 |
| 同槽植入 QMUL4 | 成功 | 首次同步报 715；0 组数值返回 | 20 |
| 故障后新进程原生健康复查 | 成功 | 8/8，canary 全通过 | 0 |

首组输入 `packed_fp4=0x7a32`、`packed_scales=0x20304038`，CPU
期望输出 `0x34b04438`，对应四个 lane `[1, 3, -0.5, 0.75]`。
实际在读取输出之前失败，因此没有可供比较的 QMUL4 数值。其余
2,096 组未执行；计划的 8,388 个标量结果不能记为已核验。
