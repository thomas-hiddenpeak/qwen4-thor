## MTP on/off 冒烟+粗测提速 & mtp_verify_numerics 近 tie 阈值 ULP 修正（20261012 晚，进行中）

- 做了什么：
  1) MTP on/off 冒烟与粗测（binary build/q4t 5dd192cd，21:19 构建，含已暂存
     的 small-M GEMM v2 + draft 设备侧流水线）：三组对照 plain（MTP 关）/
     mtp（k=3）/ mtp-1k（1K 上下文），证据 .q4t-work/verify-profile-20261012/
     {plain,mtp,mtp-1k}/server.log。单步耗时 draft≈14.5ms + verify≈70–75ms +
     extend+accept≈9ms ≈ 95ms/步；接受率默认上下文 87 步 a=3 占 54%、a=0 占
     22%，1K 上下文 72 步 a=3 占 82%。粗算吞吐默认上下文约 2.95 token/步
     ≈31 tok/s、1K 约 3.58 token/步 ≈37 tok/s（plain 基线约 18 tok/s，粗测
     约 1.7–2.1 倍）；a=0 步单步仅 1 token（≈10.5 tok/s，慢于 plain）。
     仅冒烟粗测，非五档 E2E 验收。
  2) mtp_verify_numerics（binary q4t_tests ee69d0c1，22:30，全模型 1K prompt
     256 步 plain T=1 vs batch T=4 差分）FAIL：flips=4/256，其中 3 个被判
     "双侧 confident"。证据 .q4t-work/verify-nums-20261012-2230/run.log。
  3) 分析定位：FAIL 源于判据标定错误而非数值缺陷。关键证据：
     min_nonflip_gap=0.125（= logit 量级 ~24 处的 BF16 单 ULP），4 个 flip
     的两侧竞争 token 均相距 1–2 ULP（step53 差 0.25/0.125、step66 差
     0.125/0.125、step143 差 0.125/0.125、step72 plain 侧完全 tie gap=0）；
     causality 负控通过（row0 跨 filler 逐位一致，无因果泄漏）；状态采样
     reldiff ~0.5–1.25%（~1–2 ULP）。旧判据 kConfidentGap=0.05 为绝对阈值，
     低于单 ULP（0.125），把 1–2 ULP 的舍入翻转误判为"confident"。
  4) 修正 tests/mtp_verify_numerics_test.cpp：判据改为 ULP 感知——新增
     Bf16Ulp()，near-tie 阈值 = kConfidentUlps(=4) × 该侧 top-1 量级处的
     ULP；仅当两侧 top-2 gap 均 > 4 ULP 才判 confident。1–3 ULP 视为在已测
     舍入范围内。构建零警告（仅重编该测试并 relink）。
- 为什么：EVALUATION.md 要求近似须有定义合同与证据、near-tie 不得作为一切
  差异的 blanket 解释。旧绝对阈值 0.05 < 1 ULP 使判据失效（任何 ≥1 ULP 的
  非 tie gap 都被判 confident）。改为 ULP 感知后，判据与 BF16 实际量化尺度
  对齐，才能区分"舍入级 1–2 ULP 翻转"与"真实 >4 ULP 分歧"。
- 结果判定：ULP 感知判据重跑 **PASS**（binary q4t_tests 重编后，证据
  .q4t-work/verify-nums-ulp-rerun2/run.log，EXIT=0）：flips=4/256、
  confident_both_sides=0，4 个 flip 全部 near_tie=1（step53 2.0/1.0 ulp、
  step66 1.0/1.0、step72 0.0/1.0、step143 1.0/1.0，均 ≤ 4 ULP）。causality
  负控通过、状态差有界（~1–2 ULP）。结论：MTP verify（T=4）与 plain（T=1）
  在 flip 位相差 1–2 ULP，为 48 层不同 GEMM/GEMV tiling 的累积 BF16 舍入，
  非缺陷。旧 FAIL 纯为判据标定错误（0.05 < 1 ULP）。
- 下一步：重跑 PASS 后，(a) 在 EVALUATION.md 定义 MTP vs plain 的近 tie
  合同（top-2 相距 ≤ N ULP 允许分歧，N 取已测舍入上界）；(b) 转向性能——
  实测 small-M GEMM 对 verify 阶段（~72ms，占单步 75%）的提速，再按五档
  E2E 做 MTP on 的正式性能与质量验收，目标 decode 提速 50–200%。
- 边界：本轮不改 kernel 产品行为/阈值/默认部署（MTP 仍默认关闭）；两候选
  env 保持 unset；staged 的 small-M GEMM v2 + draft 流水线仍未提交。
