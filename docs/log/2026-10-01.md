## 补载管线（路径 C）代码核验：stage→commit 串行无重叠，可重叠优化（06:38）

第二轮候选在途（204800 档）期间核验补载管线（纯代码，无 GPU/构建）：
`Resolve()` 循环为 `LoadPhase1(stage, 并行 NVMe→L2) → LoadPhase2(commit,
串行 H2D→GPU slot) → LoadPhase1 → LoadPhase2 …`，**stage 与 commit 不重叠**
（每 chunk 先全部 stage 完再 commit，下一 chunk 在上一 chunk commit 后才
stage）。L2 buffer 复用靠 commit 的 CUDA event 保证安全，但当前实现未利用
event 做 stage/commit 重叠。路径 C 的具体优化点：(1) 用 commit event 重叠
「stage chunk i+1」与「commit chunk i」（隐藏 NVMe 时延于 H2D 之后）；
(2) LoadPhase2 的 H2D commit 目前逐专家串行，可多 stream 并行；(3) 提高
NVMe 并行度（load_threads_）。定量：单 miss 有效 6.2 ms 中 NVMe 仅
~1.44 ms，~4 ms 为管线开销（串行 commit + 无重叠 + 互斥/条件变量往返），
重叠+并行 commit 有望压到 ~2 ms（C=256 下 decode≈54% 基线，过门槛）。
