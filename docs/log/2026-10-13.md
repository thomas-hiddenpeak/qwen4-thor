## small-T 稀疏注意力改走列分裂 kernel（T<=8，20261013 下午）

- 做了什么：
  1) qsa_decode.cu 的 QsaDecodeSplit 增加 T 参数，launch grid 由 (1,2,4)
     泛化为 (T,2,4)。kernel 本体本就是 T 通用的（t=blockIdx.x），每个 block
     负责一个 (token, kv-head) 的 64 列输出分区，故逐 token 的 QK/softmax/PV
     算术与 T=1 decode 完全一致（逐位）。
  2) full_attention.cu 派发：T<=kSplitMaxT(=8) 且 nq=24/nkv=2/hd=256 时走
     列分裂 kernel（原先仅 T==1），T>8（prefill）仍走通用 SparseAttentionKernel
     （分裂会 4x 重读 K，prefill 下通用 kernel 已占满 SM 且 K 流量更省）。
     Q4T_ABLATE_QSA_T1 消融开关保留（强制 small-T 走通用 kernel 以复现 QSA
     T 依赖）。
- 为什么：verify(T=4) 细分计时显示 full_core 中稀疏注意力 grid=(T,nkv)=8
  block，20 SM 欠并行；且通用 kernel 与 T=1 列分裂 kernel 的 PV 分块不同，
  是 MTP vs plain-greedy 分歧的一个 T 依赖源（见 2026-10-10 消融）。改走列
  分裂后：(a) T=4 时 8 block 变 32 block，占满 SM；(b) 逐 token 注意力与
  T=1 逐位一致，消除该 T 依赖源。
- 结果判定：
  - mtp_verify_numerics 256 步 PASS（flips=4/256 与改前一致，全部近 tie、
    confident_both_sides=0、max_flip_l2=0.0683，≤4 ULP 契约满足）。
  - 生产计时（4K 上下文，.q4t-work/verify-qsa-split-153025/）：full_core
    11.0→10.3ms（-6%）；verify total 76-78ms（与改前 76-78ms 持平，full_core
    之外各项不变）；wall_s 7.2（改前 7.25）。full_core 含 indexer/topk，
    稀疏注意力 kernel 仅占其中一部分，故整体收益有限。
- 边界：MTP 仍默认关闭；两候选 env unset；未做五档 E2E 正式验收。分裂仅
  用于 T<=8，prefill 路径不变。
- 下一步：(a) MoE 专家权重流量（verify 最大单项 21-37ms，专家缓存/驻留，
  独立工作流）；(b) 优化后 MTP on 五档 E2E 性能+质量正式验收。
