# BF16 GEMV 输入 shared staging 向量化

日期：2026-09-21。完整 HTTP、逐位专项与时间线完成，本次改动接受。

## 改动与边界

基线为 6bd400f。普通 Bf16GevKernel 使用 256 个线程合作将 K 个 BF16
输入复制到 shared，然后每 warp 计算一个输出。旧复制循环每线程
一次搬运一个 BF16；K=10240 时为 40 轮。候选在 x 16 字节对齐时
用 float4 搬运八个 BF16，源码循环降为 5 轮，shared 显式 16 字节
对齐。未对齐输入仍逐元素复制，Bf16Gev 原有 K%8==0 校验保留。

这里的 float4 只搬运位模式，不进行浮点转换。权重、输出行分配、
每 lane 累加次序、f32x2 FMA、shuffle、alpha 和 BF16 舍入代码不变。
HC 四输出专用实现不变，M>1 prefill GEMM 分派不变；这不意味着
HTTP TTFT 一定不变，因为其中也包含最终输出头及其他运行开销。

减少源码复制迭代数不等于已经证实指令数下降，更不等于稳定 E2E
提速；编译后实现与局部耗时仅在完整 E2E 通过后核对。

## 当前证据

目录 `.q4t-work/e2e/gemv-vector-stage-20260921/`，保存旧/新二进制、
候选 patch、构建日志、完整请求与响应、版本和 SHA-256。
必要构建零警告，首项为 1K HTTP 三次，输出一致、服务退出 0，
decode 16.993 tok/s（16.896–17.055）。随后质量 11/11 通过，包含
200K 请求，服务退出 0。没有前置数值测试、单测、bench 或 profile。

正式性能在同一服务中按 1K→4K→8K→44K→200K 顺序各三次；
固定 greedy、MTP 关闭、单流、256 输出、max_prefill=8192。
完成五档 15/15 请求，输出摘要一致、服务退出 0，TTFT/decode 对固定
参考和上一版本均未见不利的不重叠范围。完整结果：

| 输入 token | TTFT 均值秒 | decode tok/s |
|---|---:|---:|
| 1024 | 0.847363 | 16.984854 |
| 4096 | 2.848017 | 15.178663 |
| 8192 | 5.629962 | 15.984708 |
| 45056 | 33.135030 | 15.595934 |
| 204800 | 181.723432 | 14.710586 |

TTFT 包含接入、分词、prefill；decode 是三次总首 token 后输出数除以
总对应耗时。对照脚本和全部重复范围保存在 `comparison.json`，
同时使用冻结正式参考与上一阶段完整结果，避免将逐次波动累计为收益。

## 完整 E2E 后的专项与时间线

`tools/verify/compare_gemv_staging.py` 从 6bd400f 提取原 kernel，
与接受快照中的新 kernel 对照。K 覆盖实际输入宽度 320/640/2560/
6144/10240，另含 8/256/1280；N=1/4/7/8/9/17/320，包含尾部
不满 CTA 的输出行。输入偏移 0/1/7 个 BF16，覆盖对齐与标量分支。
普通随机、正负零、subnormal、交替正负输入，三种 alpha。

2016 组、105408 个 BF16 输出逐位一致，无非有限结果，编译零警告。
首轮 1764 组通过后，时间线形状清单发现缺少 K=640，故补齐重跑；
原证据保留于 `numerical/`，最终结果在 `numerical-all-k/`。
这覆盖输入搬运与数值一致性，不代替完整模型业务精度或并发验证。

同一 E2E 二进制的 1K HTTP 时间线完成且正常退出；专项在采集结束后
执行，没有与 profile 并行占用 GPU。255 次 decode 中，普通 BF16
GEMV 仍 151215 次，累计 9599.386720→9520.707648 ms（约 -0.82%，
每步累计少 0.309 ms）。HC 专用 kernel 不变，343 ms 左右；异步
分配/释放仍各 554 次/步，counts D2H 仍 48 次/步。

按形状分组，多数 GEMV 累计约 -0.4% 至 -4.0%；输出头 N=248320、
K=2560 为 1292.043→1293.484 ms，基本持平。原/新普通 GEMV 的
registersPerThread 为 39→40，dynamic shared 大小不变。没有采集
DRAM 硬件计数或将这些结果称为指令计数证明。完整原始值见
`shapes-comparison.json`，分组由 gridX、dynamicSharedMemory 与
源码核对；当前普通路径 N 均为 8 的倍数，HC 四输出另有独立 kernel。

## 接受与下一步

改动仅增加对齐复制分支与显式 shared 对齐；完整 E2E 未见可辨识
回退、逐位输出一致、目标累计耗时小幅下降，接受此有限优化。
各档 decode 对上一阶段均值约 +0.09% 至 +0.28%，不把小样本当作
稳定整体提速证明。正式速度参考仍不重置。profile 墙钟带有采集开销，
不替代正式 E2E；某些非目标 kernel 的波动也不能归因于本改动。

剩余 GEMV 仍占 decode kernel 累计时间约 58.7%。下一步根据形状与
权重字节预算区分大投影的带宽成本和小投影的归约/启动成本，再选择
单一候选；不继续凭源码循环次数缩减推断收益。保留精度和 E2E 优先。
