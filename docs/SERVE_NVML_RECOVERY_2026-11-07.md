# NVML错误分类与显式有界监控恢复

本文保留v8阶段合同；当前新v9策略见[辅助依赖隔离](SERVE_AUXILIARY_ISOLATION_2026-11-07.md)。

用户授权开发及针对性CPU验证。复用当前分支，以独立提交保留边界；
视觉候选、默认程序及封存包保持，不追加模型、GPU、NVML运行查询或
服务操作。本项不证明驱动根因修复，也不属于视觉优化验收。

## 冻结实现范围

- 新准备的degrade包升级为v8，绑定分类与恢复代码；默认仍严格，
  v1至v7封存包不改写。degrade继续要求`restart-limit=0`。
- 明确区分外部期限超时、NVML超时/资源暂不可用、配置错误、未分类
  NVML错误、明确设备故障、Python/查询协议错误及worker未回收。
  保留原错误码，不通过匹配错误文本决定恢复资格。
- 仅临时类别沿用5/10/20/40/60秒、最多5次自动重试；配置或未知
  NVML错误直接暂停监控。明确设备故障及查询/协议错误停止自有服务，
  不重启模型、不重置设备。启动前任何未知仍拒绝启动。
- 暂停后使用显式`resume-monitor --run DIR`请求；至少冷却60秒，
  同一controller代次最多2次，每次只补一次查询（5秒期限+1秒回收）。
  失败重新暂停，成功才恢复常规观察；成功不返还显式恢复预算。
- 旧Popen对象必须确认回收；缺失回收证据时不新建worker。请求绑定
  随机监控代次及暂停序号，过期/重复/停止后的请求不能触发新查询。
  执行方再次检查资格，CLI返回提交成功不等于监控已恢复。
- 当前PID未知、最近成功观测和历史缺口分开记录。恢复不清除历史
  缺口，终态仍为COMPLETED_WITH_MONITOR_GAPS；严格验收规则不变。

错误码按本机CUDA 13.3 `nvml.h`及[NVIDIA官方枚举](https://docs.nvidia.com/deploy/nvml-api/latest/api/group__nvmlDeviceEnums.html)
核对；退避/暂停/停服的分组是本项目的工程策略，不是厂商恢复保证。

## 冻结验证范围

成组修改后执行CPU分类矩阵、合成worker协议/超时与回收、虚拟时钟
冷却与总预算、旧代次/重复/停止竞争、缺口保留、真实CPU子进程及
独立测试锁下的guard/恢复闭环、包版本与配置组合回归。所有NVML
入口均替换为CPU fixture，不加载驱动或模型。必要的Python语法/来源
检查纳入证据；无C++改动时不重编译推理程序或重复host全量用例。
真实失败保留原件，修复后只重验受影响项。

分类策略如下，码值含义按上述官方枚举核对：

| 类别 | 典型来源 | 本阶段策略 |
|---|---|---|
| QUERY_TIMEOUT / NVML_TIMEOUT | 外部5秒期限 / NVML码10 | 有界退避；耗尽后显式恢复 |
| RESOURCE_UNAVAILABLE / NOT_READY | NVML码20/23/27 | 有界退避；不据此推断模型OOM |
| CONFIGURATION | 不支持、权限、库/驱动不匹配、Python模块缺失 | 直接暂停，人工处理后可显式重新观测 |
| NVML_UNCLASSIFIED | UNKNOWN及未列为可重试的其他/未来码 | 直接暂停，不当作暂时错误或空GPU |
| DEVICE_FAILURE | GPU不可访问、需要reset等 | 停止自有服务，不重启模型或reset设备 |
| QUERY_ERROR / PROTOCOL_ERROR | Python逻辑、错误参数、协议损坏等 | 停止自有服务，不开放恢复 |
| WORKER_UNREAPED | 原查询未回收或缺少回收凭据 | 禁新建查询，确认回收后才具显式恢复资格 |

真实CPU子进程在同一私有测试锁下暂停/恢复监控，前后PID相同；
缺口终态保持COMPLETED_WITH_MONITOR_GAPS。明确设备故障另验只
启动一次CPU payload，退出后无替代启动。停止请求和查询worker
回收均有独立用例；没有模拟或声称实际D-state进程已成功退出。

每次显式恢复只授权一条补充查询；成功后回到原观察循环，原有
退出context确认可能在同一扫描再查。CLI提交结果只表示请求已保存，
实际结果查看`last_resume_request`与`last_resume`；不承诺端到端恰好
6秒，也不把恢复成功抹成全程可见。

`ea1b474d…/3eb46385…`、视觉候选/父程序`34e7ceef…/982bba07…`
全部未变。0模型、0真实模型HTTP、0 GPU测试、0真实NVML查询、0生产
服务操作。v8仍只有CPU接受，旧v7的业务接受不自动扩展到v8；真实
