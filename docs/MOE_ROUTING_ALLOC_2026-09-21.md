# MoE 路由表分配隔离实验

日期：2026-09-21。合并异步分配已接受：完整 E2E 无可辨识回退，资源管理调用减少。
此前四表持久化的失败记录见 [MOE_WORKSPACE_2026-09-21.md](MOE_WORKSPACE_2026-09-21.md)。

## 已知结果

源码显示原候选同时改变了元数据存放/生命周期和 MoE 后续缓冲起点。
DecoderLayerForward 将 MoE、GEMM、HC、PLE、激活区域顺序排列，因此
增加 routed workspace 会移动多块区域，不能仅称为删除分配调用。

固定 1024 输入、256 输出、MTP 关闭、单流，各三次真实 HTTP：

| 对照 | decode tok/s | 三次范围 |
|---|---:|---:|
| 布局扩容，四表仍单独分配 | 16.868 | 16.790–16.931 |
| 仅 counts 持久化 | 16.916 | 16.840–16.965 |
| 仅 offset 持久化 | 16.890 | 16.785–16.958 |
| 仅 token_list 持久化 | 16.874 | 16.844–16.903 |
| 仅 row_of_flat 持久化 | 16.866 | 16.838–16.891 |
| 原失败二进制复测 | 11.434 | 11.387–11.468 |
| 四表合并一次异步池分配 | 16.917 | 16.861–16.952 |

各组 prompt、输出摘要和长度一致，服务正常退出。布局扩容及 counts
单表对照先跑质量 HTTP 11/11，再 1K；其他三表与原二进制复测采用
1K HTTP 失败定位。每个代码候选均先必要构建再 HTTP，未运行单测、
bench 或 profile。这些单档对照不代表质量/五档完整验收。

单独扩大布局、任意一张表持久化均未复现约 33% 回退；原失败二进制
直接重放仍慢。这支持原现象可复现，不能据此认定某一张表有问题，
也不能声称已确定 CUDA 分配器、提交节奏、缓存或地址映射的机制。
多因素交互仍可能存在，尚未测量底层原因。

## 已接受的合并分配实现

恢复原 workspace/API，仅在 MoERoutedForward 中将 counts、token_list、
offset、row_of_flat 合并成一次 cudaMallocAsync，四区域各按 256 字节
补齐，统一在原释放位置 cudaFreeAsync。保持异步池来源、数学、host
计数回传、专家多流及汇合；增加对 counts 清零返回码的检查。

E=512、k=10 时，M=1 共 6656 字节，M=8192 共 17109248 字节。
这是分配请求大小，不等于池实际保留的物理容量。没有新增持久全局
缓存或增加模型 workspace。offset/row 的分配提前到同一 slab 获取时，
原数据生成和读取顺序未改。错误路径恢复范围未扩展。

每层从 4 对分配/释放降为 1 对，48 层减少 144 对；普通前向
从 698 降至 554 对，完整 E2E 后的 HTTP 时间线已核对。
这不是减少模型权重流量，不预先承诺 tok/s 增益。

## 完整验收

必要构建零警告。首测 1K HTTP 复现通过后，质量 11/11、五档各三次
15/15 全部通过，实际长度正确，输出 256、length、摘要一致，服务
退出 0。没有前置单测、bench 或 profile。

| 输入 token | 平均 TTFT 秒（旧 → 新） | decode tok/s（旧 → 新） |
|---|---:|---:|
| 1024 | 0.850 → 0.848 | 16.893 → 16.912 |
| 4096 | 2.851 → 2.853 | 15.089 → 15.108 |
| 8192 | 5.631 → 5.638 | 15.891 → 15.902 |
| 45056 | 33.152 → 33.164 | 15.511 → 15.510 |
| 204800 | 181.959 → 181.886 | 14.670 → 14.682 |

各档 TTFT 和 decode 的新旧三次重复范围均有重叠。44K decode 均值
-0.007%，其他档 +0.069%–0.127%，不视为已证明的速度提升；8K/44K
TTFT 均值略升，重复范围仍重叠，完整范围保存在 comparison.json。
按保持精度、无可辨识性能回退的复杂度改进接受，正式速度参考不更新，
避免把波动逐次积累为基线变化。TTFT 不等于纯 prefill。

## E2E 后的调用数核对

完整门禁通过后才采集 1K HTTP 时间线：输出一致，采集及服务正常退出，
255 次 decode 前向，对应 cudaMallocAsync 与 cudaFreeAsync 各 141270
次，即每前向各 554 次。既有 1K 时间线（output-limit-20260920/count-check）
同为 255 次，二者各 177990，即 698 次；本次减少各 36720 次（每步
144）。该旧采集早于 top-k/shared 优化，此处仅核对分配调用数量，
不使用两条采集比较耗时收益。计数也与当前源码相符。

专家计数 D2H 仍为 12240 = 255×48，没有消除逐层同步。采集时的
性能不计入正式参考。数学路径未改，未另跑数值微测试或全量单测；
当前门禁不证明未覆盖的并发/MTP/多模态路径全部通过。
