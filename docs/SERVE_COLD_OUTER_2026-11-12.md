# R07 / R08 / R09：冷启动许可与原生外层恢复组合

已有原语仍不能直接拼接为已完成能力：一次性冷启动令牌被第一代
Guardian 消费后不能给第二代复用；现有设备域与资源 service 叶也
是不同的内核 cgroup。下面是继续实现的合同，不是缩小验收范围。

## 原执行边界保持

- 原资源安装提供 outer/service 两叶，设备规则只允许同一 service
  叶；外层没有模型设备访问权。核验实际 boot、cgroup2 inode、域
  UUID、UID/GID、限额、root 目录和公开回执，不只接受路径字符串。
  借用资源叶不创建第二个模型叶、不移动外部进程。解除设备规则
  不删除资源安装；资源卸载须确认已撤该安装的设备规则。
- 旧 v1 设备域接口与冻结的 R07 plan-v2 继续保留身份；新资源绑定
  使用显式新合同，不能偷偷改变旧凭据的允许范围。跨 boot 必须
  先完成原资源 epoch 续办，再对本 boot 实际设备环境重新取得资格；
  核心、外层、设备三组额度都不清零。
- 设备资格检查依然要求受支持的实际驱动、完整宿主独占事实、空的
  原 service 叶及持续 GPU 租约。监控未知不等于空闲。真实设备故障
  保留保护，不重置 GPU、不卸载驱动、不停止外部服务来自动凑条件。

## 按次准入及辅助故障隔离

显式部署的 root 保护入口提供本项目自己的有界许可通道；运行
源码只能来自已选、已哈希核验的 root 副本，不借 sudo/setuid 脚本、
nginx 或 systemd 执行模型恢复。普通 UID 的外层为一个即将启动的
原生根请求一次许可，根通道只处理设备资格和一次性凭据，不决定
核心何时重启，也不能把监控失能当作重启理由。

请求必须绑定服务/宿主安装/资源域/当前包、实际请求者身份、原
实例和 GPU 租约 FD，并有对应外层启动意图。每次重新核验原域
空、设备资格及持续所有权，设备额度先持久扣减，再签不可重放的
新凭据。根/凭据回执丢失不返还额度、不靠重发原 nonce 补办。
Guardian 仍独立核验规则、cgroup、时间、原租约及一次性令牌，
在原模型额度内执行适用 CUDA 探测。

通道/记录/管理器失能只使新启动等待或保护；已有健康核心继续
原 PID 服务。工作者超时后未实际回收就保留槽位和租约，不增殖
控制工作者。人工 STOPPED、旧树未回收、设备隔离、已退役宿主
入口或额度耗尽均不能取得新的根启动。普通健康根接管不申请或
消费冷许可。没有 systemd 时使用相同原生许可与外层入口。

## 接续实现及有界验证

1. 显式资源绑定、旧设备域兼容、实际允许叶核验及卸载顺序互锁。
2. 受保护原生许可通道的配置/身份、FD 保管、有界工作者和失联隔离。
3. 外层每代启动意图与新凭据交接；旧根退出/完整清理后才允许下一代，
   并覆盖宿主交接、跨 boot、回退及 STOPPED 竞争。
4. 针对性 CPU 先验证真实自有资源叶、权限、持久状态、拒绝边界与
   故障注入；不查询 GPU 或安装宿主设备规则。成组开发后固定用例，
   只有具体失败才补受影响项。
5. 完成适用业务短验、回退包与发行；GPU 验证仍持同一严格租约。
   涉及既有 nvargus/jtop 的临时维护仍等此前问题的回答，不把本
   原生源码开发或已有 GPU 许可扩大为操作其他服务的授权。

R07 资格业务、R08 统一 DRAM 压力与实际恢复、R09 无外部依赖的
连续恢复仍保持未完成；全部 OpenAI 和总计划任务继续。

## 设备撤销边界（针对性 CPU 接受）

仅删除 bpffs pin 后，持有 link FD 的进程仍可使旧规则生效。新控制
操作单独使用 BPF_LINK_DETACH，验证内核 cgroup_id 已为0，再移除
同一 pin；旧低层 RemovePin 保持其引用移除语义。中断后以持久
保存的原 link/program/规则身份继续撤销，已脱离对象不能被普通
adopt 或冷启动消费。旧原生helper若没有新操作则明确失败，不能
把仅unlink当成规则已撤销。针对性CPU已通过，冻结R07旧包保持。

接口依据为[Linux 6.8 cgroup BPF实现](https://raw.githubusercontent.com/torvalds/linux/v6.8/kernel/bpf/cgroup.c)
和[系统调用分派](https://raw.githubusercontent.com/torvalds/linux/v6.8/kernel/bpf/syscall.c)；
只参考接口，不复制外部实现，实际行为由本机自有CPU域短验确认。
