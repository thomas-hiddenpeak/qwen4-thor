# 视觉服务 v1：开发与生产准备合同

2026-11-06，用户授权完善视觉部分、生成图像/视频测试并配置持续目标。
基线 main `f350cf0a`，默认 ELF `aa528a68` / sidecar `46aa73bd`。
本阶段使用 `codex/vision-production-v1`，未接受前不替换默认程序。
本任务为功能、正确性和可靠性推进，不声明性能优化收益。

## 交付范围

首版为本机 Thor、固定 checkpoint、greedy、单 GPU 执行槽的图片和
有界采样视频服务。允许多个有配额的客户端排队；不声称并行视觉编码。
图片最多 8 个媒体项，PNG/JPEG data URL 或规范 base64；视频每项
2～32 个已解码图像帧，新增显式逐帧时间信息。客户端视频适配器负责
有界解码/采样，runner 不联网下载、不在 HTTP 内执行任意 ffmpeg。

| 能力 | 当前事实 | 本阶段出口 |
|---|---|---|
| 图片预处理 / ViT / 注入 | 已实现、历史有限数值验证 | 复用未变证据，补当前源码的独立坐标与真实业务检查 |
| 视频时间语义 | 一个 video 块承载所有时间组、无时间戳 | 对齐固定参考的每时间组时间戳 / 边界 / MRoPE |
| 图像 / 视频 preflight | 强制 text-only | 与生成共用展开计划，返回真实 prompt token 与预算；不解码像素/跑 GPU |
| strict tools / JSON 输出 | 媒体被拒绝 | 补媒体输入与既有约束解码的组合，验证解析、最终 schema 和工具往返 |
| 客户端配额 / 公平准入 | 媒体被禁止 | 按展开后 token 预留/结算，单槽公平排队；无 GPU 时间公平保证 |
| MTP / suffix / 状态缓存 | 组合未验或明确拒绝 | 首版明确拒绝；不通过简单移除 gate 授予接受 |
| chunked prefill / 多槽 | 视觉无分块和批量 prefill 合同 | 明确拒绝超 prefill 和多执行槽；上限在能力发现与示例中一致 |
| 失败 / 取消 / 资源 | 有限故障已验 | 受影响路径针对性回归；所有权额度不宣称整机物理 RAM 硬限额 |
| 发布 / 运维 / SDK | 已有文本工具链 | 固定视觉身份与声明、客户端实例、回退、可选 TLS/Key 及用户长稳交接 |

## 静态审计的首批问题

1. `chat_prompt.cpp` 对整个视频只放一个视觉边界。固定 Transformers
   5.16.1 的 `Qwen3VLProcessor.replace_video_token` 按 temporal patch
   group 放 `<x.x seconds>` 和独立边界；`Qwen4ExpModel.get_rope_index`
   同样把 video_grid 拆成 t=1。旧两相同帧测试不能覆盖该差异。
2. `BuildRopePositions` 遇到不足网格静默回退，块尾只更新 temporal
   最大值；需要独立可测试、拒绝坏形状的 host 合同，保持普通文本。
3. 配额在媒体展开之前预留；直接移除 client-policy 限制会少计视觉
   token。必须先统一规划再开放，而不是只改布尔 gate。
4. preflight 拒绝媒体，但已有 header/geometry planner 可在不运行
   视觉塔时计算展开容量；当前注释“必须执行模型才能计数”不成立。
5. `--allow-media` 没有关闭默认 MTP，首版应要求显式 `--no-mtp`，
   并在模型加载之前拒绝未支持配置。

参考只读：本地 vLLM `67111973eeb104e83bc6707a2d0f139737b711a0`、
`reference/.venv-tokenizers/lib/python3.13/site-packages/transformers/`
内 qwen4_exp 模型和 qwen3_vl processor，及 checkpoint 的 processor
JSON。这是固定参考审计，不冒称线上最新版本。具体文件摘要随夹具封存。

## 阶段与退出条件

1. **V0 合同与素材**：冻结矩阵、来源、独立真值、负控和 CPU 差分入口。
   程序生成文档、表格、图表、多图次序和运动视频；另用 imagegen
   生成自然场景，人工检查后冻结标签。生成提示词不充当图片真值。
2. **V1 正确性与接线**：一次成组完成视频时间/位置、统一媒体展开、
   preflight、约束输出、配额、可取消锁等待及加载前组合拒绝。
   针对性 host/processor/reference 检查通过后冻结运行来源。
3. **V2 有界实机**：先校验实际 GPU 占用，再在整阶段共享租约中验证。
   数值/输入缺陷可先直接差分；业务 HTTP 覆盖图片/文档/图表/多图/
   动态视频、JSON/SSE、真实只读工具回填、配额/取消/错误恢复及文本
   保护。回答语义、模型计算和协议结果分别记账，失败不换题掩盖。
4. **V3 生产准备**：只有必要合同和约定业务通过才形成接受包；冻结
   ELF/协议/SDK/素材、声明和回退，执行有界安装健康，提交推送/PR。
   未接受项明确拒绝或列出模型能力限制，不能写成“全视觉无遗漏”。

V0/V1 当前 GPU/模型/生成 HTTP 预算均为 0。V2/V3 在候选、逐请求
清单与素材冻结后单独给出精确预算；初始总上限为 8 次模型启动、
128 次生成 HTTP、5400 秒 GPU 租约，以及 3 个数值夹具进程/300 秒。
该上限包含父版/候选和安装健康；控制/拒绝请求另外计数并设硬限。
不得因质量未达标自动扩样；仅具体失败修复后，冻结受影响项和剩余
预算再验。已通过且身份不变的证据直接复用。

## V1 发现与补充边界

- 固定参考的 Python round 为 ties-to-even；旧 C++ std::round 和视频
  ceil 帧预算导致 29/101 差分失败，已修复为 101/101。
- 模型/两份 processor JSON 在任何模型加载前校验固定架构、token、
  patch/merge/时间维度及归一化配置，未知配置不沿用硬编码默认。
- PNG RGB 与 Pillow 预处理逐值一致；JPEG 用 stb_image 解码，与
  Pillow/libjpeg 不位等。本测试文档 1059/1179648 通道差异、最大
  1 uint8 灰阶；生产 JPEG 与生产解码后 PNG 的后续处理完全一致。
  初次像素严格检查保留 7/8，不改写成全通过；JPEG HTTP 质量另验，
  不将本夹具误差外推所有 JPEG。视频保留原 .02/.005 后端合同。
- 2026-11-06 用户允许直接使用 Jetson 硬件编解码。客户端新增显式
  jetson 后端，H.264 MP4 经 nvv4l2decoder/nvvidconv，保留真实 PTS；
  不自动降级，不进入 HTTP 进程。实际测试同持 GPU 租约。
- 硬件编解码先固定 8 帧 384×256/2fps：H.264 有损后端验收仅要求
  每帧平均 uint8 误差<8、红圆中心误差<2px，PTS 与源完全相同；
  无吞吐/零拷贝/全格式结论。其 1 个顶层 worker 包含于 3 个本地
  数值/编解码进程、300秒总预算，模型/HTTP预算不增加。

## 生产准备的界限

- 不安装常驻服务，不恢复已停止的 vLLM，不触碰其他会话资源。
- 每个 GPU 阶段完整驱动持有同一共享锁，末样本/退出屏障必须通过。
- 图片标签、视频帧序/时间、参考输出和完整响应均可追溯，prompt 不
  泄漏答案；不以固定颜色题代替 OCR/时序/工具业务。
- 输出目录只在 `build/` / `.q4t-work/`；当前盘余约 19 GiB，先设
  素材/构建/证据预算，保留旧包和其他任务数据，不自动清理研究现场。
- 长时间稳定性由用户开展；真实 LAN/证书/来源策略启用时另验。
  生产准备就绪和正式生产部署分别记录。

## V2-A 首轮冻结（执行前）

`tools/vision_service/stage.py` 冻结请求原文及源码/ELF/素材摘要：
1次候选 no-MTP 模型，计划24次Chat尝试（含5次输入拒绝、1次取消），
上限30次；控制上限100，1800秒含清理。先运行2个原生进程（旧完整
27层ViT参考双用例、1个Jetson编解码闭环），120/90秒上限。
HTTP清单：自然图JSON/SSE和空间关系3，PNG/JPEG文档2，图表1，
多图1，正序/反序/奇数视频3，JSON object1，tool none1，文本2，
真实资料工具调用/回填2，输入拒绝5，取消/恢复2，硬件视频1。
每个普通请求都先做实际 preflight，并核对生成usage的prompt_tokens；
回答语义与协议、数值分别记录。不会在失败后自动改题或重试。
治理/文本父候选/发布健康另冻结剩余预算，全部受总8模型/128尝试/
5400秒约束；不把本次一个服务当作完整生产接受。

V2-A首轮已失败保留（0模型/HTTP，2原生进程）。V2-A续轮
`phase-02`仅1编解码进程/90秒，复用未变ViT探针/参考以及已编码
H.264；普通HTTP请求原文复用。其余上限仍1模型/30Chat/100控制/
1800秒，总原生进程累计最多3，不自动再补硬件试验。
