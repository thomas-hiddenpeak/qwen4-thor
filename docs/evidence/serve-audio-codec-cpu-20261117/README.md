# 原生音频codec的针对性CPU验收

2026-11-17。18项音频与3项受影响视频/sandbox共21项独立用例完成。
包括失败定位和必要复验共58次执行、5.466秒；9次构建零警告。
0模型动作、0HTTP，默认rev266及五项发布/账本SHA保持。音频服务
接口、资产生命周期和真实模型组合仍继续，不能把codec当A10交付。

## 实现与已验行为

复用原视频的受信系统库加载、exec隔离、seccomp及线程/回收额度。
只有worker动态加载音频库；不扫描任意插件或启动外部解码程序。
视频继续只加载原视频依赖。实际WAV PCM16/24、F32/F64、FLAC、
MP3、AAC M4A/ADTS、Ogg Opus/Vorbis和WebM Opus输入通过。

输出为16kHz有限F32；各声道先重采样再以FP64均值降为单声道。
源字节/采样率/声道、累计解码量、输出数量/时间各自有限额。源长度
与输出ceil数量、PCM摘要和转换策略由母进程复核；错误不发表部分
音频。缺库之后普通文本仍可执行；取消、超时、崩溃、线程容量和
未回收占槽清理通过，源/PCM/策略回执篡改被拒绝。

## 保留的失败及修复

首组20项18通过，重采样相位和AAC夹具长度失败。原AAC独立系统
解码与worker的14336样本逐位相同；夹具原来没有预期的一秒可解码
内容。显式在编码输入尾部增加2048静音样本供延迟/末帧使用后，
解出16384样本、真实440Hz信号通过。原短夹具和两次失败不追认。

PCM24源转换的96000值与独立整数解码逐位一致，排除了源解码错误。
系统GStreamer 1.24.2默认cubic系数表有观察到的相位偏移；改AUTO
表仍失败。源码核对后选择其现有LINEAR系数插值，保持Kaiser质量10
及1MiB的AUTO完整表阈值。原48→16k RMS从9.55e-4降至5.89e-8；
44.1→16k、8→16k及非整秒尾部为1.18e-5～1.24e-5，均满足原1e-4
门限。这里没有修改系统库或复制它的源码，也没有性能接受主张。

新升采样用例揭示EOS排空少一个目标样本。现在向同一滤波器提供
一个零延拓输入帧，再取原始源长度对应的ceil输出；延拓不计入源
数据，也不人工补输出值。原第一次排空实现受source pad已标EOS
影响而失败，随后改为事件到达前向滤波器sink送边界帧。保留原容量
故障，不让排空/bus错误覆盖。8k一秒输出16000个样本，末样本为
非零实际滤波结果；非整比例和多一源样本的长度边界均通过。

最终18项音频中13项沿用排空组通过记录，5项按最终修复复验通过。
公共加载器最后增加了所需符号，因此两项视频又在最终二进制复验，
0.064秒；未改的sandbox实现沿用首组记录。全部原FAILED保持。
