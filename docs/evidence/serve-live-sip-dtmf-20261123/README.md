# Live SIP 电话按键与按键后的语音业务

Thor 上的官方 JS SDK 7.47.0 通过原生 TLS 接听一通来电。独立本机中继使用双向 TLS 和加密 RTP，语音为 48 kHz Opus，键音单独协商 8 kHz、事件 0–11。验收使用本机中继，公网运营商互通待实际部署验证。

| 检查 | 实测结果 |
|---|---|
| 电话发 `#` | 对端发送起始报告及三份结束报告。应用旁路收到一次 `transport.dtmf.received`。 |
| 应用发送协商范围外的 `A` | 只有该命令收到 `sip_dtmf_not_negotiated`，错误保留原客户端事件 ID。 |
| 应用连续发送两个 `*` | 对端独立解密出两个不同时间戳，各 12 包、3 份结束报告。SDK 按请求顺序收到两笔不同 ID 的发送回执。 |
| 随后继续本次通话 | 用户语音转录为“请查询当前项目版本号。”，客户端读取项目记录后回填，模型播报 rev426。对端解密、解码 24,000 个语音样本。 |
| 挂断和清理 | 所属应用挂断得到 200，旁路关闭码 1000，再次挂断得到 404。同一模型的普通 Chat 回答 42。 |

成功短验用时 64.44 秒，一次模型启动、一次接听、六次 SDK HTTP 调用。62 次 NVML 查询全部成功，自有进程、端口及 GPU 租约已回收。模型、入口和两个 SIP 进程的 SHA-256 及业务结果见[验收记录](acceptance.json)。

首轮业务短验在 37.70 秒失败。电话对端已解密收到两个键音，测试客户端将 SDK 对同一预期协议错误的第二次通知当成了新错误。驱动现在按原始事件对象关联，其他协议错误和传输错误会继续导致失败。两轮使用相同的模型程序。[首轮失败](business-first.json)；[SDK 身份关联与反例](sdk-wrapper.txt)。

45 项针对性检查通过，包括 9 项键音、9 项安全媒体和 8 项 SIP 对话，另有 6 项会话与准入、5 项媒体调用和 8 项所有者检查。覆盖 G.711 同时钟、Opus 同时钟、Opus 配 8 kHz 键音、收发方向限制、未协商、没有可选键音生成器、重传、认证失败、长事件续段、背压和超时后的迟到回执。[媒体与对话](media.txt)、[会话](session.txt)、[媒体调用](media-call.txt)、[所有者](owner.txt)、[来源审计](inventory.json)。

早期媒体回环暴露了生成器事件投递和排空问题，修复后又暴露连续按键抑制后续语音及不同时钟共用 RTP 源的问题。同一时钟现共享普通 RTP 复用器，异时钟使用独立 RTP 会话与来源。最终回环在三种时钟与编码组合中均要求按键之后仍能收到语音。[首轮媒体失败](media-first.txt)、[次轮媒体失败](media-second.txt)。协议依据为 [RFC 4733](https://www.rfc-editor.org/rfc/rfc4733.html) 和 [RFC 7160](https://www.rfc-editor.org/rfc/rfc7160.html)。
