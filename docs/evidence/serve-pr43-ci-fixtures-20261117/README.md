# PR43两项失败夹具的针对性修正

同一head 01f88698的push检查通过，pull检查在两个Batch复合断言失败。
原日志没有指出复合表达式中的具体子条件，不能断言已确定唯一根因。
源码审查发现两个语义用例分别将正常worker启动/前置读写和恢复事务
限制在100/250毫秒；这会把调度或文件系统迟延混成目标故障。

仅修测试：前者先验证worker普通请求，I/O等待给1秒，丢回执hook仍在
真实提交后无限等待，保留unknown/私有引用/保持hold及原件恢复全部
断言；后者也给普通事务1秒，保留重算usage、单次执行、预算回收和
recovered=1断言，并拆开断言以提供明确后续诊断。生产时限未变。

本机必要构建零警告，两个直接用例1.115秒通过；不追加模型或性能
测试。[接受记录](acceptance.json)、[日志](affected-batch-tests.log)、
[原CI与构建日志](ci-and-build.tar.gz)。最终head两组检查仍须通过。

PR43一并纳入此前意图容量修复的正式包/CLI收尾，全部代码均有各自
针对性及实际交付证据，不把尚未实现的其余协议/后端工作混入通过结论。
