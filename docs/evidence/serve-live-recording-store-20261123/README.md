# Live 会话录制的存储与 HTTP 边界

16 项原生 CPU 检查、4 项托管启动器检查，以及下载波形判据的 5 个反例通过。原生可执行文件和入口在 Thor 上构建，零编译警告。初次 CLI 夹具缺少必需的模型目录参数，修正后仅复验了该项。原始日志的 SHA256 见 [验证清单](result.json)。

- 真正启动隔离对象存储进程，提交前读取得到 404。重建存储实例后，相同身份收到 200、正确的音频类型、长度与交错样本，每个块都由存储根引用，保留时间为 30 天。其他身份得到 404。
- 取消、身份撤销和队列超限均未发布半成品。存储错误只产生一次关联到 `session.store` 的错误，原生会话随后完成语音与正常关闭。会话未选择录制时，存储工作进程启动数为零。
- 启用方需要同时指定部署开关、具名客户端和会话授权。每次录制独立预留 64 MiB 工作内存，应用对象仍受原有字节、对象数和到期回收限制。服务端在有界后台队列处理 IO，下载按有限块解码并交错。输入包按采样和到达时间定位，20 ms 内的抖动以连续样本处理。

本组无 GPU 启动。真实 SDK 语音、正文下载与密钥隔离另行短验。
