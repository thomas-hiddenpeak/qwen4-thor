# 可选媒体程序的安装与迁移

修复前，CMake 对 `--component q4t-live-workers` 返回成功，目标目录为空。直接复制构建目录中的 SIP 信令程序会保留一条指向开发工作区的 Sofia-SIP 动态库搜索路径。

现在显式安装该组件会将本次构建生成的媒体程序放到指定目录，供引擎按同目录文件名启动。Thor 上生成的三个程序均有执行权限，逐个检查 ELF 动态段，没有 RPATH 或 RUNPATH。完成安装后移动整个目录，再以新路径运行下列回环。[三个安装产物的身份](artifacts.json) · [源码核验](inventory.json)

- SIP 信令与电话媒体通过双向 TLS 建连、应答和 ACK，实际发送并解密 PCMU，随后正常挂断。测试进程的加载路径提供了当前机器尚未全局安装的 Sofia-SIP 运行库。[SIP 回环](sip.txt)
- WebRTC 音轨双向传送 Opus，同时交换两条数据消息。数据通道关闭后音轨继续工作。缺插件、指纹错误、无效绑定、所有者消失及 15 秒启动超时均有定向检查。测试对端使用此前验收的 NICE 插件。[WebRTC 回环](rtc.json)

该阶段使用 CPU，本机系统与默认模型包均未部署新文件。托管包还需要绑定选定组件的安装后身份、接入中继配置，并完成主轻两套配置的恢复与回退验收。
