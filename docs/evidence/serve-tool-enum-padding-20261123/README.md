相同的 `lookup_project_record` 定义在 CPU 上可确定性复现一个解析缺陷。用真实约束解码器逐字节选择工具调用，在枚举字面量 `release` 两侧生成空格和制表符，语法接受这些字节，原解析器在关闭工具帧时拒绝。另一项新增用例要求可区分枚举值本身带有的前导空格、末尾空格与换行，旧表示也未通过。[修复前](cpu-before.txt)

现在只有受约束的 XML 字符串枚举会去除语法允许的两侧空白，每侧最多 16 字节。枚举值本身含边缘空白时，模板和解码器选择项目已有的 JSON 对象表示，由约束工作进程校验原值。XML 参数名仍可提前流出，枚举值在参数关闭时发送，普通字符串继续增量发送。12 项检查覆盖逐字节流与最终参数一致、超限空白、未声明的值、自由字符串和其他工具的既有行为。[CPU 检查](cpu.txt) · [来源审计](inventory.json)
