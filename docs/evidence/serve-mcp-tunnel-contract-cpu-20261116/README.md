# 隧道公开合同与可选前置针对性CPU验证

基线89a6e510；22项不同用例最终通过，共34次执行。0GPU，实际默认
rev126程序/发布记录逐次SHA保持。没有C++改动，复用前一阶段已验的
候选引擎与ingress构建；本阶段没有完整性能或全模型正确性测试。

## 实现与证据

- 三条原生隧道路由进入公开OpenAPI及单文件bundle；独立wire schema
  覆盖metadata、poll命令、四类回传、原RPC ID及q4t未知结果扩展。
  schema不代替动态授权、token精确匹配、字节和全局资源上限。
- 显式可选nginx的两套渲染器均接通受保护头；独立poll/response
  每客户1/2、全局4/4槽位，独立10/20rps及20/64burst。保留关闭
  自动上游重试，回传不重放工具。元数据仍走运维端口。
- 实际nginx1.30.6监督模式和独立私有包的TLS、原始body、身份/
  凭据转发通过；重复头、Connection/Trailer指定头及非法值在转发
  前拒绝，合法单字段逗号不被误拒。仅复用已验二进制，无安装。
- 原生入口四项TLS/路由/容量/头部回归通过。可选前置全部应用路由、
  换代身份和已接收POST失败不重放三项通过。来源7项负控/688锚点过。
- 合同扫描发现并修复存储Chat的filePart缺失引用及content_parts
  漏项；补实际文件消息schema验收。扫描器识别字面`$ref`属性，
  旧路由测试按其所负责的Chat/Responses/Conversation集合核对。

## 原失败与修复

1. cpu-01：12项中9过，失败来自旧引用扫描将字面`$ref`误认成引用、
   两个TLS夹具未适配可选nginx的配置/域名。完整日志保留。
2. cpu-02：3项中1过；引用扫描继续发现真实的chat_input_filePart
   悬空引用，独立包夹具CA缺少严格链校验所需扩展。
3. cpu-03：6项中5过；独立包使用了初始配置token，与运行中的后端
   generation token不一致，被真实后端403拒绝。改为已知当前token。
4. cpu-04、cpu-05及native/routes/storage组全部通过。仅重验受影响
   项和必要新增合同；通过且身份未变的结果复用。没有放宽TLS或鉴权。
