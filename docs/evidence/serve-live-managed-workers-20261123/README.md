# 实装媒体组件、原生入口与裸机降级

已用真实包管理器构建 Ubuntu 24.04 arm64 可选组件包，核对提取后三个程序的 SHA、ELF 平台和许可证。apt 模拟在此机只新增 q4t-live-workers、gstreamer1.0-nice、libsofia-sip-ua0t64，零升级和移除。未在主机全局安装。实际正向短验只将来源与 apt 索引哈希匹配的两个发行版依赖只读投射到私有挂载命名空间，随后降为普通用户，在严格租约内运行相同候选。核心服务本身没有 NICE、Sofia-SIP 启动依赖。

在已准备媒体环境的候选中，官方 SDK 7.47.0 通过 loopback 原生入口完成两次 WebRTC 201，数据通道均收到 started/closed。中间终止自有网关，网关代数 1 → 2，原模型保持第 1 代。前后 Chat 均答 42，可取回持久化回答，录制默认关闭。51.60 秒，一次模型启动。未部署这些系统库时，已就绪服务的媒体请求返回 503 live_media_unavailable，前后 Chat 仍答 42，存储可读，网关、模型、控制器与 Guardian 的 PID 相同。46.69 秒，一次模型启动。两次严格租约均完成并释放。

初次把配置请求发向公开端口、未为测试对端提供 ICE 插件的启动记录均保留。普通主机首轮降级请求曾返回通用 503 service_binding_unavailable；经前置 Chat 确认业务通路后，得到媒体专属错误。首次错误原因尚待定位。随包 SDK 说明 README 的旧元数据摘要也已修正，许可证内容未变化。

校验器将 Live 资格与实际通过 SDK 的入口程序绑定；两种配置均接受已验入口，均拒绝旧入口和缺失入口。该校验属于下一候选的管理代码。原候选实际二进制已匹配，下一步使用两个真实候选验证受注册恢复。48 项 CPU 检查通过，包括修正旧模拟记录夹具后的重验。[两种环境、程序摘要与原回执](checks.json)
