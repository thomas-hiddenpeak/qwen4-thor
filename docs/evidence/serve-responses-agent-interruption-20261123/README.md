# 后台代理在模型退出后的终态与断点续读

默认 rev438 在已持久化 `spawn_agent` 调用和结果后失去模型进程。Guardian 启动第二个模型，SDK 连续八次查询仍收到 `in_progress`。同阶段显式取消的另一个任务正确保存为 `cancelled`。这次短验用时 111.42 秒，两次启动，清理完成，原始结果保留为失败。

`ResponsesState::Interrupt` 曾给已提交的两个代理条目补上 `status`，违反条目 schema，导致包含 `response.failed` 的整个写入被拒。修复保留已经提交的调用、输出和终态消息，只转换仍在执行且允许转换的条目。图片生成的中断状态为 `failed`。补丁调用只能表示进行中或已完成，对执行结果未知的调用保留最后观测值，由外层 Response 表示失败。

将上述两份原始对象逐字节复制到私有存储，通过候选引擎及原生 HTTPS 网关回读。官方 SDK 第一次查询取得 `failed / background_execution_interrupted`；修订从 5 到 6，原有两项输出均一致。从事件 6 续读只收到事件 7 `response.failed`，另一客户得到 404，已取消对象的文件摘要保持一致。这次用了一个模型，耗时 33.92 秒，退出后端口释放。两次测试的默认部署文件摘要保持一致。

八项针对性 CPU 用例通过。首版新增夹具缺少 `annotations`，在原始条目校验处被拒，修正后单独验证带、缺 `status` 的相反结果。运行结果、源码对应的候选二进制、两份原始对象和租约摘要见[核验记录](checks.json)。正式主轻配置、可回退发行另行验收。

## 主轻配置与回退资格

主、轻配置各从同一份 rev438 故障原件恢复一次，两次均在首读提交失败终态并保留两项输出，84 次设备采样正常。两份新资格逐层重建旧资格，自动切回有该缺陷的 rev438 已拒绝。待托管主备接管和发行。 主配置完成后将终态文件另存，再给轻配置装入原件；同期其他业务对象通过共享存储跨配置回读。两份资格在既有 8 MiB 限额内。首次离线封存因相对路径校验失败，修正路径并校验实际终态文件摘要后复用了同一组 HTTP 数据。[逐配置与反例](profiles.json)

## rev440 托管发行

主包与独立回退目录都包含经过验证的同一修复引擎。模型突然退出时，原 Guardian 启动第二代，已提交的两项代理输出逐项保留，断点之后仅一个失败事件。注册主包的网关致命退出时，旧模型仍能提交 `wait_agent` 并记录 `service_draining`。回退包接管后，SDK 从原断点按序读到那次调用的 added、done 和唯一的 failed，其他客户得到 404，新的 Chat 回答 42。两个包共享引擎实现，此处验证的是已注册包的进程接管。

首次网关演练已经完成主备切换，但检查器误断言一定要看到模型骤停的错误码；原失败保留。按两种故障分别核验后，模型骤停和网关排空演练分别用时 112.19 秒、122.06 秒，各启动两个模型。排空消息把共享的模型步骤误称为文件配额不足；后续源码修正已通过 9 项 CPU 检查，rev440 仍返回旧的说明文字。

发布和注册均完成。默认停止，主包与回退包的能力和配额边界相同，13 份受保护状态文件摘要保持一致。24 小时计划已固定 696 份源码并通过只读预检，实际长稳由操作员运行。断电重启或 NVML 冷启动另计，rev440 原包已经通过冷启动来源检查。宿主只读检查仍发现相机和监控服务占用设备，设备围栏与冷启动推理尚待维护窗口。[发布、长稳入口和冷启动预检](delivery.json)
