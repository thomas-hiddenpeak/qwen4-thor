# Realtime 电话打断和会话历史

电话会话按响应和音频项记录已交给本地媒体发送器的 PCM 样本数，遇到发送背压时不推进计数。应用手动清空播放，或启用自动打断时检测到来电方开始说话，会丢弃未送出的音频，并在同一条对话记录中保留相应的整毫秒前缀。服务复用已有音频历史、转录清理和取消逻辑。自动打断仅影响默认对话；关闭自动打断和独立生成的回答均有 CPU 对照。计时点是服务端按节奏送出音频的边界，远端设备还可能有自己的播放缓冲。[OpenAI Realtime 打断与截断约定](https://developers.openai.com/api/docs/guides/realtime-conversations#interruption-and-truncation)。

**真实手动停播。** 在一次原生 TLS 电话中，模型根据真实输入调用项目查询工具，并使用回填的版本生成语音。对端解密 24,000 个 Opus 解码样本后，SDK 发送 `output_audio_buffer.clear`。应用在清空前后通过 `conversation.item.retrieve` 取回同一项，截断回执为 985 毫秒，原 PCM 为 107,520 字节，保留的 47,280 字节逐字节匹配原前缀，保留转录为空。收到一次清空、一次截断，不会再收到正常播放完毕事件。挂断、旁路关闭、独立 Chat=42 和资源清理均通过，严格租约内 65.98 秒。[手动停播](manual.json)、[本次函数终态](completed-tool.json)。

**真实来电插话。** 同一候选再次完成接听、工具回填及生成语音。SDK 开启 server VAD 和自动打断，关闭自动回答。对端在播报过程中通过加密 Opus 发送 46 个 20 毫秒录音包。SDK 没有发送停播命令；服务检出新的发言，发出清空和截断事件。应用再次取回原回答，107,520 字节缩为 81,696 字节，对应 1,702 毫秒，原前缀逐字节相同，转录为空。67.83 秒，65 次 NVML 查询正常，挂断、Chat=42 与资源清理通过。[电话对端与 SDK 回执](barge-in.json)。

**定向 CPU。** 18 项通过，含显式截断边界、播放背压、VAD 触发与关闭、默认与独立响应及 PCM/G.711 历史。首轮有一项失败，定位为服务把协议事件的内容类型 `audio` 和存储项的类型 `output_audio` 混用，导致找不到要截断的项。修复绑定后通过。[首轮](cpu-first.txt)、[最终结果](cpu.txt)、[来源审计](inventory.json)。

**中断与模型调用错误。** 首次实机停播测试中，外层严格验证守护器的 NVML 子进程停在初始化，查询清理超时，阶段为 ENV_ABORT，未取得打断结果。第二次测试在首个工具回合收到 `structured_output_invalid`，SDK 拒绝执行，未进入播报。该次没有保存模型的参数文本和详细终态，原因尚不能归为模型或解析器。驱动已补存 SDK 工具终态及参数。成功的独立短验仍保留这笔失败。[环境记录](environment-abort.json)、[工具失败](tool-failure.json)。
