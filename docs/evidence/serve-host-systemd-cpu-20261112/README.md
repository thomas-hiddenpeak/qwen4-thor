# 可选 systemd 触发器针对性 CPU 验收

19项不同用例、37次调用累计42.900秒，0 GPU。15项管理/故障、
1项实际原生 Guardian 健康根接管回归、2项封包及1项真实 systemd。
首轮14项因夹具清理集合被覆盖而失败，原始记录保留；按明确UUID、
创建窗口、权限/限额和空域检查回收14个测试域，未发送信号。
修复后仅补受影响项；后续卸载修正只补1新+2直接及2受影响封包。

持久选择/永久绑定先于注册，来源和drop-in必须一致；历史丢失拒绝
重置，未选择时原生服务不调用管理器。禁用先持久生效，旧入口也
不能启动；timer文件丢失仍撤实际已加载触发器，helper活动时卸载
等待且不杀核心。原生卸载要求先撤可选注册，停止业务使用原生stop。

真实短验只新建一对唯一命名的 `/run/systemd/system` 单元，运行时
启用；timer实际执行受保护host ensure并成功返回，原STOPPED和
账本保持、零角色启动。禁用后再次调用检查入口也无业务动作。
单元、启用链接、临时安装及资源域全部移除；未改 `/etc`、既有宿主
服务、设备策略或默认发行。`live-result-01.json`包含实际身份与步骤。

实际 Guardian 接管用例使用CPU角色与合成引擎核验，不能代表模型
业务。宿主升级绑定、冷准入组合、模型短验及可回退交付仍需完成；
这份证据不关闭R09或总目标。
