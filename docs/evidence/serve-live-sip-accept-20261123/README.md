# 电话接听、资料查询和挂断

Thor 上用正式构建的模型、原生 TLS 入口、SIP 信令进程和 SRTP 媒体进程连接了一个本机电话对端。业务客户端使用固定的官方 JS SDK 7.47.0。电话中听到的问题来自已有的 24 kHz PCM 录音；对端将它编码为 Opus，通过 SRTP 发送。ASR 没有收到原文。

| 业务步骤 | 对照 |
|---|---|
| 接听 | SDK 核验来电通知。其他客户接听得到 404，错误的会话类型得到 400。已加入对话的电话对端确认 SDP 后，所有者得到空正文 200。 |
| 语音和委派 | ASR 输出“请查询当前项目版本号。”。旁路客户端按委派 ID 读取并校验本次固定的 STATUS，回填后模型播报 rev426。独立电话对端解密、解码 Opus，并测量收到的音频样本和幅度。 |
| 主动挂断 | 其他客户得到 404。所属客户发出挂断后，原 TLS 连接收到真实 BYE，电话回 200 后 SDK 得到空正文 200。旁路收到同一会话的终态，关闭码 1000；再次挂断得到 404。 |
| 清理 | 同一模型用普通 Chat 回答 42。会话数、活跃 Chat、协议主机预留都回到零，序列槽空闲。 |
| 独立媒体失能 | 对端收到 200 SDP 后，驱动用 pidfd 暂停本轮新建的、属于指定模型的媒体子进程，再发出真实 ACK。HTTP 等待本地媒体就绪回执，超时返回 503。对端收到清理 BYE，媒体子进程被回收。 |

首轮模型通话耗时 63.81 秒。[首轮记录](initial.json)。关闭路径复核发现，对端挂断后已无须继续等待其套接字上的音频。改为立即排空子进程，再等待后端终态。第二轮在挂断时继续发送 32 帧 Opus，62.99 秒通过。[带尾帧通话](hangup-during-input.json)。

随后将公开接听成功绑定到媒体子进程实际发出的就绪回执。首次组合验证已观测到预期 503 和清理；并行运行的本项目 CPU 所有者夹具被严格 GPU 守卫识别为竞争任务，发出 ENV_ABORT。原检查及退出现场保留。夹具退出后使用同一二进制和原互斥规则独立复验。[中止记录](env-abort.json)。

最终候选一次启动，65.96 秒完成两通电话。第一通的本地媒体未就绪，SDK 实收 503，子进程、会话和主机预算全部回收。第二通在同一模型完成项目查询，电话端解码 24,000 个 48 kHz 样本，峰值 14,023；挂断时另传了 31 帧，远端 BYE 答复、旁路终态及后续 Chat 均正常。63 次 NVML 查询成功，进程、端口和租约回收通过。[最终回执与产物身份](acceptance.json)。

7 项真实所有者 CPU 用例验证接听与拒接的竞争、超时、迟到 ACK 的主动清理、未批准媒体地址的回退和两种通知的共同归属。4 项原生用例检查输入及准入，5 项公开合同检查通过。原生入口与可选 nginx 分别将 80 个 HTTP 路由模板转发到测试上游，核对身份、方法、正文和目标端口。[所有者](confirmed-owner.txt)、[原生准入](confirmed-lanes.txt)、[合同](schema.txt)、[原生入口](native-routes.txt)、[可选 nginx](nginx-routes.txt)、[来源审计](inventory.json)。

业务驱动为 [SIP 与 GPU 短验](../../../tools/serve_live/sip_accept_acceptance.py) 和[官方 SDK 应用](../../../tools/serve_live/sip_accept_sdk.mjs)。每次模型测试使用单独的同仓严格 GPU 租约。原始现场在本机 `.q4t-work/serve-live-20261123/sip-accept-business-01` 至 `04`；这里仅保留去除私有连接材料的回执。本轮覆盖本机电话对端与 Live 接听，Realtime 独立接听、转接和 DTMF 仍在总计划内。
