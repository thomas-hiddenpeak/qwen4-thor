# 已注册管理包启动与网关恢复

旧守护器在创建模型前为版本准备分配 5 秒。在同一封存控制包和真实凭据上，两次 CPU 复现耗时 5.75 秒和 5.72 秒。原实现对已经完整核验的两个包和回退授权重复执行了校验。一次事务现复用其已校验对象，下一次请求重新读取凭据。版本 prepare 的默认时限为 30 秒，核心日志与其余版本操作沿用各自时限。永久挂起、截止、停止和篡改凭据的检查均已覆盖。

- 在真实候选上，准备分别用时 2.63 秒和 2.60 秒。原生程序由原发行提交的 74 个已验输入单独重建 Guardian，其中只有日志实现修改。原模型程序、网关、设备控制与探针均保留原字节。
- 67 项 Python 与 12 项原生日志检查通过。第一次 Python 测试发现显式返回已注册根时，所需周期本已是当前周期，重复迁移会拒绝操作。现重新验证该目标凭据并保留原账本。另一项测试最初调用了过时的 CLI 夹具，使用当前工具快照后通过。
- Thor 实际启动一个模型。进程身份核准后终止本次网关，守护器将网关从第 1 代恢复到第 2 代。控制器、模型与守护器的 PID 相同，模型保持第 1 代。恢复前后真实 Chat 均答 42；同一客户端取回恢复前存储的回答。65.57 秒，进程回收，端口和 GPU 租约释放。
- 保留首次注册启动超时及后续一次 429 的回执。429 来自 beta 的每分钟一次配额。复验选用现有 alpha 的每分钟 30 次配额，测试未修改任何客户端策略。
