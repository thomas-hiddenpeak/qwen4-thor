# Speech压缩流与实际内容身份通过

原生请求持有一个隔离编码worker，2048样本输入、64KiB输出，
按需拉取、逐块SHA与显式EOF。MP3/AAC/Ogg Opus/FLAC结束前
已有可解码真实音频；完整输出及AAC尾部/FLAC包边界通过。
输入、输出和进程退出都确认后才发布成功，已发字节此前为临时结果。

15唯一CPU/16次执行，1.348秒；包括增量SHA与已知向量、输入/
输出预算、线程创建失败、空EOF、缺依赖、崩溃、待输入取消、
控制器及客户端取消、操作超时、生成等待计入总截止和7种畸形
协议。首组14通过，尾随额外字节原误映射413，修为worker故障503；
仅补1异常协议用例，其他14项依赖保持。原失败和所有构建保留，
必要构建均零警告，901来源锚点/12负控通过。

原已验中英文PCM各经4格式流式编码/隔离解码，8例全部输出SHA
与[既有内容验收](../serve-speech-encoding-content-20261118/README.md)
的解码PCM完全相同，复用原独立ASR原文匹配结论，未新增GPU或
ASR加载。16个编解码worker均回收，实际1.065秒、2.20MB产物。
首个驱动将完整来源清单混入64KiB执行输入而退出，0worker；
分离证据计划和执行输入后通过，没有抬高生产预算或删除失败。

本组0GPU/HTTP，默认rev306五项身份未变。程序和原始证据保留在
`.q4t-work/serve-native-tts-20261118/codec-stream-*`，公开归档逐文件
SHA见index；只包含证据，不包含模型或可执行文件。

仍需实际Speech HTTP/SSE、Chat音频历史、SDK/TLS与恢复发布。
