# 用临时凭据建立 WebRTC 对话和转录

Thor 原生 TLS 与 OpenAI JS SDK 7.47.0 建立了两通加密回环通话。第一通通过 multipart 建连，指定新指令并继承凭据上的文本模态及手动音频设置。客户端从 SCTP 的首个事件读回这些设置，发送 6 × 7 后得到 42。第二通仅提交 SDP，在实际 Opus 音轨播放项目查询录音，获得“请查询当前项目版本号。”。长期客户 Key 挂断两通电话，媒体与配额均排空，同一模型的普通 Chat 返回 42。[真实结果](http.json)

签发转录凭据后若显式提供对话类型，协商前返回 HTTP 400。13 项定向原生检查包括转录会话收到对话生成命令后的错误、更新 G.711 输入格式、旁路快照和后台 ASR 的释放。[CPU 检查](cpu.txt)

首轮测试程序未配置本机已有的 NICE 插件，模型启动后对端构造 RTP 失败，未发出任何签发或建连请求。驱动现于 prepare 阶段验证插件可加载并冻结其 SHA-256，run 复用该路径。相同候选在第二轮 47.60 秒内通过，46 次 NVML 查询正常，GPU 租约已释放。固定回环环境的 ICE、DTLS、SRTP 和 SCTP 已实际运行。跨网中继、可选前置及组合发行另需验收。[首轮与通过轮](attempts.json) · [候选程序](build.json) · [业务驱动](../../../tools/serve_live/client_secret_rtc_acceptance.py)
