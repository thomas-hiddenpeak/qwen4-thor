# 已认证来电的签名 HTTPS 通知

2026-11-23。在 Thor 通过真正的双向 TLS SIP 对端发起来电。所有者得到私有来电后按身份发出 PUBLISH，电话进程把该来电的固定事件转给独立发送进程。发送进程使用部署指定的 URL、网络名单、CA 和签名密钥。q4t 原生 HTTPS 客户端逐地址检查网络策略，验证服务端证书及域名，并仅对目标执行一次 POST。SIP 进程始终保持禁止主动 connect 的边界。

真实回环 HTTPS 接收端使用固定的 OpenAI Node SDK 7.47.0 `webhooks.unwrap` 校验实际 HTTP 字节和签名头。事件带有客户可使用的 `live_…` 来电 ID。字段保留名称、值、顺序和重复项，按 SIP 规则展开续行。未协商的媒体安全状态省略。SIP 凭据与 SDP 均不进入通知。

| 情形 | 实测结果 |
|---|---|
| 另一客户尝试发布 | not_found，接收端无请求 |
| 正常通知，随后重复发布 | HTTPS 204 后收到 delivered；成功后重复请求无第二次投递 |
| 验签反例 | 改正文、换密钥、改 webhook-id、改时间戳均被官方 SDK 拒绝 |
| 307、503 后显式重试 | 未跟随重定向；三次实际 POST 仅由三次 PUBLISH 触发，事件 ID、创建时间和正文字节相同 |
| 接收端持有请求不返回 | 重复发布收到 in_flight；对端先完成 486 和 ACK，再释放 HTTPS 响应，原投递可独立完成 |
| 不受信接收端、发送进程退出 | 未确认结果记为 unknown；无静默重发。已有电话能完成拒接及 ACK，发送进程退出后中继仍接收新来电 |

专用 host 构建执行 5 项 webhook 场景；随后用正式候选引擎的独立 worker 入口执行同 5 项和既有 9 项 SIP 回归，共 14 项通过，33.143 秒。[逐项结果](peer-tests.txt)。原始日志位于 `.q4t-work/serve-live-20261123/sip-webhook/`。全程无模型加载。默认发行 rev426 未切换。

本阶段生产代码入口为 `q4t --sip-webhook-worker` 与 `q4t-live-sip` 的可选 WEBHOOK_FD。已验收的所有者控制使用私有套接字；通过 serve 部署启动、客户 REST 接听/拒接、SRTP、Realtime 来电兼容及组合发行仍须接入和验收。
