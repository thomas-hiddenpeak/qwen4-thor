# 临时凭据跨入口与模型换代

Thor 上使用同一严格 GPU 租约，启动两个相继运行的真实 q4t 模型进程，并保持相同的入口地址、TLS 证书、长期客户 Key 与内部绑定。客户端通过原生 TLS 签发凭据并用固定 SDK 建立 WSS。两个模型均在用完后释放。此轮使用进程身份绑定的准入夹具，入口与模型由验收驱动独立更换；正式 Guardian 整包恢复需组合验收。[动作计数与环境](recovery.json)

| 场景 | 实际结果 |
|---|---|
| 第一个入口异常退出，模型继续运行 | 原凭据成功建立新 WSS，返回不同的会话 ID |
| 更换入口时撤销客户 alpha 的签发 Key | alpha 的未过期凭据得到 401，beta 的原凭据仍得到 101 |
| 更换模型进程，保持客户 Key 与内部绑定相同 | 模型拒绝 beta 的旧凭据；同客户新签发的凭据得到 101 |
| 两代结束前查询及清理 | 普通 Chat 各自回答 42，均确认会话、端口及模型排空。共 72 次 NVML 查询正常 |

README 的旧前置示例清除了 Connection 头。CPU 回环在同类配置下复现了已认证 WebSocket 收到 400。修复后的测试直接加载 README 的 nginx 片段，确认浏览器子协议经过 nginx 和原生入口得到 101，只返回协议名，双向帧及正常关闭通过。过期凭据得到 401。原有 JSON、SSE 首帧、恢复期间 503 及前置退出后的原生服务均通过。[原失败](proxy-original.txt) · [5 项检查](proxy.txt)

该前置仅透传标准 HTTP，实际鉴权由 q4t 原生入口完成。旧版让 nginx 独立承担鉴权的部署，其临时凭据兑换需单独接入。[部署示例](../../../README.md) · [实机验收驱动](../../../tools/serve_live/client_secret_recovery_acceptance.py)
