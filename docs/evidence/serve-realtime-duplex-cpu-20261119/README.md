# 原生HTTP升级字段与双向TLS传输：25项CPU通过

共享HTTP读取器保留握手字段和第一帧尾部，拒绝重复/过大key、version
与Upgrade；子协议大小写保留、重复拒绝、有界重复字段合并。握手字段
不能成为Connection剥离选项或尾部注入；待升级连接不回到普通HTTP复用。
这只解析传输元数据，鉴权、来源、客户准入和正式101必须由路由执行。

新增单线程原生双向转发和TLS非阻塞读写，两个固定64 KiB缓冲，共
128 KiB应用中转；TLS内部与内核socket缓冲另计，不声称此数是连接
总内存。SSL WANT重试保持同一缓冲及长度，单侧背压不阻塞反向事件；
写入停滞分别计时，另有空闲、整会话和每方向字节上限。EOF保持为
传输结束，不能冒充WebSocket正常关闭；不重试请求、不连接新模型。

25项CPU合同全部通过，共26次执行/约2.33秒/0GPU：7项HTTP升级、6项
旧HTTP/上传/SSE、8项实际socket与4项真实TLS。TLS1.2/1.3均验证半条
记录下反向输出、后续原数据；512 KiB完整加密输出强制多次部分写入，
最终字节完整；慢客户端仍能传入取消并命中独立写入截止时间，错误
证书在进入双向业务前拒绝。四个host/入口程序零警告构建，检查加入
公共host CTest。无新外部运行程序依赖，明文入口仍不加载TLS库。

原首次FAIL保留：夹具预设必须累计大于16384字节才产生TLS背压，
实际16256字节已阻塞。仅改正该夹具假定，继续要求实际写入截止、
反向取消到达、发送数小于接收数；生产实现和二进制不变，只重验
此一项，24项直接复用。原源码归档、配置/构建和证书留在私有阶段目录。

此阶段尚未打通实际升级路由、客户会话容量、实时ASR或官方客户端。
继续[Realtime计划](../../SERVE_REALTIME_2026-11-19.md)与全部master，
不以传输合同代替真实业务。默认rev326不变，注册ICL原FAIL/待决保持。

TLS实现依据系统OpenSSL官方[读操作](https://docs.openssl.org/3.0/man3/SSL_read/)
和[写操作](https://docs.openssl.org/3.0/man3/SSL_write/)的非阻塞合同，复用
项目已采用的可选系统库；没有复制Orator或nginx源码。
