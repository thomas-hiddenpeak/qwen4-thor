# Realtime 客户端临时凭据的签发与 WSS 兑换

Thor 上固定 OpenAI JS SDK 7.47.0 通过原生 TLS 签发两张凭据。对话首次事件带有签发时指定的指令与文本模态。临时会话持有期间，同一客户用长期 Key 建立第二个主会话得到 429。用临时凭据再签发或查询模型均得到 401。10 秒寿命届满后，新 WSS 得到 401；原连接继续完成 6 × 7，返回 42，实际用量 108 tokens。[实机观察](http.json)

另一张凭据建立独立的转录会话，首次事件回显中文语言配置。客户端发送已存的 24 kHz 项目查询录音，收到“请查询当前项目版本号。”。同一模型进程随后通过普通 Chat 返回 42。一次启动共 51.89 秒，50 次 NVML 查询成功，连接、模型和 GPU 均已清理。验收使用本机控制器夹具和实际入口、模型及 SDK。[构建身份](build.json) · [业务驱动](../../../tools/serve_live/client_secret_acceptance.py)

开发验证覆盖 18 项原生用例（含 508 个 SDK 类型样例）、8 项客户 Key 与轮换检查、7 项公开合同检查。原生浏览器子协议只回显协议名称，过期、错误签发 Key、错误进程绑定、其他客户与旁路请求被拒绝。两种入口均只将已认证签发 Key 的 SHA-256 转交模型。可选独立 nginx 承担鉴权时的临时凭据兑换仍待实现。[CPU 记录](cpu.json) · [接口清单](inventory.json)

模型内只保存凭据的摘要及受容量限制的私有配置。原生入口按当前有效签发 Key、所属客户及当前模型进程校验 HMAC，模型按墙钟和单调时钟双重检查有效期。公开响应带有 Cache-Control no-store。接下来验收 WebRTC 音轨、跨恢复边界和发行，默认版本 rev426。
