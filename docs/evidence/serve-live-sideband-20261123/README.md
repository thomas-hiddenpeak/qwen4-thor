# Live WebRTC 同身份旁路与关闭验收

固定 JS SDK 7.47.0 通过原生 TLS 连接 `GET /v1/live/sessions/{session_id}/attach`。具名客户端只能接入自己仍在运行的 WebRTC 通话，另一个有效客户端和不存在的会话均收到 404。旁路发送可信控制，浏览器保留自己配置的前端权限。首次接入和重新接入都先收到最近三秒的事件，各连接分别按原顺序和事件 ID 消费。慢读者掉出窗口时单独断连。回放窗口发生容量挤出时，新接入请求在窗口恢复前收到 503。[官方服务端控制协议](https://developers.openai.com/api/docs/guides/voice-server-controls?api=live#replay-on-attachment)。

首轮旁路正常关闭，主端漏收终态。模型进程在发送最后一组 IPC 消息后立即关闭套接字，媒体进程也未等待 SCTP 发送完成。修复后，模型进程继续接收在途消息，媒体进程有界等待可靠数据通道排空和关闭，再向模型进程确认。同一独立 Opus 对端对旧程序运行三次，两次漏收尾部消息，一次未观察到远端正常关闭；对修复程序连续三次收到按序排列的 17 条消息，最后一条均为 `session.closed`。20 项 C++ 检查、5 项公开合同检查、原生和可选 nginx 两种进程入口检查通过。审计覆盖 93 个运行时路由、92 个公开 OpenAPI 操作以及 32 项防遗漏反例。[构建身份与检查](cpu.json)。

第二轮使用同一通话，旁路断开时主端成功解除静音。重新接入后，两条控制均可回放，首次事件按原 ID 仅出现一次。再次静音后，旁路取得 22,976 字节 400 Hz 输入 PCM，模型准入为零。旁路回放的 10 帧输出与播放的 9,600 字节逐字节相同，连续时间戳覆盖 200 毫秒；主端解码 4,288 个 Opus 样本并检测到 850 Hz。主端收到同一通话的终态，两个 SDK 连接各以 1000 关闭。后续普通 Chat 返回 42，旁路名额、实时会话和主机预留归零。首轮 40.15 秒，补验 38.89 秒、39 次 NVML 查询正常，两次都已释放进程、端口和 GPU 租约。[含首轮失败的业务记录](http.json)。

本次使用本机真实媒体对端和确定性音频。既有项目资料口语查询的 ASR、LLM 与语音合成闭环见[上一阶段](../serve-live-media-create-20261123/README.md)。生产默认仍为 rev426，存储会话 fork、SIP 和带媒体程序的发行继续按总计划推进。
