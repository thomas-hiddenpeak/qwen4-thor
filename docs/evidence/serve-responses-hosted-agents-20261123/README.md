# Responses 托管子代理的真实业务短验

2026-11-23，官方 openai-node 7.47.0 经 Thor 原生 TLS 请求父代理把 19 + 18 委托给 reader。模型实际生成 spawn 与 wait 两条调用。子代理在原模型进程内生成 37，父代理读取等待结果后也回答 37。候选使用请求自己的身份、期限与配额，主验证未替换本机 rev434。

| 最终验证 | 实测 |
|---|---|
| 生成及用量 | 1 次启动，父子合计 3426 个输入、95 个输出 token |
| 流式与存储 | 24 个顺序事件，子代理文本增量带 root/reader；所有事件及终态通过发布 schema |

| 选择与边界 | 省略具名选择或给出负并发数均为 400 |
| 资源 | 6 次 SDK HTTP，41.10 秒业务及清理，严格租约正常结束，模型正常退出，端口释放 |

首次运行在子代理成功回答后返回 response.failed。根因是两次模型轮次都从调用序号 0 开始，父代理的 spawn 与 wait 得到同一个公开 ID。已在生成解析入口为后续轮次分配独立标识。第二次运行的模型和流式终态均完成，验收脚本将默认读取投影与完整 SSE 原样比较，因可选空 logprobs 字段存在差异而失败。最终运行分别校验默认投影和显式完整读回。三次原始结果与身份摘要均保留。[机器记录](checks.json)

CPU 覆盖整树并发上限、孙代理、中断后旧结果的隔离、运行中收信的先后顺序、冻结输入及已排队恢复、资源耗尽时的子代理输出与工具预算，以及 8 项共用 RPM、TPM 结算回归。公开类型图来自固定 SDK 的 6 个根、71 个节点。宿主和 GPU 两条构建均通过。

本轮 GPU 场景覆盖 spawn 与 wait。其余动作的控制逻辑已有 CPU 用例，实际模型跨轮中断、其他动作组合、执行中恢复及主轻可回退发行仍需推进。当前实现会在同一批动作处理后执行已排队的子任务，跨轮调度还需允许父代理在执行前发送指令或取消。

## 六项动作的跨轮验收

新生成的子任务会先让出一个父代理轮次。官方 SDK 顺序执行 spawn、interrupt、followup、send、list 和 wait。被中断的任务没有进入模型，重新分配的子任务只运行了一次，收到新值后答 47。父代理也答 47。一次启动、4 次 HTTP、40 个顺序事件、59.17 秒业务与清理。全轮实际消耗 9352 输入、248 输出 token。两代候选的证据分别保存。

首次测试请求 640 个输出 token，测试租户上限为 512，服务返回 400。复验将请求降至 480，按多轮消费为隔离测试客户配置累计输入 24576、TPM 32768。认证能力接口也返回六项实际动作。部署参数未修改。[原始错误与最终回执](cross-round.json)
