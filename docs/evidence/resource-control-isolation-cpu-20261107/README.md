# 资源控制面隔离CPU证据

`result.json`给出167项去重CPU通过结论、采用的逐组日志、单项复验
及未运行范围；`test-inventory.json`列出规范用例ID，29项重复由
期限模块导入监督器产生。15项新增合同包含真实CPU业务子进程；
cgroup内核文件、管理器查询和模型HTTP均为CPU替身。

`source-bindings.json`绑定9份Python、CPU登记与README，并确认默认
程序/元数据、两份视觉ELF及旧v7包未变。没有真实cgroup创建、资源
压力、模型/GPU/NVML查询或生产服务操作。

`raw-records.tar.gz`保留首轮日志、私有umask单项复验、语法/来源、
CMake登记、身份与结果文件；`manifest.json`列出成员长度及SHA256。
首轮旧观测工具权限失败保持，按其原驱动umask(077)只重验一项；
产品权限检查未改。封存初检曾把成功用例中预期CPU子进程退出的
KeyboardInterrupt输出当成日志格式不符；修正为核对unittest组
结果及完整ID，没有重跑测试，具体说明保留在封存包内。

本阶段不承诺实际systemd崩溃后存活；仅隔离查询路径，启动/清理
仍严格核验。独立host exporter尚未接受v10包，CPU结果不扩大其
旧部署范围，也不替代真实资源故障或模型业务验收。
