# 已存储 Live 会话的对话状态

启用录制的具名客户端在会话正常结束时，模型进程从已排空的前端账本获取执行历史，保留原指令、有效前端指令、音频输入的来源标记、模型回答、应用回填和调用与结果的关联。Responses 独立保存既有历史、追加项、上一轮输出和已收到的工具结果；Decisions 保存语音历史和显式项目。保存配置前清除 MCP headers、authorization 和 shell 网络凭据，另存是否需重新绑定的标志。原会话的请求、定时器、工作线程和权限句柄不进入存储。

录音对象与私有状态对象共享客户端范围，在同一事务内发布。录音保留对状态的引用；大字符串由既有对象存储分块，两者到期时间相同。WAV 下载仅读录音数据。无法取得保存状态的预算或事务明确返回容量不足时，保留可发布的录音并发出一次存储错误。无确认回执的写入不重新发布。历史版本只含 WAV，下载仍可用，读取缺失对话状态返回 409。

20 项原生 CPU 用例覆盖完成后发布、跨客户端隔离、重启后读取 2 MiB 历史、容量回退、无存储授权、真实存储故障、委派结果与前端私有上下文分离、凭据清除及已有 Responses 与 Decisions 保护。生成的协议与清单一致，运行时和宿主最终构建均零警告。首轮增量链接跨越回调签名变更，最终按一致源码重建。[构建与 CPU 明细](cpu.json)。

一次模型启动完成用户语音“请查询当前项目版本号。”、客户端读取项目记录、回填和播报 rev426。存储包含 9 条前端历史、1 对委派调用与结果，另一个 Decisions 账本独立包含同一问答。双声道 WAV 有 654,640 帧，输入和输出按原始音频逐字节复核。后续 Chat 返回 42，资源归零，65 次 NVML 查询正常，已释放进程、端口和租约。

原 GPU 驱动在模型业务、下载和后续 Chat 结束后误以裸字符串检查 ASR，原结果保留 FAIL。模型收到的历史是带实际消息 ID、内容位置和 JSON 转录值的文本帧。离线复核验证了帧边界、来源、问答、项目原始记录、两份存储对象摘要和双声道内容；错误来源、错词、漏工具结果、错误调用关联、错误资料摘要和缺失回答六个反例均拒绝。原 GPU 时间 67.12 秒，复核没有启动模型。[原件摘要及复核](business-review.json)和[复核程序](../../../tools/serve_live/fork_state_review.py)。

本阶段验证到重新打开私有存储。通过新 WebSocket 或 WebRTC 连接继续这段对话属于后续业务验收。存储源须已完成，子会话需要新的连接与 ID。[官方会话 fork 指南](https://developers.openai.com/api/docs/guides/live-conversations#store-and-fork-a-session)。
