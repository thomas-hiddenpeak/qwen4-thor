## 保留的未通过与覆盖界限

- 原直接状态组合在长前态prefill预测EOS，整组FAIL仍保留；独立
  long-only补件使用事前已有的固定8196题面，只补缺失长decode域。
- 原普通与strict边界末项都自然提前EOS，原输出/路径覆盖FAIL
  不改写。28条自然响应逐对一致；强制选择补件证明真实尾部控制，
  不证明该受控输出为greedy，也不作为任务质量或性能证据。
- 自然完整GPU extend观察形状为1/4；2/3仅有真实TU控制与受控
  verify证据，未宣称完整GPU四形状全覆盖。
- 持续8对输出一致但人工质量有4题不足，自动原分数保留。
- HC首处差异与有限误差筛查相容；intrinsic观察界不是全输入数学
  保证，也不批准整个快速T4轨迹。
- 资源/forward错误均是实际调用后的逻辑Status注入，不声称真实
  OOM或硬件致命CUDA故障恢复。RST首非空内容实际为两个换行。
- 保存首次HC独立审查的路径错误及更正，不为更正重跑capture；
  保存host临时产物位置偏差与整理记录，不冒称首次完全合规。

## 如何审查

`pack-manifest.json`逐个绑定包内文件与本机原件。verbatim文件为
原字节复制；compact文件明确原路径、SHA/bytes、保留和省略字段，
不是修改原件。全量逐项审计、数组、SQLite、长题面与完整源码快照
保留在原`.q4t-work/mtp-strict-20261009/`，通过清单可在本机复核。
SHA证明身份，不代表远端仓库包含相应raw数据或足以独立重跑全部
模型验收。模型权重/PLE payload未复制入本包。

协议和结果保留当时的绝对路径、时间和构建身份；从其他目录复跑
应创建新的`build/`或`.q4t-work/`输出，重新绑定当前环境，绝不可
覆盖原件或把旧SHA当作新运行证据。诊断源码归档保持原字节，
不把文件简单换路径后的调用冒称原运行。

HC可离线复核：恢复归档的`analyze_hc.py`/`test_analyze_hc.py`
至新的`.q4t-work/<review>/hc-analysis/`，核SHA后使用原15数组、
capture stdout和归档flags；输出必须为新文件。无需重新加载模型。
资源/尾部变体则按各自协议编译独立host wrapper、链接已绑定的旧
objects/libraries；它们是有意改变错误/选择的测试服务，不用于部署。

五档结果保留全部三次TTFT、decode与整请求时间。固定顺序小样本
仅作成本记录，不证明因果差异、统计显著性或性能不回退。严格路径
资格不使MTP默认启用，旧T4仍实验。main未自动合并或部署。
