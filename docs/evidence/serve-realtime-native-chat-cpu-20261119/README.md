- 每轮重新核验客户端身份和数据名额，复用正常 Chat 的 RPM/TPM、
  调度、取消与实际解析器。一次性执行标记禁止结果丢失后重放。
- 会话默认与响应覆盖、函数开放 schema/强制选择、工具 ID 与回填
  内容保持；`inf` 使用本 Realtime 适配器的 4096 上限，并受实际模型
  上下文与客户端限制。显式数字越过客户端限制仍拒绝。
- 实际模板计数后选择成组历史前缀，不能以截断绕过配额或其他错误。
  retention_ratio 只在越过阈值后生效；成功默认响应的截断以代际票据
  持久保存，条目仍可查询/显式引用。带外、显式输入不改默认上下文，
  删除后重建的同名条目不受旧截断影响。
- 元数据超限在发布/申请响应之前报错。取消留下的不完整服务端工具
  可查但不进入默认上下文；客户端 status 字段不能隐藏有效历史。
- 每连接协议预留 2 GiB（四工作线程规范化/截断/终态副本与会话队列），
  每份保留执行计划的 JSON 上限 64 MiB，各输入结构仍最多 16 MiB。
  模型、媒体和全局请求正文预算另计，共享 Realtime 协议池上限 8 GiB。
- 原两项失败是夹具问题：负例在 JSON 解析层已拒绝，夹具误要求解析
  成功；另一项持有临时事件的悬空指针。修复断言和生命周期，生产
  判定未放宽。独立构建遗漏生成头、依赖链接与归档目录的失败也保留。
