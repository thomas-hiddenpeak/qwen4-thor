# 原生服务入口封包、再次封包与录制开关

工作分支中的轻量托管入口已可选择 Live 录制，`q4t service prepare` 曾拒绝同一选项。两者现在共用对象存储目录、用量限制和录制参数的解析。省略该选项时保留原包设置格式；显式开启需要所选引擎具有录制声明。[原始参数错误](original-cli.txt)

用实际引擎执行 `q4t service prepare` 后，发现首次封包会在读取原生构建来源时失败。构建工具快照原先只带管理源码与许可证，而封包还核对 75 份原生来源。快照及 CMake 依赖现已包含这组文件。以已封包程序生成后继包时，使用已核验父包回执中的来源摘要；校验和写入使用同一份新回执字节。[原始进程失败](original-native.txt) · [快照身份](snapshot.json)

在 Thor 上用本次构建的原生 CLI 和 CPU 模型夹具完成 11 项检查。首次准备和检查成功；从父包显式开启后，子包生成的引擎命令恰好有一个 `--live-recordings`。改变原生来源摘要会被拒绝。另一次离线部署、回退和状态比对通过，最终为 STOPPED。旧版无录制声明的包继续拒绝开启。验证未启动模型，完整语音业务与实际主轻恢复仍需在对应发行包上组合验收。[检查结果](checks.txt) · [来源审计](inventory.json)
