# Realtime SIP 来电与原生工具业务

OpenAI Node SDK 7.47.0 通过 Thor 原生 TLS 接听一个已认证的本机 SIP 对端。所属客户提交扁平的 Realtime 配置，在远端 ACK 和媒体就绪后收到空正文 200。接听请求结束 3.2 秒后，应用用 `OpenAIRealtimeWS({callID}, client)` 接入已存在的会话，并收到该会话的模型设置。其他客户的接听、旁路和挂断均得到 404；错误的接听配置得到 400，同一笔来电随后可成功接听。[SDK 与环境回执](acceptance.json)。

电话对端发送 `#` 和真实中文录音。按键只出现一次。ASR 输出“请查询當前項目版本號。”。模型发出 `lookup_project_record({"record_key":"release"})`，客户端核对真实 STATUS 文件的 SHA-256 并按原 call ID 回填。语音回答完整转录为 `rev426`，其播放开始、排空与生成终态具有同一 response ID。对端独立解密 Opus 并解码 24,000 个样本，峰值 14,023。挂断获中继 200、旁路关闭码 1000，重复挂断得到 404。独立 Chat 回答 42。[语音及计量](speech.json)、[输入转录](transcript.json)。

第三轮严格租约用时 68.48 秒，1 次模型启动、1 通电话、6 次电话控制 HTTP、1 条获准的 SDK 旁路。66 次 NVML 查询全部正常，自有进程、端口及 GPU 租约释放。前两轮失败保留。第一轮将同一句话的简繁混写判错；针对该固定录音，逐字接受对应简繁写法，词序、字数和标点必须一致，五个改词等反例均被拒绝。第二轮真实工具回填成功，客户端设置的 64 个输出 token 无法合成完整播报，服务返回 `tts_output_limit`，对端收到零样本。第三轮沿用已验证的双向语音预算 3,457，实际消费 5 个文本和 449 个音频输出 token。[原始失败摘要](prior-failures.json)、[字形正反例](orthography.txt)。

原生会话定向组 31 项、电话接入组 6 项、公开合同组 5 项均通过。原生与可选 nginx 的路由检查分别通过，来源审计核对 103 条公开方法/路径及 36 个变异反例。用例组之间有重叠。[会话](session.txt)、[电话与音频](carrier.txt)、[公开合同](public.txt)、[原生入口](native-routes.txt)、[可选 nginx](nginx-routes.txt)、[来源审计](inventory.json)。

本轮检验的是本机加密电话对端、受控客户、手动语音提交和一次可回填的真实查询。实际运营商互通、听感、Realtime WebRTC 和打断后的自动播放历史对齐仍有各自的验收边界。候选在工作分支，默认发行 rev426。
