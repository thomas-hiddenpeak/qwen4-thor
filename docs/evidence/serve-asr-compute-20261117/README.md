# 原生ASR计算与定点数值复核

2026-11-17。3层卷积、18层分段音频encoder、28层普通Qwen3 decoder
和真实输出head已实现。8项布局CPU通过（0.007秒），隔离CUDA驱动
零警告构建。以下证据接受该计算实现继续服务集成，**不把原差分门限
追认为通过，不构成音频API、完整质量矩阵或默认发行验收**。

## 原始结果与失败

固定官方Qwen3-ASR-0.6B权重、来源和两段官方中/英文音频。原生一次
GPU加载、2次encoder、60步decode，3.618秒；两段完整生成均正常EOS，
与固定CPU参考文本完全相同。真实PCM的全量log-mel满足1e-5合同，
encoder输入和输出4组均通过；8组logits中5组超出运行前冻结的相对
L2/余弦阈值。`compute-reference-02/run/result.json`保持FAILED。

首轮参考还曾错误要求输入表/head指针不同：两份实际存储的权重字节
相同，官方按配置别名有效。保留原断言失败，只补CPU参考，没有重跑
已完成的原生生成。参考为官方源码7c6daf77、Transformers4.57.6、
PyTorch2.14.0+cpu；音频encoder eager路径显式加cu_seqlens对应的
分段mask，不能称未修改官方eager或FA2逐位对照。Python依赖只供开发。

## 对具体失败链的复核

CPU隔离1次加载/16前向，7.209秒：原CPU8组逐位重现；替换成原生
音频向量后仍有decoder差异，中文首步相对L2达0.124。随后仅抓这
一步的实际GPU操作数：1次GPU加载、1次encoder/1步decode。其encoder
输入、输出和首步logits全部逐位复现原生结果，诊断未改算术。

第一轮CPU检查完成前27层共1836项，无违例；末层检查器遇到FP32
exp溢出而退出。原源码、日志和COMMAND_FAILED保留，因异常未落盘
的逐项对象没有重建或冒充原报告。修复检查器后只补最后一层及最终
norm/head，71项、2460800个值、1.969秒通过，包含一项重复输入检查；
173个溢出位置与固定CPU参考SiLU一致，4个损坏反例均被拒绝。

实际投影/QK/PV/head满足FP64点积、FP32累加误差预算与BF16舍入区间；
重排/残差/位置表一致。norm、RoPE、softmax和SwiGLU按实际操作数、
实际归约与有限ULP实例检查，没有发现该捕获中的索引/结构错误。
这解释了最突出样本与合法浮点实现相容；不证明全部可能输入相同，
也没有逐个捕获其余7个logits样本。端到端阈值、原FAILED和限制均
保持，不能仅凭文本一致或此局部复核宣称全模型正确性通过。
