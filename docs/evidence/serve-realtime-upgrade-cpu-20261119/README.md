# 原生入口WebSocket升级与治理：16项CPU通过

原生入口为GET `/v1/realtime`和`/v1/live/sessions`接通鉴权后升级与
双向转发，保留query和上下游同包首帧。先校验来源/Host/Origin、
外部Key和握手，再申请独立的每客户1/全局4个会话连接槽；普通生成
连接和其他客户保持独立。会话内每轮生成/音频请求的RPM/TPM还须
由待接通的后端会话实现，不把握手计数当作整会话用量。

浏览器密钥子协议保留大小写，不能与Authorization重复；原密钥
不转发、不回显。只传原生认证客户及绑定token，选择显式提供的
realtime/live子协议。原生入口自己计算挑战值，只有上游101严格
匹配accept/升级字段/所选协议且没有帧长或扩展协商，才给客户端101。
上游有限4xx/5xx保持HTTP错误，不转成已升级或成功会话。

长期连接在转发前及随后每秒复核凭据与原绑定；撤销/服务代次变化
终止当前连接，不重连、不重放。每次复核复用有界原生控制通道。
应用中转固定两块64 KiB，TLS/内核/握手缓冲另计；独立写入、空闲、
整会话、字节限制继续有效。正常关闭帧透明传递，TCP断开不伪造成功。

16项CPU全部通过，共19执行、16.916秒、0GPU：8项socket生命周期和
8项真实入口/CPU WebSocket对端。覆盖明文/真实TLS、二进制帧、双向
首帧、错误挑战/重复字段/错误扩展/上游200、前置鉴权和独立容量、
原普通HTTP，以及绑定token变化后旧连接关闭且没有重连。TLS/no-TLS
入口均零警告构建，公共host CTest包含新检查。

原两项FAIL保留且解决：

- 普通HTTP在CORS关闭时不需要生成跨域响应头，但WebSocket浏览器
  不靠这些头限制连接。补上未配置允许来源时拒绝Origin的实际检查，
  并验证显式允许来源与大小写密钥的成功握手。
- TLS夹具证书受当前umask生成0664文件，原凭据安全检查正确拒绝。
  定位显示`tls_material_unreadable`；仅将新测试证书固定0644，保留
  原失败证书与诊断，生产读取权限不变。

只重验受影响3项，其余13项按未变路径复用。默认rev326及账本身份
核对不变。后端Realtime/Live会话、真实ASR/LLM/TTS、每轮RPM/TPM和
实际SDK/恢复/发行仍须继续；CPU回声不是模型响应，未宣称这些API
已业务可用，也未替换默认程序。
