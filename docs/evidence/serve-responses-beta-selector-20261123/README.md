# Responses Beta 选择参数与官方客户端

冻结的官方 JS SDK 7.47.0 使用六条带 `beta=true` 的路径，对应七种 HTTP 操作。候选已将创建、压缩、输入计数接入已有执行器，并在历史查询、取消及删除中解析选择参数。读取时可同时使用分页、include 和 SSE 回放游标。重复参数、无效值和错误类型继续受原有校验约束，跨客户端操作继续使用原有授权和配额。

在 Thor 上用最终候选和原生 TLS 入口启动一次模型；12 个 HTTP 请求在 36.74 秒内完成。普通计数、Beta 计数和实际生成均为 99 个输入 token，回答为 42。压缩返回含加密内容的压缩项。存储结果经显式 include 回读一致，能列出输入项、拒绝另一客户、删除后返回 404。另一个真实后台生成在首个文本增量后断开订阅，SDK 取消成功并从已有序号继续回放。原序列前六个事件与回放重叠部分逐项相符，回放共 17 个事件。租约完成，端口清理，默认部署未变。

10 项直接受影响的 C++ 用例、官方 SDK 对原生 CPU 后台任务夹具的组合用例、实际计数响应 schema 与开放接口生成检查均通过。保留此前的测试失败：初次 TLS 客户端误用 localhost 而证书只认证 127.0.0.1；一次对比未请求 logprobs 的存储投影与创建响应，发现空字段呈现不同；首轮 CPU 用例误用稳定版 SDK 的 output_text 便捷属性。修正后均按真实协议复验。另有一次 Python 校验在其输入夹具生成前启动，已补跑来源及校验。
