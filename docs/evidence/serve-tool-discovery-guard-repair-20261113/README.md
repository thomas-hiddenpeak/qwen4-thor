# 工具发现大词表guard资源误拒修复

先用30万候选词的两个CPU用例复现：直接语义guard耗尽工作额度，
真实隔离grammar worker在接受工具前缀后返回同样的资源失败。
错误不是已证明的物理内存不足；旧统一消息误写为memory limit。

仅负责拒答帧的guard，一旦确认普通输出前缀，后续工具/文本词法已经
由原grammar约束。删除这一分支对每个XML字符串候选的重复语义扫描；
JSON、绑定schema、拒答前缀、空token及停止检查保持。额度和内存上限
没有放宽。统一错误消息改为resource limit，HTTP错误码保持。

修后12项针对性CPU全部通过，包括两项原失败、大词表真实隔离worker、
拒答截断/混合、schema绑定/依赖故障及工具发现parser。原失败保存，
修复属于功能缺陷，不主张性能收益。其余身份未变的CPU证据复用。
