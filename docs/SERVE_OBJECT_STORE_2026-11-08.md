## 必须实现的行为

- 状态由项目自己的 C++ worker 管理，不依赖 nginx、外部数据库或
  另一个 Python Web 服务。使用本机文件系统，发行支持显式状态目录；
  独立运行可使用 XDG 用户状态目录，开发验证只写 `.q4t-work/`。
- 所有对象归属由认证后客户端身份决定。API 中的 user、metadata、
  文件名、ID、路径以及 previous/conversation 引用都不能覆盖归属。
  匿名本机模式有单独命名空间，不能借此读认证客户端的对象。
- 新写入必须原子提交并同步必要目录；更新有 revision/条件写，不能
  让并发请求覆盖新状态。内容摘要、类型、归属和 ID 均在读回时核对。
  ID 不是路径；采用持有的目录 FD、openat/无符号链接路径和私有权限。
- 有对象/客户端/全局字节、数量、TTL、队列和单次 I/O 上限；清理只
  处理可证明归属的对象/临时文件。列表游标与跨客户端访问同样校验。
- 持久成功要有已提交回执；超时但可能已经提交不能擅自重放。读取与
  再次查询用于确认对象状态，工具执行尤其不得靠重试重复副作用。
- previous_response_id 延续前次 input/output，不自动继承其 instructions；
  Conversations 按 revision 原子追加。删除、过期、跨客户端引用、
  部分失败和重启后的状态都有可核对结果。

## 故障隔离设计

复用已有 exec-only worker 的 FD 隔离、父进程死亡处理、内存上限、
pidfd、100 ms 清理和延迟回收，新增独立 objects 域；grammar 保持
原有单槽。对象 worker 未回收不能占用语法槽，也不能增殖新 worker。

对象管理器有一个独立调度线程和有界队列。启动进程、握手和 IPC
均由这个线程拥有；请求等待有 deadline/cancel。这样连 posix_spawn
本身遇到文件系统阻塞时，也不会把请求线程永远留在启动调用里。
超时后的任务/线程保留唯一所有权，不能由另一个请求反复创建替身。
后台持有的数据、计数器和清理对象不得引用已结束的请求或 ChatServer。

普通读写由同一 q4t ELF 的私有 object-worker 入口执行，无模型加载。
启动/恢复有退避与次数预算；IPC 有版本、序号、字节上限及整体期限。
父侧不得因对象 worker 失效调用模型重启或全局设备故障保护。
存储不可用时只拒绝依赖存储的请求；store=false 和不依赖它的 Chat
继续。状态明确区分 unavailable/cleanup_pending/unknown，不能报告
空对象或假成功。真正 CUDA/PLE 设备故障保护保持原合同。

## 后台执行与事件

background 需要真实任务队列和独立执行所有权，返回 queued/in_progress
后仍能 get/cancel。复用生成器的直接 sink/cancel 接口，不再引入内部
HTTP 服务。连接断开不等于后台取消；显式 cancel 必须作用于真实任务。
请求对象的停止意图与完成状态要持久化，进程重启后不得盲目重放
已经执行或状态不确定的工具。A11 工具执行日志与此对象状态衔接。

Responses 的摘要、加密推理、文件与内建工具仍是必做依赖，不用固定
拒绝代替。加密复用系统成熟密码库，不自造算法；将客户端和对象
身份绑定到认证数据，存储密钥与请求元数据分开。
