实际36个线性层均GdnRegPrepNormKernel后接GatedDeltaNetRegKernel<8>，
每层T4096、nkh16、kd128、每key对应3个value head、vd128、nv48，
扫描grid=(4,48)、block128。不是可选的32-token tensor-core chunk路径。

和全部y；用实际指针将前处理输出绑定扫描输入。保存已有首pooled
decode交接观测，324份历史BF16/FP32快照逐字节不变。

初始状态共28311552个FP32全部为正零。归一化前后905969664个v值
逐字节不变；末状态同首decode初始状态。72组dt_bias/A_log实际参数
逐字节匹配checkpoint各层[48] BF16张量。

## 独立CPU全递推

设备辅助程序只计算alpha/beta的exp/log1p等基础非线性，不调用生产
扫描kernel。CPU从捕获的全零初态出发，顺序处理4096个位置：

1. 每lane连续4个k维度，显式FP32 fma计算旧状态点积。
2. 完整重建32个lane的XOR归约（16/8/4/2/1）。不同lane有不同
   浮点加法顺序，不能只计算lane0再向所有lane广播。
3. delta = fma(-alpha,u,v) * beta。
4. 先将k*delta舍入FP32，再更新S = fma(alpha,S,k*delta)。
5. 每lane显式fma读出，再按lane0的归约树合成，最后BF16 RNE。

36层CPU从初态独立生成的28311552个最终FP32状态，全部逐位一致；
全部4096位置的905969664个BF16输出也逐位一致。不是仅末token，
不是只验证状态交接，也未将中间实际状态灌入参考来消除累计误差。
CPU和设备辅助构建零警告，各进程退出0，独立核查再次比较全量文件。

接受二进制的SASS中，例如0x1910的FMUL先计算注入乘积，0x1960的
FFMA再计算旧状态乘alpha加该乘积；0x19b0/0x1a00对应delta的融合
减法后乘beta。参考依此固定收缩顺序。另保留第0层相反收缩顺序
fma(k,delta,alpha*S)的结果：406928个状态、6102个输出不同，全部
差异索引和输出文件留存。没有在多个候选中只保留更小的差异数。
