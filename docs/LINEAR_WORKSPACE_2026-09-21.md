# 线性注意力临时缓冲生命周期与合并分配

日期：2026-09-21。候选因 TTFT 小幅回退已否决，运行时代码撤回。

## 所有权与消费边界

代码来源：`src/model/linear_attention.cu` 的 LinearAttentionForward。
所有下表中间量均由本次函数调用拥有，正常路径的 kernel/GEMM 在同一
caller stream 排序；原实现全部在首次投影前分配，在最终投影入队后
释放。conv_state、ssm_state、checkpoint、输入/输出均由外部持有。

| 临时区域 | 形状（BF16） | 生产者 | 消费者及保留原因 |
|---|---|---|---|
| qkv_raw | [T, in_qkv] | QKV 投影 | 卷积、conv state/checkpoint、晚期调试导出 |
| qkv | [T, in_qkv] | 卷积与 SiLU | GDN 归一化/递推、晚期调试导出 |
| z | [T, v_dim] | z 投影 | 递推之后的 NormGate |
| a | [T, nv] | a 投影 | GDN 递推 |
| beta | [T, nv] | b 投影 | GDN 递推 |
| y_ssm | [T, v_dim] | GDN 递推 | 调试导出、原位 NormGate、输出投影 |

额外专家 stream 不消费这些区域；异步释放仍按 caller stream 顺序
发生。调试导出是额外 host 观测，不在本次修改中调整其同步行为。
qkv_raw 的计算消费者结束后仍可能被 Q4T_LIN_DUMP 读取，后续做覆盖
复用必须把这一观测边界纳入契约，不能仅看正常 kernel 路径。

## 已撤回的候选改动

六次 cudaMallocAsync/cudaFreeAsync 合并为一对，内部六区独立，逐区
256 字节补齐。区域不做覆盖复用，数学和 kernel 调用顺序不变；继续
使用异步池，不与 cuBLASLt workspace 共用，避免 GEMM scratch 覆盖
中间输出。不扩大外部 workspace、不新增持久缓存、不改外部 API。

本模型 in_qkv=10240、v_dim=6144、nv=48。单 token 分配请求
66048 字节，较六区有效数据总和增加 320 字节对齐填充；T=8192
分配请求 538443776 字节（513.5 MiB），各区自然对齐。上述是请求
大小，不是内存池实际保留容量实测，也不是整个模型内存占用。

普通前向有 36 层线性注意力，静态预期每步减少 36×5=180 对调用，
从上一阶段 554 对降到 374 对。因 E2E 回退，未进行时间线采集核对。
该改动不减少权重或中间数据流量，不能直接推导吞吐提升。

## HTTP 结果与回退决定

必要构建零警告。第一项测试为真实 1K HTTP，三次输出一致、256 输出、
length，decode 16.877–16.960 tok/s；随后质量 HTTP 11/11，通过 200K，
服务正常退出。未运行前置单测、bench、数值微测试或 profile。

正式矩阵前三档输出一致，但 1K decode 均值 16.823，低于本轮初筛，
8K TTFT 5.652–5.680 秒，慢于固定参考 5.627–5.637 和上一阶段
5.635–5.641 秒，范围不重叠。为复核，在 44K 阶段主动终止客户端
（143），服务正常退出 0。44K 未完成、200K 性能未运行，不算通过。

使用保存的新旧二进制，各按 1K→4K→8K 顺序、每档三次、同 prompt
和 256 输出作相邻 HTTP 复测，保持分配池的请求历史顺序一致：

| 输入 token | 平均 TTFT 秒（旧 → 候选） | TTFT 增加毫秒 | decode tok/s（旧 → 候选） |
|---|---:|---:|---:|
| 1024 | 0.844 → 0.848 | +3.8 | 16.968 → 16.918 |
| 4096 | 2.853 → 2.866 | +13.1 | 15.146 → 15.118 |
| 8192 | 5.641 → 5.660 | +19.8 | 15.929 → 15.931 |

4K TTFT 旧范围 2.852162–2.854129，新范围 2.855792–2.877661 秒；
8K 旧范围 5.637940–5.645494，新范围 5.649295–5.670736 秒。
两档范围均不重叠，均值约 +0.46%/+0.35%。decode 范围均有重叠，
此前 1K 明显偏低未稳定复现；不能把所有差异统称为 decode 回退。
每组三次并不足以证明精确的长期损失百分比，但当前证据不满足
保持性能的接受要求，故撤回，而不临时设容忍比例。TTFT 含接入及
分词等，不等于纯 prefill；没有低层采集，不臆断减速机制。

**决定**：恢复 c215f74 的源码和已接受二进制，正式参考不变。
候选只保留本机 patch 与原始结果，不进入运行时代码。必要恢复构建
零警告，运行产物恢复为旧原件（SHA-256
2626c015d03667765c24ee8d0ba36d74bdd3a1d52a2a82078c19731173d6d631），
再做 HTTP 恢复检查。恢复后的 1K 三次输出一致、服务退出 0，decode
均值 16.824、范围 16.784–16.846 tok/s。该旧二进制也出现约 16.82
的结果，进一步说明此前 1K 偏低不能单独归因于候选；它不改变本次
4K/8K TTFT 相邻对照未满足接受条件的决定，也不证明底层因果机制。
恢复检查不算新一轮完整五档验收；详见 restoration.json。
