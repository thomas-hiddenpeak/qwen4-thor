# Serve 工业化持续目标与验收账

用户目标：**持续推进完善serve到工业水准**。这是持续目标，不以一个
子任务交付、兼容字段增加或单次HTTP通过作为完成。上一目标轮完成了
B1代码、默认交付和原始证据，属于实际进展；05a已交付，继续05b真实预算。

已确认范围：本机Thor、原生Qwen文本模型、OpenAI兼容Chat API、真实
项目资料/运行记录查询。部署边界已向用户询问；尚未答复时，开发规划
暂按单台Thor、多个受控内网客户端考虑，所有验证服务只监听loopback。
该暂定边界不授权公开网络部署。多模态、分布式和全部OpenAI端点不从
“工业化”推导为已有模型任务，但支持的接口必须形成完整可依赖合同。

| 要求 | 当前权威证据 | 还需完成的证明 |
|---|---|---|
| 输入、消息、工具和结构化输出 | 输入A组、grammar隔离、serve A/B1交付 | SRV-05推理控制、SRV-06 stop、SRV-07预检；支持/拒绝组合和错误位置一致 |

| 持续流与取消 | A心跳、普通流背压、取消/排空 | 严格长payload实际背压、长等待、混合负载与终态/资源回收；不能复用未观察项 |
| 有界资源和过载 | body/chat/slot边界、单严格租约/exec worker | 明确排队/限流/公平策略、统一RAM实测与保护、多个客户端受载时控制可用 |

| 访问与运维 | 本地受控服务、identity sidecar/回退工具 | 按实际部署配置鉴权、TLS/网关、请求限制、有效配置发现及运行手册；验证绕过入口 |
| 长时间稳定与发布 | 有界业务检查、零警告构建、可核验回退链 | 冻结业务负载及时间/资源接受标准后做持续运行与故障注入；重启、发布和回退演练 |

先完成[PHASES任务队列](PHASES.md#队列与依赖)B组，再根据部署答复
激活必要C项，补持续运行和运营验收。工业化接受必须逐行检查当前
源码/部署/真实证据，缺失、间接或过时证据都记未完成；不把“无已知
失败”当成证明，不为追求通过而降低既定业务要求。

每批仍是有界变更与验收，不是无限测试。性能优化按既定五档E2E；
业务可靠性记录有界质量和时延，不能冒充性能非劣。GPU验证全程互斥，
不干预别的运行服务；通过后沿用已授权的默认交付、封存、commit/push。
