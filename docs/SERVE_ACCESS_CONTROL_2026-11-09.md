# N04 原生密钥、客户端策略与配额连续性

2026-11-09。R04/N06已默认交付后继续总计划。本组是功能和可靠性
交付，围绕受影响合同验证，不运行完整性能/全模型正确性矩阵。

当前实现：原生入口认证Bearer，再向核心传递受私有代次凭据保护的
client_id；取消、缓存、对象、会话和公平队列已按这个稳定身份隔离。
API Key和backend策略随包固定。分钟额度保存在模型进程内，Guardian
在后继模型接单前保守等待60秒，避免重启提供免费额度；这不等于
精确连续账本，也不能代替可用的策略更新。

## 全部交付项

1. 原生认证快照：每个稳定client_id允许有界多Key重叠轮换和全部
   撤销，替换原子发布。新请求使用当前快照；已经获准的请求持原
   身份到完成，不换租约、不重放。客户端槽位只追加、不重排复用；
   撤销保留身份和历史Key指纹，旧Key不能转授其他客户端。
2. 私有策略存储与原生管理入口：预期revision、持久提交、读取核对、
   失败/未知提交处理、跨入口代次恢复和可查询状态。Key不进入日志、
   指标、公开HTTP或验收原件；有效更新必须报告实际应用代次。文件
   I/O隔离在自有辅助进程，不能堵住HTTP/模型或引发模型重启。
3. 动态客户端限额及连续用量：变更不清空已用请求/token/预留，撤销
   不释放仍在执行的租约；降低限额只影响后续准入，额度关闭再打开
   不能获得免费重置。持久/运行态版本一致后才允许新客户端接单，
   控制、取消、数据三通道及公平队列的边界继续成立。重启、跨boot
   与未知账本必须有明确保守恢复路径，不允许通过重启绕过限额。
4. 随包CLI/原生入口组合、官方客户端适用场景、实际工具/会话隔离
   与故障短验；证据满足后可回退默认交付，再继续其余总任务。

外部nginx只作为可选前置；本组权威认证/策略不能依赖它的私有头。
未实现项保留为必须完成的任务，不以“固定包不支持更新”结案。

## 首组有界实现与验证

先做认证快照和身份不复用原语，再接持久事务/管理与额度。首组CPU
冻结6类：重叠轮换/全部撤销及原请求身份；版本冲突/畸形输入原子
拒绝；客户端重排/删除/跨客户端复用Key拒绝；历史指纹恢复后仍拒绝
旧Key转授；并发认证只能看到完整旧或新快照；客户端/Key/历史容量
边界及状态输出无秘密。只构建独立host目标，默认v6及引擎保持。

之后按实际接口冻结受影响集成/额度CPU和必要真实GPU业务短验；
已通过且身份未变的证据复用。N04只有全部四项完成才标记交付，
首组原语或任何阶段完成都不结束总目标。

首组6个原语CPU已通过。下一组持久合同冻结8项：Python/C++同一
指纹/格式且大历史清单有界；真实持久与幂等；rename前完整pending
恢复；rename后fsync未知提交识别；损坏/缺失不恢复旧包Key；外来
身份/链接/写者竞争拒绝；receipt数量/旧请求边界；来源变化与伪造
pending前驱拒绝。所有文件仅专属CPU夹具；持久成功明确不等于
live_applied，后续仍须接实际入口和查询生效代次。

原生入口接入采用稳定认证快照。独立私有SEQPACKET通道只接受父
网关进程发布；同UID其他进程只能读摘要状态。最多2连接、每个
1MiB/3秒、每轮每连接8个16KiB帧；状态和TLS管理各自保留，公开
HTTP不提供密钥管理。新托管配置先无认证策略，返回明确503，只有
已验证持久快照发布后才认证；旧v1/v2启动配置兼容保留。提交滞后
可按预期当前revision追到更高已持久版本，但槽位/全部Key归属必须
单调延伸，不能回滚或重置旧策略。

此接入组冻结：2个新增C++追赶/回滚合同；6个真实原生入口CPU场景
（初始503与完整安装、重叠轮换/撤销和在途身份/容量、只读外来进程
不能发布、大历史分段与慢/损坏消息、新入口恢复最新撤销和摘要
冲突、旧配置兼容/伪造身份头）；另验证Publisher身份/新鲜度。
使用合成CPU上游，不能算真实模型业务；持久I/O辅助进程及其隔离
预算、完整管理CLI/配额协同仍接着实施，不在此阶段结束N04。

隔离读取采用单个持久CPU worker；父进程在spawn前创建独立abstract
Unix拥有租约，worker继承，因此即使卡在解释器/模块读取阶段也不
能跨入口代次累积。该租约不占GPU锁；只传私有IPC/独立拥有FD，
不继承模型/Guardian控制FD。完整策略读取与重新fsync均在worker；
父循环仅收有界分段、核对身份/顺序/摘要，每次请求2秒期限，实际
回收后才替换，3次/60秒和退避。普通文件/写锁错误在同worker内
报告UNKNOWN并重试，不能回退旧包或重启模型；已认证原生快照继续
服务，首次没有可信策略才保持认证入口503。

I/O组冻结7类CPU：真实持久读取及新版本；写锁竞争/损坏错误不
增殖worker；SIGSTOP超时/回收和启动预算；竞争独立租约不spawn；
父退出后遗留FD仍阻止增殖；坏序列/大帧有界拒绝；私有FD继承及
原生已应用快照在文件失能时继续服务。只操作专属CPU夹具。

托管管理接入使用v7包/v3网关配置，旧v1—v6来源清单固定保留。
新服务明确初始化journal，旧服务只允许在STOPPED且独占Guardian/
核心写者时显式迁移；独立永久标记使整个journal目录丢失也不能
再次初始化旧Key。首次入口在策略发布确认前不绑定业务代次；文件
失能后的已有认证快照继续服务，不关闭模型。CLI支持access-propose
（私有原始Key文件生成无明文Key的版本提案）、access-apply（UUID/
预期版本幂等提交）、access-status（持久/真实入口代次分别显示）及
旧包access-migrate。提出方案不算提交，提交不冒充live_applied。

此组冻结8个管理/实际托管CPU（5管理合同、3托管HTTP/重启/文件
失能）；4个受影响包/来源/启动合同、3个受影响I/O以及1个旧v2
实际托管入口回归。合成模型/Guardian明确标注，不替代真实业务。
新客户端在backend动态更新接好前拒绝提前生效，下一项必须补齐
其协调发布、动态额度和重启连续性；这个临时保护不作为完成结论。

动态backend先实现v3策略快照/用量原语：只允许稳定槽位追加和更高
revision，模型私有代次token与公平模式保持；全局容量不足原子拒绝。
请求持不可变身份快照，而数据/控制/取消/RPM/TPM计数在固定槽位，
更新不复制或清零计数。新的Reserve检查当前限额，v3额度关闭时仍
记录逻辑用量；已经预留的请求继续结算，跨分钟保留尚未完成的预留。
v1/v2维持固定配置合同，不被暗中转成动态模式。

原语组冻结6个新增CPU：v3版本输入、快照/槽位/身份移动、降低限额
时三通道与转移租约、额度关闭再启用和跨窗口预留、旧身份不能绕过

客户端合同统一运行，非全项目测试。仅host构建/CPU，持久用量恢复、
backend私有发布和新客户端协调还须继续接入；默认及GPU证据保持。

持久backend限额使用独立client-limits journal与永久标记，复用已验证
的事务/未知提交恢复实现，通过不同格式和目录拒绝与Key journal
互换。持久策略不保存模型代次凭据；模型侧注入当前私有token，
C++/Python共享语义摘要仍保持相同限额身份。Key轮换不触碰限额
事务，限额变更也不恢复撤销的Key；新客户端须先持久保存限额，并
在模型确认实际安装后才通过入口准入。用量持久恢复另有运行态合同，
不把保存限额当成用量已恢复。

此组冻结6个新CPU：跨语言/代次摘要、大客户端/receipt上界、两类
journal隔离、写入中断恢复、整目录丢失不回退、槽位/公平/全局
容量。复用事务引擎的9个既有CPU、1个永久标记恢复、1个真实I/O
读取及1个实际托管轮换复验。仅这18项，模型私有发布和用量恢复
继续实施，未进行GPU业务或默认替换。

模型私有发布采用独立线程和abstract SEQPACKET，父controller身份由
pidfd固定；父退出后，已经建立或转交的写连接也不能继续发布。
同UID其他进程只读状态，最多2连接/64KiB/2秒，每轮8帧；坏消息、
异常和失联不撤销已生效限额。发布尝试持有准入队列锁，忙则重试；
追加客户端保留队列轮转、旧票据和所有用量/预留，不等待模型锁。

父退出后的在途连接拒绝。另加1个新队列追加合同和2个受影响公平
队列合同，共8项。仅host/CPU，随后接托管模型和控制器协调、连续
用量与真实交付，不把私有通道模块通过当作N04完成。
