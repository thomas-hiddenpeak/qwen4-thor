# 媒体状态缓存与视觉分块接入

2026-11-17，继续A05/A10/A12/Q01。当前rev204虽能接受Chat/Responses
缓存控制，但媒体请求主动绕过缓存；显式状态目录不能与媒体并用，
视觉提示超过prefill工作区被拒绝。这些是本组必须解决的功能缺口。

## 合同与实现顺序

1. 缓存身份绑定实际解码来源字节、处理参数、几何与token位置，不能
   只比较相同的image/video占位符。按完整视觉块比较已缓存前缀；
   追加媒体不使此前相同前缀失效，改变前缀内像素/帧/参数必须未命中。
   客户身份、API key scope、TTL、取消和成功后发布规则继续有效。
2. 保存有效三轴位置及实际RoPE偏移，恢复后正确接续；target与MTP
   布局隔离。视觉仍使用target，不能把文本draft套到视觉。普通文本
   和无媒体的既有MTP路径保持其数值合同。
3. 把实际模板的byte/token边界映射到媒体展开后的token；不在视觉块
   中途发布/命中快照，不凭字符数估算。schema、工具、存储和多choice
   组合复用相同路径，缓存失败仍只失去缓存，不拖垮健康核心。
4. 原生视觉分块使用整条提示的三轴位置和每块正确的特征行切片，
   PLE历史与各层状态连续。分块长度只受工作区限制，整体仍受实际
   context、媒体解码/特征和准入预算约束；不通过删除资源校验放行。
5. 同步能力描述与测试入口，通过必要业务后可回退交付、实际合main；
   不将此阶段当全部A10或总目标完成。硬解码和视觉并发不在本组扩展。
