## 合同与实现顺序

1. 原生请求/结果规划：标准input字符串、字符串数组、文本/图像对象
   数组；字符串数组逐项、单字符串或一组多模态内容单结果。默认
   当前本地模型，可用已配置别名，返回实际模型；不冒充云端模型。
   严格拒绝混合错误类型、未知字段、无效图像结构和非有限分数。
2. 原生HTTP执行：复用真实受约束13类模型分类及内部步骤通路，
   单外部请求/取消/准入所有者，全部步骤计入一次RPM与真实累计TPM。
   返回标准id/model/results；内部工作用量在诊断与Batch私有结果
   保留，不污染标准结果字段。不完整分类返回有限错误，不能发布
   部分成功或补零。设备故障保护、超时、断开和Batch取消保持。
3. Batch准备/真实模板计数/预留/执行接通moderations，沿用原行期限、
   原子实际用量、重启不重放。配置/能力/协议来源、原生入口和官方
   SDK同步，其他四类Batch后端与A10媒体任务持续保留。
4. 针对性CPU与真实官方SDK网络验证，再必要有界模型业务/兼容发行。
   非性能任务不重复完整性能或全模型正确性矩阵；已接受同身份的
   嵌入式审核、内部步骤和存储/双池证据复用。

单请求服务容量：最多32独立文本结果或一组最多256多模态部分；
总文本至多1MiB，图像另受既有媒体/HTTP容量控制。每个分类步骤最多
512输出token，整个请求同时受客户端累计提示/TPM和原截止时间约束。
这是明确有限资源边界，不是删掉其他输入类型；真实媒体路径也须验收。
局部CPU/提交不能结束本项或Serve总目标。

## 真实业务冻结

同一严格GPU租约最多2启动、8请求、9模型步骤、900秒。文本MTP
配置验证2文本顺序/良性与威胁分类、未知模型404、独立TPM16客户端
429、2分类步骤的单行Batch、运行中8输入Batch取消及同进程普通
Chat。排空正常退出后，显式视觉配置验证原Batch和结果File原件、
实际PNG的文本+图像及仅图像分类。原图是项目自有红/绿矩形，输入
固定SHA；检查13类适用类型和分数，不虚构云端校准。

每次外部审核只占一个RPM，各内部分类的实际输入/输出计入同一TPM；
拒绝不运行模型，取消不发布部分结果、释放全部占用，Batch独立池
与真实逐行用量一致。配置转换是驱动显式安排，不是故障自动重启。
默认/其他服务保持；失败保留原件、修复直接问题，只补受影响部分。

## 依据

2026-11-11已读取[官方Moderation指南](https://developers.openai.com/api/docs/guides/moderation)
及[创建接口](https://developers.openai.com/api/reference/resources/moderations/methods/create)，
并核对固定OpenAI Node7.47.0的ModerationCreateParams/Response定义。
官方多模态示例将一组文本/图像传给ClassifyInputsAsync并返回单一
ModerationResult；本地据此按同组内容分类。逐项字符串数组保留顺序。
沿用已有本地模型0.5阈值和完整13类估计，接口兼容不等于云端模型校准。
