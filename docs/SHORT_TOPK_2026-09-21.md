# 短路径 top-k 寄存器网络（2026-09-21）

状态：接受。基线 4f4b8d8；质量 HTTP 11/11、五档性能 15/15，
完整门禁后的 4K HTTP 时间线及精确选择专项通过，正式参考整体更新。

## 固定形状与语义

FullAttentionForward 的短上下文分支中，max_blocks=2048、
block_topk=512 时选择独立 short_topk.cu。tokens=1..8192，共用
已有私有 BitonicSortAscWarp<2048>；该模板本身不修改。其他预算
继续原实现。单 token decode 与多行 prefill 都属于本轮影响范围。

原 kernel 的内联 shared 比较网络被替换，其他语义保留：可见组数
不超过 512 时按位置直接展开；否则按原严格比较与同分 ID 排序，
按照排序后的块槽展开 complete groups，仅追加未完成组的可见尾部，
最后填 -1 并写 topk_len。不能以集合相同代替槽序相同，槽序决定
后续注意力的累加顺序。

没有新 scratch 或回读，输入分数与候选覆盖不变；每 CTA 原 shared
分数/ID 数组仍为 16384 字节。完整 E2E 后 cuobjdump：REG 40→44，SHARED 均为 17408 字节，
STACK/LOCAL 均为 0；编译工具口径不与源码数组容量混算。
只改变执行映射，不能从源码比较次数或旧网络耗时推导 E2E 提升。

## 已接受参考成本

基线对应 `.q4t-work/e2e/indexer-decode-cta-20260921/timeline/`，
4K 单流 HTTP、255 次 decode：TopkSelect 3060 次累计 226.446 ms，
约 0.888 ms/步；prefill 12 次累计 25.608 ms。1K 的 dense 展开历史
采集约 0.043 ms/步，不具有同样排序成本。采集有额外开销，不混入
正式 TTFT 或 decode 吞吐。

## 完整五档性能

TTFT 包含 HTTP/分词/prefill，取三次均值；decode 用首 token 后
总生成数除以总时间。没有拼接最优档位。

| 输入 token | TTFT 秒 | decode tok/s |
|---:|---:|---:|
| 1024 | 0.829905 | 18.610975 |
| 4096 | 2.793991 | 17.871090 |
| 8192 | 5.487675 | 18.160609 |
| 45056 | 31.856343 | 17.855478 |
| 204800 | 165.022657 | 17.072029 |

4K decode 17.737→17.871 tok/s，约 +0.76%，新旧三次范围不重叠。
8K TTFT 5.547→5.488 秒，约 -1.08%，三次均优于旧范围。其余 TTFT
与 decode 范围重叠，微小均值变化不视为稳定收益，无可辨识回退。

## 完整 E2E 后的精确选择与时间线

候选 4K HTTP 完成且正常退出、SQLite 完整导出后，串行执行
compare_short_topk.py。工具校验完整门禁、SHA 与源码快照，从
4f4b8d8 提取原 TopkSelectKernel，与候选实际公共入口比较。

352 组、277598448 个位置槽/长度逐位一致。1/3/33 行覆盖
0/1/511/512/513/2047/2048 组、四种尾位置、随机/同分/正负零/尾组
胜出，另含 8192 行混合 dense/sparse 和上边界。全部 -1 填充也比较，
不是只比较集合。构建零警告；公共模板源码未变化。
