# 原生 MCP 接入实施与验收清单

本组落实 A07/A11/A12，沿用全部 33 项 Serve 总目标。原生入口、
持久状态和恢复不依赖外部代理；MCP 服务是用户显式选择的工具数据源。
该数据源失效仅影响对应工具，不停止健康模型，也不触发模型重启。

## 固定合同

协议基线为已安装 OpenAI Node SDK 7.47.0 的 Responses MCP 类型、
官方 MCP 工具指南，以及 MCP 2025-06-18/2025-03-26 Streamable HTTP
与 2024-11-05 HTTP/SSE。后续协议变更单独追踪，不无限追随网页。

实现工具列表、过滤、默认逐调用审批、审批拒绝及续接、实际调用、
标准 items/SSE、鉴权头隔离、调用上限/超时/取消，以及持久会话、
后台、工具发现和程序调用组合。connector_id/tunnel_id 需要部署端
明确映射和实际接入，不能假装是任意 server_url 或从完成表中删除。
工具返回的文本、结构化数据、媒体与资源引用须保留原语义；不可
捏造结果或通过固定错误实现接口。外部副作用不自动重放。

## 顺序与出口

1. 原生传输：复用已有 URL/DNS/CIDR/TLS 与 HTTP framing，实现
   POST、增量 SSE、版本/会话协商、旧传输、分页及明确的协议错误。
   独立有界 worker，不占 grammar/文件/模型执行槽；未回收保留本域。
2. 工具及权限：认证客户端绑定的目录、调用参数/结果 schema、
   allowed_tools/allowed_callers、require_approval、认证状态加密。
   authorization及私有headers只在本次请求内存中使用，不写入持久
   Response/工具状态或回显；续接由客户端重新提供。后台恢复缺凭据
   时保留明确失败/待续接结果，不能从日志恢复凭据或重放调用。
   结果不确定与未执行分开，持久派发记录防止恢复后重复外部调用。
3. Responses 接线：列表/审批/调用 items 和完整事件、模型模板、
   续答/压缩/计数、发现/程序、background/Batch 与资源预算。
   输入合同通过必须伴随真实执行；能力声明在完整接线后启用。
4. 针对性 CPU、官方 SDK 及本项目真实只读资料 MCP 闭环，再完成
   适用主轻/恢复资格、可回退发行与实际主线合并；继续剩余总计划。

不新增 HTTP/JS 服务程序，TLS 复用既有系统 OpenSSL。地址策略由部署
控制，请求不能放宽；鉴权只发给明确目标，不沿跨源跳转传播。凭据、
带秘密的 URL/会话标识不进入模型、普通日志或公开回执。

## 首组针对性验证冻结

先开发传输及 worker，统一验证以下行为：JSON/SSE 双响应、旧 SSE
初始化、会话/协议头、分页与重复游标、JSON-RPC ID/错误、结果类型、
无审批前派发、请求头注入/目标限制、截断/帧冲突/容量、超时/取消、
未回收占槽和其他域继续、无调用自动重试；直接受影响的文件获取
framing/TLS 验证复用或针对性重验。0 GPU，不替换 rev126。
公开接线完成后另固定必要真实请求和身份，不开展完整性能/质量矩阵。

传输部件已通过[21项针对性CPU](evidence/serve-mcp-transport-cpu-20261115/README.md)，
其中HTTPS只读真实项目资料；首次夹具错误及修复记录保留。
公开接线、权限/审批状态、真实模型业务和发行仍未完成，继续实施。
每次传输操作当前建立并关闭一个会话；跨调用会话连续性在执行层
接入时仍须核对，不能以部件验证替代完整接入。

公开声明，原始输入/输出schema保留，默认审批、显式never和always
覆盖及readOnlyHint默认false均已接线到部件。connector/tunnel目前

凭据不存储、重启不重放未知派发、成功结果持久回读及实际本地工具
确认后派发。CPU成组验证，0GPU、默认rev126保持；公开业务随后继续。

包括官方SDK消费；成组针对性CPU后冻结真实资料HTTP短验。
