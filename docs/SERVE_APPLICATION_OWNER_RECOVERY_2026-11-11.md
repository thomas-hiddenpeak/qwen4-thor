# 应用任务执行器首次失败的有界恢复

承接A09与R01：fc69f823已完成永久输出容量组件。源码确认ResponsesJobs
和BatchJobs在Start中只创建一次；异常只记日志，后续60秒轮询仅能给已有
ResponsesJobs启动扫描器，不能恢复空执行器。这是待实现的可用性缺陷。

本组原生补齐以下合同：

1. 两类执行器的初次创建和Responses恢复扫描器的初次启动分别持有固定
   重试状态。失败间隔至少250毫秒、每60秒最多3次尝试，窗口结束可继续
   恢复；不在请求路径临时创建线程，不重启模型，不引入外部程序。
2. 执行器只发布一次，使用acquire/release指针供请求和后台线程读取；
   成功发布后地址与所有权保留至服务请求/任务排空。已有失败、卡住或
   尚持任务的执行器不能被另一个执行器替换，也不能重放已开始任务。
   构造抛异常必须先完成已有构造器的部分线程清理，再允许下次尝试。
3. Start和服务循环作为创建协调者；回调只创建本地有界线程/规划快照，
   不同步执行模型或存储I/O。请求线程读取和健康查询不等待创建。
   停止意图立即阻止后续创建；已经开始的创建在发布时停止新对象，
   原shutdown顺序负责排空。SIGINT/TERM入口保持仅无锁原子操作。
4. 配置诊断明确显示未创建、创建中、退避、可用、停止，以及尝试/失败/
   恢复次数和剩余重试时间；其失败不改变健康模型readiness。
5. 针对性CPU检验真实执行器创建失败后恢复、真实任务完成/取消、部分
   线程清理、并发读取/单次发布、停止竞争、频率上界、扫描器失败恢复
   与不替换已发布对象。测试可以缩短内部时钟窗口，生产默认保持。
   批量完成后统一验证，仅具体失败补验，不追加完整性能/模型矩阵。

完成本组后继续Batch实际模型业务与兼容状态/配额/父关联/失败结果读取
回退及发行，再继续全部Serve总任务。本计划不将CPU通过冒充业务交付。
