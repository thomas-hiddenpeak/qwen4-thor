# 自动恢复 A/B 执行与验收边界

2026-11-07。承接[已确认设计](SERVE_SELF_RECOVERY_DESIGN_2026-11-07.md)，
本轮为服务可靠性任务，不作吞吐优化或长稳结论。

## 有界交付

- A1：纯 CPU 故障决策、持久恢复账本和私有事务协议。恢复预算不依赖
  控制器 PID、发布目录或墙上时钟；停止、故障锁定和中断的启动授权
  不能被下一次启动隐式清空。账本由独立 worker 单写，Guardian 不在
  控制循环中执行 fsync；持久化失败冻结新授权，已有健康业务继续。
- A2：不链接 CUDA/NVML 的独立 Guardian，process 资源模式，受限
  控制通道、pidfd/subreaper/父死清理、同租约 FD、前后台及停止接口。
  CPU 子树、并发启动、停止竞态、坏账本和清理失败成组验证。
- B：接通生产控制器与模型恢复、固定入口的代次重绑、恢复前生成
  检查及配额等待。单严格 GPU 租约最多 4 次模型启动（含自动替换）、
  20 条 Chat、30 分钟；涵盖 JSON/SSE/工具、辅助故障不换 PID、模型
  死亡恢复、控制器死亡恢复和最终清理。生成自检计入 Chat 预算。

实现与 CPU 验证按 A1/A2 清晰提交，再统一 B 业务验收。已经通过且
身份不变的证据复用；具体失败后仅重验受影响项。每次测试留原件，
失败不覆盖。未通过 B 不宣称自动恢复已生产交付，不改默认程序、
旧封存包及视觉证据。

## 固定政策

模型替换最多 3 次/30 分钟、6 次/24 小时，控制器替换 3 次/15 分钟。
首次创建可启动一代；以后即使手动 stop/start 也不重置替换预算。
重试 5/20/60 秒，熔断至少 15 分钟且自然预算恢复后才允许半开。
同发布与配置下同故障在两个模型代次出现时锁定；未知退出最多一次
探测恢复。稳定窗口关闭 incident，不清空预算。

所有预算用 boot ID 与单调时间。跨 boot 不用墙上时钟推断已过去的
时间，保守保留剩余窗口；墙上时钟只用于审计展示。没有账本、损坏
账本、并发 writer、未对账的授权均不得按“第一次运行”自动重建。
初始化必须显式，service_id 与私有持久目录绑定。

停止首先在 Guardian 内存中冻结授权，再持久化 STOPPED 意图，
按期限清理自有进程。持久化失败也继续清理，但不得声称已持久停止；
下次启动须重新核对未完成事务。辅助错误不改模型健康，真实设备
错误/身份损坏/未回收旧进程继续保护，运行期不重放 POST 或工具。

## 不纳入

阶段 C 的通用执行进度 watchdog、所有局部 worker 阻塞隔离，以及
阶段 D 的 profile 自动降级、委派 cgroup、NVML-free 冷启动和整机
恢复均后置。Guardian 最外层死亡时无反向复活；无外部启动入口
不承诺断电、重启或整个进程树被杀后的自行启动。
