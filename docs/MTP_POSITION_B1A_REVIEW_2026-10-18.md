# B1a实现、证据复审与补验提案

2026-10-18。审查对象 `1c6e792`，父版本 `867b8a6`。
本轮仅源码/文件/已有计时的离线审查，新增HTTP/GPU请求0，不构建、不运行
模型、不profile。B1b不在范围内。旧冻结结果与原始证据未修改。

## 审查结论

未发现本次位置下传的生产实现缺陷；在已验证范围内保留计算合同与HTTP
质量的结论。**性能仍为证据不足，不批准合入或替换生产binary**。
“有界交付完成”表示候选和证据已交付，不表示性能接受完成。

实现核对：

- `MtpForward`末尾增加默认-1参数，原调用保留fallback；仅两个multi调用
  显式给值。草稿第j轮对实际上传的B个`P[b]+j-1`取max；B已经检查>0。
- extend只打包非终止序列，取实际`ext_pos`最大值；仅在T_ext>0内求max，
  空向量不解引用。slot不是逻辑位置，未用容量、MRoPE或未来位置代替。
- `FullAttentionForward`原分派仍使用 `(max_pos+1)/4`；8194/8195分别为
  2048/2049组。相同max、T及slot映射保持分派与QSA算式，未加padding。
- 原位置复制、MoE计数同步、接受/恢复与KV更新未改。被移除的只是下层
  重复位置D2H/vector/stream wait；上传host数组活到step cleanup，后者
  仍等待stream完成，未发现因删中途同步而提前释放源数组。
- k1没有草稿循环；非空extend仍下传。k3非空通常省3次位置回读等待，
  不等于整步零同步，也不是3次等待对应的耗时收益证明。

## 已有证据能支持什么

本轮只读核验B1a raw-manifest的355个文件，全部大小/SHA匹配；另核验
历史phase04中用于对照的18个关键文件（结果、binary身份、runner、cache、
各档responses）。两侧runner SHA、EvalScope版本、CMakeCache一致；服务
配置相同，binary路径、端口及采集时间不同。raw响应重算TTFT均值与
`Σ(output−1)/Σ(latency−TTFT)`和原报告一致，输入长度、prompt、输出文本
逐条一致。见[复算](evidence/mtp-position-b1a-review-20261018/recomputed.json)。

| 层次 | 证据判断 |
|---|---|
| HTTP | 两组质量各11题、五档各3次及尾部/取消通过，原结论可保留 |
| 位置逐位 | 56组、T1…8、8194/8195等边界，sample/multi/logits及全部draft KV/raw/comp逐位相同 |
| multi接入 | k1/3、slot交换、不同P、a=0/1/3、全终止及最大P序列终止均有实际PASS |
| 完整恢复/N=4 | 复用旧机制证据并结合此次接入/HTTP；不是在新binary上重跑了完整256步N=4 |
| 性能 | 只有跨日、不同binary的历史对照；不能确认持平、收益或真实回退 |

覆盖限制不是新发现的计算失败：位置夹具从零状态设置稀疏高位置，两次
前向重用位置，不是完整长前缀逐token推进；生产step没有单独控制a=2。
T=3逐位测试不能冒称a=2接受/恢复已独立验证。multi测试检查输出与调用者
推进语义，不是完整step新旧两binary所有状态的逐位差分；QSA选择未单独
导出比较。结合此次未改变接受/恢复或分派公式的源码范围，这些不要求现在
重跑全模型或重开数值研究；若扩展范围则另冻结合同。

流程记录也应准确：测试夹具在HTTP期间仍有完善，完整测试身份并非在
首项HTTP前全部定稿；最终执行身份已保存，最后样式整理后的测试binary
与已执行版本SHA相同。此事实不应改写为“所有工件事先完全冻结”。

## 缺少的性能证据与现有数据的补齐能力

| 缺口 | 当前数据能否补齐 |
|---|---|
| 同期精确父版本A与候选B的可比矩阵 | 不能。保存的父binary8685d8bf未测；旧矩阵为be74946d，候选为44abd8b1 |
| 同身份、同请求位置、无插桩的跨服务重复与漂移控制 | 不能。完整五档每侧每模式只有一个服务生命周期，3次是服务内重复 |
| 每档TTFT/decode分别有依据的分辨带 | 不能。没有独立A/A校准/验证；不得用候选差值或三次极差倒推容忍度 |
| A/B差值的不确定区间 | 不能可信补齐。跨日偏移、启动/热态和次序效应未分离，小样本重采样不能创造独立信息 |
| 原计时、实际长度、首请求身份、工具一致性 | 可以，已离线核对；但这是数据完整性，不是上述缺口的替代 |

[记录清单](evidence/mtp-position-b1a-review-20261018/available-runs.json)
搜索本仓库`.q4t-work/`的binary.sha256配套results.json，限定上述三个SHA。
完整矩阵的额外副本结果SHA相同，是归档/暂存拷贝，不是独立重复。
其余基线记录只覆盖200K；HC系列包含插桩、观察器、调频、地址/内存干预，
或不同请求次序/客户端组织。即使某个控制项未受特定干预，也不能补齐其他
四档或拼成同配置完整校准。原频率clock-cross同样启用oc-observer，不因
“O”标签就当未插桩性能证据。该清单不声称找到了机器上所有可能命名的证据。

统一正值表示变慢，历史对照的观测范围：

| 模式 | TTFT均值变化 | decode吞吐下降（负值为改善） |
|---|---:|---:|
| MTP on | −0.0117%～+0.6055% | −0.5330%～−0.2568% |
| plain off | +0.0994%～+0.5625% | +0.1278%～+0.3173% |

1K首次请求、跨档借TTFT范围给decode，或以“同步少了”替代E2E判定。

## 最小有界补验提案：最多150个请求，尚未授权执行

这是补齐同期对照和测量能力的提案，**不是保证150请求能证明0.3%量级
变化的功效计算，也不是已经具备数值阈值的GO卡**。最低工程成本的选择
仍是维持未决候选、0新增请求。若要继续争取接受，建议以下一个完整阶段，
不只对看到好转/变慢的档位补采样。

A固定保存的父版本8685d8bf（源码867b8a6），B固定已验候选44abd8b1；
不重编、不替换为含其他优化的binary。分别运行on/off，同一GPU lease，
原五档输入、每档3次256输出，单流、容量1/8192/208896、相同模式/客户端
和启动策略。每个“轮次”包含on和off两次服务生命周期，各15请求，共30。

| 阶段 | 轮次 | 请求预算 | 用途 |
|---|---|---:|---|
| 测量能力门禁 | A0、A1 | 60 | 同身份重复；发现启动/时序/环境不一致或明显不稳定可在此停止 |
| 条件交叉对照 | B1、B2、A2 | 90 | 连同A1组成A-B-B-A；两次独立B启动，末尾A用于检验漂移/校准适用性 |
| 总上限 | A0 A1 B1 B2 A2 | **150** | 每mode五档各A×9、B×6；没有额外热身/探测请求 |

固定全序：A0-on/off、A1-off/on、B1-on/off、B2-off/on、A2-on/off。
每次完整矩阵按1K/4K/8K/44K/200K、各3次执行，不使用显式单档入口改变
客户端启动组织。ABBA的对称次序可减少线性时间漂移影响，但不能假定
实际时间间隔对称或漂移必然线性，保留真实时间戳；不通过拟合强行校正。

为什么不是只补30/60请求：单独补一轮A仍留下跨日/启动混淆；一轮A+B
没有同身份重启参照或反向次序。单纯ABBA为120请求，但没有比较前的
独立A/A测量能力门禁。加A0并复用A1，五轮150是本提案的最小结构，
不是所有统计设计的普遍最小样本数。旧B矩阵不能冒充新的B1或B2。

### 统计与停止约束

1. 启动前固定比较统计量、分辨带估计及验证方法、差值区间方法、环境
   有效性规则；不得留到看过B1/B2后调整。分辨带只能来自A数据及可比的
   独立既有校准，不能由B的效应大小反推。**目前这些可信数值带未建立。**
2. A0/A1的各档三次不能被宣布成完整噪声上界；60请求门禁只是检验测量
   条件与继续成本，不能自动授予“已校准”资格。若无法在有限证据下说明
   区间/分辨带为何可信，应停止在60，不为填预算自动进入B。
3. 基本比较保留每个服务内请求序号、1K首次与后续的区分，按同位置配对。
   每模式/档分别报告TTFT均值、总decode吞吐和A1→B1、B2→A2两个方向；
   ABBA汇总同时保留两方向结果。服务内3次不是3次独立服务重启，不能
   将所有token、SSE chunk或相关请求当成独立样本做伪精确置信区间。
4. A2作为未用于初始分辨带估计的留出检查；若其同位置A/A观测推翻校准
   适用性，不在看过B后扩大带宽，判证据不足。方向反转或对时间假设敏感
   同样不能凭均值抵消。只有可信差值区间上界不越过可信回退边界，且
   所有20个指标/保护项满足原规则，才能接受；不是“不显著即持平”。
5. 预算尽或方法能力不足仍未决就停止；明确真实退化则NO_GO；环境竞争
   则ENV_ABORT，保留现场。无自动重跑、追加样本、剔除失败或profile。
   环境失败后要修复/冻结受影响重验范围，不能无限扩充150上限。

本提案故意不编造0.5%/1%阈值或给小样本硬套95%区间。若要求预先保证
分辨0.3%变化，现有数据不足以给出可信最小样本量；需要另行评估测量
能力，不能承诺在上述预算内必定GO。执行授权与补齐方法卡均为前置。

质量22题、尾部/取消8请求和9项直接合同按原身份复用，**不计入新预算、
不重复运行**。新性能请求仍逐条核对已有参考输出。新差异或实现变化才
单独冻结受影响验证。实现、测试、模型、生产binary及B1b均保持不动。
