## 唯一候选与边界

沿用 [8K 离线诊断](MTP_SUFFIX_8K_DIAGNOSIS_2026-10-23.md) 的机制证据，
只增加一道确定性候选准入，不改 k=3、3–64 token 匹配范围、四候选、
最长匹配与最新平局选择、完整三候选和 d0 门槛，也不搜索次优候选。

在这些原有门槛之后，检查**整个选中匹配段**：若至少含一个 ASCII
数字，且全部字节均属于下列集合，则拒绝 suffix，回到现有神经 MTP。

- 数字：`0x30..0x39`。
- 空白：`0x09..0x0D` 或 `0x20`。
- 标点：`0x21..0x2F`、`0x3A..0x40`、`0x5B..0x60`、`0x7B..0x7E`。

不使用 locale 分类，不引入新的最小长度参数；只含标点/空白而无数字
不拒绝。字母、非 ASCII 字节、其他控制字节、空 token 或不可解码 ID
不视为纯数字格式，保留原准入。该范围不声称覆盖 Unicode 数字。
数字与运算符组成的纯代码片段也可能被拒绝，这是本次需实测的代价。

仅显式 `--mtp-suffix` 时，服务启动用现有 `Tokenizer::Decode({id}, false)`
生成一张全模型词表的只读属性表；不擦除特殊 token，不做子集映射。
每个全局 ID 一个字节，服务所有、请求借用。上限 256KiB；本模型
248320 字节。只对 suffix 配置检查该容量，超出时启动失败。
每次准入最多读 64 个属性，查询时无文本解码、分配或 tokenizer 锁。

请求索引 payload 上限仍为 2MiB（当前容量 208896 时 1884160 字节），
另计对象与新增共享表，不能把共享表从统一 RAM 扣除。共享表构建、
释放与字节数记服务日志；`numeric_checks`、`classified_tokens`、
`numeric_rejected`、`numeric_ns` 记请求日志。`numeric_ns` 包含在
`query_ns`，不得相加双算。`hits` 只统计最后实际采用的 suffix。

GPU verify、checkpoint restore、draft extend、next_d0/next_g、全局
token ID 与取消/槽位生命周期保持。关闭 suffix 时不构表、不扫描。
不增加自适应选择、长度策略、head 量化、PLE 预读或其他优化。

## 有界验收卡

只有一个候选、一轮主阶段，最多 **238 推理 HTTP、18 服务启动、4小时**，
包括直接合同总计最多 20 分钟。不预热、不重试、不扩样、不扫描参数。
普通健康/取消控制 HTTP 单独记录，不混入生成请求计数。若候选接受，
另最多 3 启动/3 推理健康请求（累计 241）；失败不部署。

顺序：

1. 完整 head suffix ON 原 11 题质量，作为第一项测试。必要构建、
   静态审阅、夹具生成不算测试；首门前不运行 host/GPU 合同或 profile。
2. 新 host/准入与阶段审计合同，再子集 ON 11 题质量。
3. 两 head 各两个启动配对块，完整为 OFF→ON、ON→OFF；子集为
   ON→OFF、OFF→ON。每次服务启动固定运行 22 请求：新五档各 3 条
   （15），新四场景各 1 条（4），旧 8K（1），旧 code/text 各 1 条（2）。
   八次服务共 176 请求，全部未插桩。保留每次首请求及实际长度。
4. 同期已交付父程序与候选普通 decode，新五档各 3 条，共 30 请求。
5. 两 head 各控制、显式取消、同槽新请求恢复三条，共 6 请求。
6. 四臂旧 8K 各 1 条独立计时，共 4 请求；仅作诊断，不替代主测量。

质量 22 + 主矩阵 176 + 普通 30 + 生命周期 6 + 计时 4 = 238。
输出上限 256、单流 greedy、MTP k3、max_prefill=8192、max_len=208896。
全阶段同一外层 `gpu_exclusive.py` 持共享独占锁，含测试间隙。
保持已交付 auto 资源预留与自然继承文件缓存，不清页缓存、不宣称
冷 SSD。统一 RAM/NVML/退出过程保留；监控失败或环境竞争记 ENV_ABORT，
仅停止自有进程。合同、质量、身份、超时或资源门首次失败即停止。
性能结果按冻结矩阵完成后统一审查，不因中间弱结果追加或更换请求。

接受条件分开判断：

- **旧 8K 回归关闭**：两个配对块中，每 head 的 ON decode 均不低于
  同块 OFF，并且 verify 轮数和普通尾部工作不增加；不把历史 69/2
  强行当作新输入路径的固定 oracle。原八处数字误匹配须由新规则拒绝，
  实际新路径可能改变步序，不要求运行时恰好记录八次拒绝。
- **重复收益**：每 head 分别检查新/旧 code、text 四个场景；两个启动
  块配对 decode 比的几何均值至少 1.05，且每块均大于 1。不能用
  完整 head 抵消子集，不能用 code 抵消 text。
- **保护**：新五档每档 TTFT/decode、数字枚举、非重复、普通 decode、
  质量、输出及生命周期逐项审查。无统一百分比损失容差；可信回退不能
  被其他收益抵消。新五档不是旧 8K 的调参材料。
- **正确性与资源**：所有新合同/HTTP 门通过，未解决的状态或生命周期
  问题否决。报告匹配/拒绝/接受分布、索引与属性表全生命周期成本、
  verify/draft extend、统一 RAM 和最终吞吐；计时窗口与重叠分开。

两个启动配对块仍不足以自动证明统计非劣。报告各块、请求原值、顺序、
首请求及缓存条件；不把同启动三请求伪装成三次独立启动，也不由噪声
推导允许损失。最终分别记录证据有效性、测量完整性、统计结论与工程
决定。预算完成或失败后停止；只有满足全部接受条件才按已有授权完成
回退包、适用程序/发布元数据、健康检查、文档与提交推送，否则保留
f356 默认程序并归档候选。提交推送不代表优化通过。
