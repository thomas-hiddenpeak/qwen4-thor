# 视觉塔内部计时：有界诊断计划

2026-11-07，父提交0f540480。用户授权继续目标：先定位视觉forward内部
瓶颈，再决定实现方向。本轮只交付诊断能力和观察，不实现优化或接受
性能收益，不替换默认ea1b474d/sidecar3eb46385与任何旧包。

## 冻结范围

`Q4T_VISION_FORWARD_TIMING=1`独立显式启用，默认不创建event、不读时钟，
不改变HTTP响应。按请求记录patch、位置表构造/上传、位置嵌入、两处
LayerNorm、QKV、RoPE、attention、输出投影、MLP、merger与未覆盖间隔。
QKV含bias；输出投影含bias/residual；MLP含两GEMM、bias、激活与residual；
merger含LN、两GEMM、bias与激活，不将这些组合区间称为纯GEMM时间。

CUDA event均放在原stream上，预先有界分配，成功路径仅在原有
cudaDeviceSynchronize后读取；不新增逐层或最终同步。每个端点相对同一
起点计算时间，要求单调，以非重叠区间与残余还原总span。event测量包含
stream间隙/主机提交等待，尤其位置表段不能称纯GPU kernel时间。
位置表主机墙钟另列，含现有blocking copy对之前工作完成的等待，不与
event时间相加。另列event准备/读取墙钟；插桩数据不作未插桩性能基线。

最大8192个event，超出或创建/记录/读取失败时拒绝完整计时，不能把缺失
记0；CUDA错误沿既有设备失败边界处理，不清除错误或降级隐藏故障。
默认关闭无event资源；提前返回只释放实际创建的event，不读取未完成项。
新文件纳入来源身份和serve审计锚点，算术、kernel、流和张量布局不变。

## 验证与停止条件

成组实现后检查CPU事件状态机（关闭、重复阶段、容量、失败、未完成、
顺序/非有限数据、资源释放）、严格解析负控、既有两轮子进程退出合同，
再构建独立诊断程序。复用未变的预处理/HF数值证据；不重新跑全塔参考。

GPU整阶段同一独占租约：最多2次模型启动、12次生成、32次控制请求、
0原生worker、600秒。相同候选先关内部计时、再开内部计时；两边均开
既有流水线墙钟计时以便对照。各6题固定顺序：JPEG地球、PNG舱内、
两者多图、已有正向8帧视频、纯文本42、重复JPEG地球。完全复用之前
请求内容与真值，只变请求ID/取消令牌；记录原件、输入/程序/来源SHA。

所有12题校验答案、JSON/SSE终态、schema、preflight/usage；6组成对
message/finish/usage必须一致。纯文本无视觉计时；5条开启记录必须完整，
patch/层数/阶段次数与冻结几何一致。保留全部E2E和计时正负观察，不宣称
零开销、统计非劣或五档优化接受，不以不确定性追加采样。

启动/请求/时长预算用尽即结束；具体失败只在剩余额度内修复受影响项，
原失败保留。竞争或监控失败记ENV_ABORT，仅清理自有进程，不停其他服务。
核对两模型退出/回执、GPU、18146和原共享锁；不留自动恢复或常驻服务。
结束后独立从原始HTTP、计时和guard日志重建，不仅相信驱动摘要。

输出各输入的主耗时段、规模变化与源码解释；attention若占主导则提出
最小数值安全的后续候选，若GEMM占主导则检查对应形状。结论不自动授权
实现下一项优化。nvJPEG、视频硬解码、视觉并发和长稳不扩展。

CUDA事件语义依据[NVIDIA CUDA 13.3 Event Management](https://docs.nvidia.com/cuda/archive/13.3.0/cuda-runtime-api/group__CUDART__EVENT.html)。
