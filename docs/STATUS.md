# 当前状态

更新：2026-09-20。代码是实现事实来源；验收规则见 [EVALUATION.md](EVALUATION.md)。

## 当前目标

先完善 runner，建立可复现的单流普通 decode 基线，再决定数据流引擎演进顺序。
保持当前精度、不造成性能回退的复杂度降低也属于有效改进。

主模型位置元数据改动已接受：质量 11/11、性能 15/15、聚焦数值检查通过，
五档 decode 提升约 4.85%–7.17%，此前固定矩阵的历史速度差距已追回。
当前工作分支可作为合入 main 的阶段候选，尚未合并；下一步建立真实 E2E
负载上的阶段时间账，再选择后续优化，不等待数据流引擎重写才形成基线。

## 数学修复阶段记录（本次简化之前）

- 原生模板检索题 11 条：旧版 6/11，固定顺序+并行归约版 7/11；原先正确的
  六条全部保留，但 8K/44K/200K 仍有失败。实际输入长度全部达标。
- 失败期间暂停数值细分析和最终性能验收。8K 同三题分别用 max_prefill
  8192/4096/2048/1024 重放，输出全部相同，暂不支持大块 prefill 是原因。
- 静态对照官方模型实现和 tokenspeed：索引器 Gemma RMSNorm 漏了权重的
  +1；主注意力及索引器 RoPE 符号与官方相反。另有索引器归一化后跨 warp
  读取缺同步。同步单独修复后短题仍 7/9；仅补 +1 后恢复为 9/9。
  后续分别修正 RoPE 方向、QSA 仅追加未完成组尾部，各自首测均为 9/9。
- serve 已读取 generation_config.json 的停止 token 列表，同时识别 im_end
  和 endoftext；PLE 历史填充仍使用原主 EOS。完整首测 **11/11 精确正确**，
  包含 44K、200K，实际长度匹配、正常 stop、服务退出 0。
- 五档同输入各三次复测完成：15/15 成功、长度达标、每档输出一致、退出 0。
  当前 1K/4K/8K/44K/200K decode 为 15.507/13.992/14.617/14.308/13.776 tok/s，
  比旧版同输入低 0.36%/1.73%/1.35%/0.88%/1.10%。**不声明整体优化完成**。

- 当时旧 CPU oracle 已修正并新增索引键检查，编译零警告但未执行；性能门禁未通过，
