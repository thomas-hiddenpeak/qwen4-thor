## A：host exporter接入

当前`tools/serve_host/observer.py::prepare`只接受v5/v6资源包；
`source.evaluate`仍使用默认严格资源采样，`core.snapshot`要求四项
普通统计均为整数。仅放开包版本会重新引入管理器查询依赖，并把
v10允许的统计未知误判为整个数据源失效，因此须同步修改投影。

1. 新观察包明确绑定v10后端清单及必需源码；旧观察包和旧资源包
   不重打、不改写，保留现有版本的来源校验和严格行为。
2. v10运行期观察直接核对cgroup身份、成员、限额及关键事件，
   不重新依赖systemd/D-Bus查询；启动/终态身份约束不得绕过。
3. 普通统计缺失在JSON中明确未知，Prometheus不伪造数值零，
   增加有固定取值范围的可用性表达；现有有效性指标含义须明确。
4. 当前可用性与监督器历史缺口分别记录。只读取已有历史计数，
   不把每次抓取再累加为后端故障；恢复不清零，不重复计数。
5. 生命周期、readiness、数据新鲜度与资源统计完整性分别表达。
   保留30秒过期、未来时间、重启代次和历史终态的校验。
6. exporter退出或日志/快照失败只影响观察器；不得向模型发送
   信号，不得自动激活、重启模型或接管未确认的旧代次。

CPU覆盖：v5/v6/v10包矩阵及篡改拒绝；管理器不可用但内核证据
有效；普通统计缺失/恢复；关键事件缺失/OOM/限额或身份漂移；
过期/未来时间与旧终态；缺口计数不重复；观察器失败不触及后端。
必要时使用已有固定nginx/promtool做配置及指标规则检查，沿用
原入口`umask(077)`，不启动生产监听或通知外部人员。

## B：语法worker有界回收

当前`src/server/grammar_process.cpp::Stop`发送SIGKILL后执行
阻塞`wait4(..., 0, ...)`；请求的编译/传输期限不能覆盖该等待。
现有`chat_generation.cpp`回调又捕获请求上下文，因此不能只把
wait4改成后台等待后直接保存所有回调。

1. 使用单调时钟、非阻塞等待和固定清理期限，保留pidfd身份；
   清理超时明确返回“回收未确认”，不伪造退出状态或释放容量。
2. 活跃与未回收worker共用固定容量约束，创建前预留槽位。
   首版保留一个语法worker槽位；旧进程未回收时拒绝新建，
   不通过创建替代worker、线程或更换PID记录绕过容量上限。
3. 延迟回收状态归属进程级生命周期，不保存请求栈引用；后续
   非阻塞确认回收后只结算一次计数、报告和容量。错误等待、
   重复停止、析构及服务收尾均不得重复释放或无限等待。
4. 依赖语法worker的请求在容量不足时明确失败，不降级成无约束
   文本；不依赖它的普通聊天保持原准入规则。真正资源/模型故障
   仍按已有保护处理，不自动重启模型。
5. 清理期限、容量及错误码在实现前固定到对应合同；CPU注入
   接口不得成为线上可绕过隔离或抬高资源上限的配置入口。

CPU覆盖：正常回收、超时、取消、短读、闭端写入、重复停止；
可控注入“尚不能回收”与等待错误；请求结束后回调生命周期；
连续失败的进程/FD/容量上限；延迟退出后一次结算与准入恢复；
结构化请求明确失败而普通请求路径不受辅助故障牵连。
真实CPU子进程用于验证可终止路径，注入用于验证不可回收状态机；
不制造真实内核D-state，也不宣称证明内核进程可被限时杀死。
