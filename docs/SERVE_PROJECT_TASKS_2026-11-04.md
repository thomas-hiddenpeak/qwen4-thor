# SRV-11：项目查询的持久任务与显式恢复

本批推进已经选定的只读项目资料查询场景。现有 v1 journal 只提供
恢复判定；新 `tools/project_tasks` 入口提供持久幂等键、客户端隔离、
进程退出后的执行恢复及未知结果的显式处置。不修改 v1 原件或默认
ELF，不把 serve 的活跃 request_id / session_id 当作任务数据库。

## 固定合同

- 本地可信操作员为每个客户端提供私有 0600 profile：TLS origin、
  真实连接 IP、CA、独立 API Key、client_id、模型及 protocol/template
  身份。仅受控 LAN/loopback TLS，不跟随重定向、不读取代理环境。
  client_id 是此本地受控入口的配置，不是接受远程用户自报身份的 API。
- `(client_id, idempotency_key)` 在私有 store 内唯一。相同键/合同
  返回已有任务状态；不同问题、预算、绑定或来源冲突拒绝，不能覆盖。
  完成任务重复提交不再发送 HTTP 或执行工具。新任务由 submit 执行，
  旧未完成任务必须显式 resume；未知状态的 resume 不做网络/工具操作。
- 每任务独立 flock，一次只有一个写者，不锁住其他客户端任务。
  SQLite rollback journal/FULL、完整事务及哈希事件链保留状态；模型
  请求/工具开始先提交意图，完整 wire+EOF/工具结果持久化后才能推进。
  单次任务 2..8 请求、1..32 工具尝试、最多16次显式运行；请求最多
  512 输出 token，wire/event 各1MiB，最多192事件，不自动扩预算。
- 已知工具结果精确复用原内容/源 SHA/引用，文件更新不会悄悄重新读。
  整批参数校验后仅执行尚未开始的允许工具；完整批次才能回填历史。
  保存后的完整响应可继续处理，不重新生成该轮。截断、未知工具、
  引用失败等不能成为任务成功；全部资料读取失败标记 UNVERIFIED。
- REQUEST_UNKNOWN 保留原 request/cancel 凭据和现存 wire，不把部分
  输出当答案或工具参数。显式 `discard-request` 只丢弃该未知输出，
  不声称请求未执行/取消成功；后续 resume 使用新凭据并继续扣原预算。
- TOOL_UNKNOWN 不自动重放。显式 `repeat-read` 仅适用于固定只读查询
  allowlist，原未知尝试继续计额，新读取结果可能因文件更新而不同。
  处置必须携带当前 revision 和原因；旧 revision/预算不足拒绝。
  `abandon` 明确终止未完成任务，不修改或抹除历史。
- profile/ledger/wire 含私有请求、结果和取消凭据。CLI 不打印 API Key
  或远端错误正文；查看任务答案和修复权限属于本地可信操作员。
  不声明同 UID 安全隔离、通用 exactly-once、断电/硬件故障耐久性。
- store 显式新建，默认最多16任务、可选1..64；每任务 DB 最大32MiB，
  wire最多8MiB，加 rollback journal 计80MiB保守目录预算。任务创建
  前检查空间；不自动删除终态/未知任务，否则幂等键可能丢失。此预算
  不是文件系统硬 quota。迁移、归档后仍保持幂等键、跨机器协调另立合同。

## 验证与边界

先成组 CPU 验证：重复键/冲突/隔离、真实读取、结果复用、未知请求
和工具处置、预算、失效引用/截断/业务错误、目录身份、完整 wire、
实际 SIGKILL、新进程恢复及未提交 SQLite 事务回滚。CPU fixture 不
开 HTTP/GPU，原失败保留，仅修复受影响项后定向重验。

之后冻结单次真实模型/TLS短验，覆盖应用进程中断后的已知结果复用、
未知只读结果的显式处理和重复提交。真实驱动及准确预算在 CPU 通过
后单独冻结；全过程使用生产后端的同一 GPU 租约，先停网关再停后端，
记录真实工具/引用与业务时延，不作性能优化结论。

不执行用户小时/day计划，不安装常驻服务，不开放实际LAN。该阶段
不能代替应用队列/远程任务API、多机任务库、正式访问策略或长稳。
