父版 5d560f5。证据 `.q4t-work/e2e/vision-score-barrier-20260921/`。
本轮已接受；容量缩减候选的原始证据在
`.q4t-work/e2e/serve-logits-capacity-20260921/`，运行时补丁已暂存。

## HTTP 暴露的问题

父版正常调度与禁用调度器的内联 decode，两组真实 EvalScope HTTP
均复现：相同显式模板单图、双图、视频请求各三次，生成文本不确定。
无模板的原单图请求则三次立即停止，不能提供生成性能样本。
全部原始请求、响应、用量和失败记录保留，未通过换输入覆盖异常。
显式模板绕过了 serve 仅拼接 role 前缀的现状，不代表普通 messages
的模型模板支持已修复。

## 源码原因与最小改动

`src/vision/vision.cu` 的 AttentionKernel 在共享数组 s_score 中存放
原始 QK 分数。每个线程扫描全部分数求 row_max 后，部分线程立即
原地写入 exp。扫描结束与覆写开始之间没有 CTA barrier，先完成的
warp 可能覆盖其他 warp 尚未读取的原始分数。

候选仅在 row_max 扫描之后增加 `__syncthreads()`，让所有线程读完
原始分数后才能写入指数值；公式、归约次序、布局与分组不变。
这是静态竞态依据，尚不能代替修复效果和精度的运行证据。

## 验收范围

必要零警告构建后首先运行真实 HTTP：质量 11/11、五档性能
15/15，对直接父版和固定参考无不利范围分离。随后视觉四组
48 请求，候选重复及重启后一致，父版三类生成仍非确定，候选
性能没有不利范围分离。原始立即停止请求未计视觉生成性能。

全部 HTTP 通过后才运行实际 attention 的解析逐位用例及扩展
完整视觉塔参考。旧 reference 只有每时间组 4×4 个 patch，分数
覆写者集中在一个 warp，不能充分覆盖本次跨 warp 竞态；新增
16×16 图像与每组 8×8 视频，沿用原 NumPy 参考和误差条件。
解析用例覆盖 S=64/256/1024、时间组 1/2，各五次；Q/K=0、有界
整数 V 和二次幂 S 使均匀注意力运算可精确表示，按 BF16 逐位比较。

## 最终结果

2026-09-21：最终源码、二进制和库摘要一致，原始 HTTP 成功记录
质量 11、性能 15、视觉 48 条已独立核对。解析用例 23224320 个
BF16 值逐位通过。完整塔旧图像/视频相对 L2 误差 0.031691/
0.020551；新增大图像/视频为 0.039954/0.028093，最大绝对误差
0.028735/0.011400，均满足原测试两个 0.05 条件，未放宽标准。
大形状三次原始 BF16 输出逐位一致。

首次完整塔工具误用了不存在的 libq4t_vision.a，链接失败保留在
 tower-numerical；实际视觉实现属于 model 库。修正工具后在
 tower-numerical-v2 完成零警告构建和全部对照，运行时未改变。
本轮接受，固定参考不更新；没有根据此同步修复宣称性能提速。
