# Batch永久输出容量故障的有限终结

承接A09.6与05e05e11实际失败用量组件。该组件已有26项针对性CPU证据，
默认和GPU保持；本项解决另一处真实故障，不把前项完成当作任务终点。

当前代码：Finalize按128行/4MiB每轮保存两条聚合manifest；任一File超过
8GiB或16384块返回binary_capacity_exceeded，BatchJobs会永远重试同一位置。
已有最终检查点可能处在一个大结果行中间。队列配额校验还只允许validating
转failed，正常resources_released又解除原页/结果引用。因此不能简单换状态
或发布当前字节前缀，否则会丢结果、产生截断JSONL或被存储合同拒绝。

## 必做实现

1. 区分硬字节/块容量与可恢复存储配额、超时、未知回执。仅确定的硬容量
   拒绝进入本路径；未知提交回执继续对账，绝不重发模型。
2. 增加可信私有汇总失败检查点，固定容量原因，记录首个无法发布行的边界；重建若仍超限，只允许
   边界向前收缩，不会重复同一失败位置或增加未容纳的行。
   能预先确认整行字节不适配时，不开始复制该行。旧的部分行或最后flush
   块数失败时，可有界地从原结果重建完整行前缀；只重读结果，不推理。
   保持每轮128行/4MiB、公平让出，丢回执/重启沿同一失败检查点恢复。
3. 两条可用的完整JSONL前缀File与failed终态同事务发布，标准errors标明
   容量故障与第一条未发布行。request_counts和usage保留原实际执行结果，
   不伪造未执行，也不把部分File当作全部输出。未发布半行不得逃逸。
4. 扩展配额状态迁移校验，只允许已执行排空、有确定汇总失败标记的
   finalizing进入failed。释放队列token与执行槽，但用独立的期限引用保留
   原始结果页及其依赖，期限沿output_expires_after；到期解除，不无限pin。
   部分公开File仍按自己的到期时间回收；临时暂存必须清理。
5. 集中针对性CPU覆盖：字节上界、块上界、跨轮部分行、原结果/usage保持、
   真丢回执和进程重启、完整行前缀、scope、真实保留/回收、额度释放、
   临时配额不足仍可恢复。内部有界配置用于小体积真实存储夹具，生产
   默认边界保持8GiB/16384块；不追加完整推理/性能矩阵。

之后继续辅助任务所有者初始构建失败的有界恢复，统一真实模型业务、
兼容状态/配额/绑定/结果恢复回退和发行，再推进全部Serve总计划。
本计划不是验收结论；尚未实现的路径仍按未完成记录。

## 当前实现与证据

本组已实现并通过[22项不同CPU检查](evidence/serve-batch-finalization-cpu-20261111/README.md)。首3项读取失败已修，原件保留；CPU结果不代替尚待进行的模型业务与兼容回退发行。上述后续任务及全部总目标继续。
