# MoE 路由元数据持久 workspace

日期：2026-09-21。候选已否决并撤回。质量通过，性能回退，正式基线不变。

## 已撤回候选的改动与容量

`MoERoutedForward` 原来每次异步分配、释放 counts、token_list、offset、
row_of_flat 四张表。48 层普通 decode 对应 192 对调用。候选把四表纳入
已有 MoEWorkspace，尺寸构造与 RequiredBytes 共用计算；模型层容量查询
及 scratch 起点同步更新，专家数量 E 成为必传参数。

激活区域原布局不变，后续元数据按 256 字节补齐。E=512、k=10 时，
M=1 增加 6656 字节，M=8192 增加 17109248 字节（约 16.32 MiB）。
这是 routed workspace 查询增量；不是整个模型实际占用增量的实测，
模型共享 scratch 取各模块容量最大值，还需考虑原异步分配池的保留内存。

## 生命周期与边界

每次先清零 counts，构建 token_list 后仍回传计数并同步 caller stream。
专家额外流只读取对应有效列表、写各自 dn_out 行，原事件汇合留在
combine 前。正常成功路径在同一 caller stream 复用 workspace，覆盖
数据前遵守原流顺序；没有新增全局缓存或数学变换。

仍保留每层一次计数 D2H/同步、host 前缀和、逐专家 GEMM 分发。
此改动不解决并发使用全局专家 scratch，也未扩大错误路径恢复保证。
只减少资源管理调用不能推导吞吐收益；以完整 HTTP 结果决定接受。

## HTTP 结果与决定

必要构建零警告，第一项测试为真实 HTTP 质量 E2E：11/11 通过，
包含 200K；输出与参考一致、服务退出 0。随后正式五档性能矩阵在
完成 1K 后出现明显回退，因此于 4K 执行期间停止。客户端退出 143
来自主动 SIGTERM，并非服务崩溃；服务退出 0。4K、8K、44K、200K
不记为性能通过。没有运行单测、bench、profile 或其他前置测试。

同一 1024-token prompt，greedy、MTP 关闭、输出 256、每组重复三次：

| 版本 | decode tok/s | 三次范围 | 平均 TTFT 秒 |
|---|---:|---:|---:|
| 已接受基线 | 16.893 | 16.825–16.936 | 0.850 |
| 持久化候选 | 11.330 | 11.312–11.341 | 0.857 |
| 旧二进制现场复测 | 16.914 | 16.816–16.968 | 0.847 |

decode 使用总生成间隔计算的速率（等长时等于三次速率调和均值）。
三组输入及输出摘要一致。候选约 -32.93%，远超基线重复波动；旧版
现场复测恢复，支持候选性能回退判断，不支持环境整体降速解释。
未采集候选低层性能，具体原因未定位，不能把地址变化、缓存冲突、
分配器同步或专家流重叠等可能性写成结论。

决定：撤回四个源码文件的候选改动，保留正式参考；不以减少 192 对
调用的静态估算抵消实际吞吐回退。下一轮先审查布局和生命周期耦合，
形成更小、可解释的实验，再重复 E2E；不直接推广到其他模块。
