# Serve总目标重审：补齐能力，持续执行至全部计划完成

2026-11-08，按用户对上一版目标的纠正重新配置。本文件是当前总计划；
原R1—R10成为其中的可靠性任务，不能再作为整个服务目标的范围上限。

## 必须纠正的目标原则

1. **现状限制是待解决问题，不是自动免责条款。** 当前只支持greedy、
   单choice、有限schema和Chat子集，不等于这些就是项目最终目标。
2. **去掉外部强依赖，必须补回项目需要的原生能力。** 原生TLS/LAN、
   证书管理、浏览器接入、客户端治理等有实现任务；nginx可选指实现
   路径可选，不是把对应能力也删掉。必要密码库与外部服务进程分开。
3. **阶段交付不是总目标完成。** 可以分提交、分包和分PR降低风险，
   一个阶段完成后立即推进下一项，不以“其余后置/另立项”停止工作。
4. **有界的是每次验证和故障处理，不是删减问题。** 非性能改动只做
   改进事项及直接受影响行为的验证，不跑完整性能/全模型正确性矩阵。
   测试失败、预算用尽或平台条件不足应保留未完成状态，不能变成通过。
5. **完成必须有实现与证据。** 文档披露、返回unsupported、能力表加
   false、仅加配置开关或保留NO_GO，不等于实现了该项能力。
6. **只有用户可以缩减最终范围。** 新发现的问题入表；确需调整范围，
   保留原问题、原因和用户决定。不得靠改命名/改完成条件把缺口消失。

## OpenAI接口范围与依据

本轮通过OpenAI Docs抓取Chat请求参考、Responses迁移、工具与结构化
输出、Batch及端点目录；Chat参考列出37个顶层字段，端点目录列出
245条路径。这些包含推理服务和组织/账单等不同产品职责，不能将
“OpenAI兼容”含糊等同于所有云平台功能已经实现。

**已确定必做的是LLM推理与应用服务的兼容能力**，包括完整Chat语义、
Completions、Responses、工具、结构化输出、存储会话、文件/Batch和
标准客户端接入。采样、多choice、logprobs、Responses不再放在
“按场景另立项”的排除清单。模型相关输入/输出也列为A10的实际任务，
不能用统一unsupported假装完成接入。

组织、账单、训练管理等云平台API已提出范围澄清，列为G00未决项；
尚无用户答复时继续确定工作，不把它们悄悄排除，也不承诺已支持。
确认后更新端点级清单及总目标，不能改变其他必做项。

兼容以**已抓取的官方协议版本**为起点：缺省/null、请求/响应形状、
事件顺序、错误类型、工具历史和模型能力条件一同核对。新标准字段
纳入变更流程，不让计划变成跟随网页无限漂移，也不能假称“全版本”。
OpenAI自身结构化输出也有支持范围；本项目应实现该范围，而非把
全部JSON Schema方言或任意模型能力当作同一个目标。

4. R03/R04、N04/N05/N06/N07与A08/A09，闭合状态、治理和持久服务。

## 验证规则和预算

- 保留用户最新约定：**非性能改动不做完整性能和完整正确性测试**。
  采样功能需直接数值/统计合同测试，但不因此启动整模型质量或五档
  性能评测；不宣称性能优化。真正优化另按原性能规范。
- 每组先冻结具体受影响用例、来源身份和真实HTTP请求，再成组修改/
  验证；CPU能验证的协议、网络、故障状态与包合同先CPU。纯证书/
  CORS/配置测试可用真实原生入口加CPU后端，真实业务另做对应短验。
- R01现有上限保持1次模型启动/4Chat（含自检）/600秒；其他R组
  复用原表上限。新增组在实施前冻结必要预算，普通协议组默认上限
  2启动/8Chat/900秒；涉及多个profile/后端先具体列项，不能无限扩样。
- 新增组预算不是要求跑满或所有组现在占GPU。真实GPU仍用单阶段
  严格租约；竞争/外层监控失败记ENV_ABORT，保留原件，只清理自有。
- 非性能改动的已过且身份未变证据复用；失败后只重验受影响项。
  已知失败不能以“没有完整测试要求”跳过，测试不足也不等于修好。
- 用户负责长时间稳定性实跑；我们完成开发、针对性短验与可执行
  交接，不擅自开展长稳，不让其阻塞其余已授权实现。
