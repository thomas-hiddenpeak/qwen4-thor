# SRV-11b：持久任务与客户端预算匹配

原任务入口固定512输出，无法匹配已验收的beta=64策略；生成接口拒绝
发生在已提交意图之后，任务只能保留为REQUEST_UNKNOWN。本批补应用
层生成前预算合同，复用当前服务的真实tokenizer/preflight，不修改
默认ELF或放宽Key策略。

## 合同

- 新任务持久保存显式 `max_tokens`（1..512，默认512）及
  `q4t-project-budget-v1`。同键不同输出上限冲突；resume不能覆盖问题、
  轮数、工具次数、流模式或输出上限，不能静默忽略覆盖参数。
- 每轮完整history先通过同一TLS/Key的 `/v1/chat/preflight`。检查模型/
  协议身份、真实prompt tokens、client_limits、上下文余量以及完整
  请求输出上限。available/capped减少时拒绝，不静默截短或自动加预算。
- 预检必须声明不注册请求、不执行GPU、不编译grammar、不操作缓存、
  不预留slot；不把预检通过当作资源预留或成功保证。实际生成仍可能
  因健康、过载、策略变化或输出问题失败，提交后的不确定性合同不变。
- 预检意图、完整成功/失败wire及结果持久记录。输出/输入预算拒绝、
  无效响应和预检传输失败是PREFLIGHT_REJECTED，保留有界错误code/param，
  不消耗生成/工具尝试，不进入REQUEST_UNKNOWN，不自动重试。
- 同进程只提交刚核对且字节合同一致的请求。进程在预检期间或通过后
  退出，显式resume重新预检并换请求凭据，不复用旧准入结论。仅重做
  已证明只读的检查；不重放未知模型请求或工具。已存结果仍精确复用。
- 每任务最多16次显式run（包括能力查询失败）、32次预检、256事件。
  新增check wire各最多64KiB，最多2MiB；数据库和rollback journal及
  原wire合并仍在原80MiB逻辑目录预算内，不声明文件系统硬quota。
- 旧无budget_profile账本继续可离线核验，不能自动迁移其执行源码
  绑定。源码/凭据迁移和归档后的幂等键保留继续单独推进。

## 有界验收

成组CPU验证现有恢复合同和新增预算/预检：同键冲突、整轮history、
拒绝后不执行、已知结果复用、过期准入不复用、错误定位、真实进程
死亡后重新预检、wire绑定、缺失/伪造资源声明、控制次数以及旧411
记录离线重建。只对具体失败定向修复，失败原件不覆盖。

CPU通过后冻结一次1模型/1TLS网关的真实短验：alpha512、beta64均用
相同业务键查询MODEL并引用；beta512在生成前拒绝；alpha在预检批准
后应用SIGKILL，由新进程重新检查再完成。最多4生成、6预检、4次
能力查询、1应用SIGKILL，64父控制，GPU420秒/总480秒。重复submit
不追加HTTP或工具。完整模型/HTTP阶段由原生产guard持有同一租约，
先停应用与网关再停后端；三份用户day保持，不执行长期验证。

实际结果形成前不记接受。业务质量仍为真实架构值/来源引用和工具
闭环；不以降低预算或变更问题来追求测试通过，不作性能优化结论。
