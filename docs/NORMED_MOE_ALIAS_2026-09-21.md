## 存储关系

DecoderWorkspaceLayout 将 normed offset 设为 moe offset，MoE 物理
区域预留 AlignUp(max(MoEForwardWorkspaceBytes, T*hc*hs*2))。移除
原来的独立 normed carve，combined 与 PLE trunk 随之前移。
MoE 收到的 workspace_bytes 仍为自身原始需求，不修改其内部布局。
HC GEMM scratch 与所有输入/输出保持独立；不新增分配、同步或 stream。

唯一允许的重叠是 normed/MoE。两次 GRRead 的 normed 最后读者均为
inject 投影；gate 独立存放，Write 不再读取 normed。attention 子层
执行时，normed 区域所在的 MoE 存储尚未使用；MLP Read 完成后 MoE
才覆盖它。下一层复用遵循既有 caller stream 顺序。

多 token MoE 默认使用 4 条 CUDA stream（Q4T_MOE_STREAMS 被评估
驱动清除后取源码默认值），辅助 stream 在主 stream combine 前通过
cudaStreamWaitEvent 汇合。因此单流 HTTP prefill 仍会走该汇合路径。
T=1 device MoE 使用 caller stream。候选未改变任何上述同步协议。

## 预期收益与限制

模型 hs=2560、hc=4 下，normed 为 20480*T 字节；MoE 原工作区更大，
删除这份独立区域减少 160 MiB（T=8192）共享 workspace 预算，
已由下文编译容量核对确认；不是整机峰值测量。normed 的数学与逻辑读写次数不变，
没有 DRAM 流量或 L1/L2 驻留收益的证据。地址变化仍可能影响性能。
