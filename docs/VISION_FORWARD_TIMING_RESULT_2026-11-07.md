两个容易误判的点：

- 多图`position_host_ms=8290.910`，对应event区间仅0.158ms。源码在第二
  张图的位置表上传使用原有阻塞cudaMemcpy，主机墙钟包含等待前一张图的
  工作完成。它不是位置表本身消耗了8秒，不能与attention时间重复相加。

  计划获取/首次提交及stream间隙；本轮未继续区分库初始化与kernel，
  不能把整个首请求差值当作patch计算或插桩开销。

## 下一项建议及未证明的部分

下一候选限定为**视觉AttentionKernel的行最大值并行归约**。现在256个
线程都逐个扫描整行`S`个分数；可先改为线程局部最大值加block归约，
减少重复工作。优先保持原QK点积、exp、sum归约、归一化、V累加顺序和
BF16输出，避免同时改执行映射、GEMM后端或精度。

这是源码推导出的低改动量方向，**尚未证明行最大值是attention内部的
主耗时，也未证明其HTTP收益**。当前V累加仍按输出通道串行扫描S个元素，
可能限制后续收益。此轮只确定attention优先级，不实现上述候选，也不
把它扩大为FlashAttention或融合路线。

未来实施需另冻结性能目标与保护项，首先做tools/evalscope HTTP E2E，
收益符合目标后再做完整数值/适用性能验收；不因本次插桩数据就宣布接受。
JPEG、GEMM、位置表、硬解码、并发在本阶段不继续扩展。
