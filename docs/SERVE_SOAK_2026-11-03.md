## 冻结矩阵

入口`tools/serve_soak/stage.py`，两种profile拥有独立plan/execution，
不覆盖、不自动重试、不重启失败模型。复用SRV-17已接受v3包160796c3，
不改C++、生产监督器或默认pair；没有人工内存压力、性能优化或公开
网络入口。临时user unit有独立身份、Restart=no、KillMode=control-group、
RuntimeMaxSec，清理时核对所有权后删除。本轮不安装常驻服务。

| 项 | short，本轮agent执行 | day，交给用户执行 |
|---|---|---|
| 启动与周期 | 1启动/8周期 | 1启动/5760周期 |
| 真实生成/工具 | 40成功生成/8次真实读取 | 28800成功生成/5760次真实读取 |
| 观察窗口 | 至少120秒、最多240秒 | 至少86400秒、最多87300秒 |
| GPU/总墙钟上限 | 600/720秒 | 87720/87900秒 |
| 显式控制上限 | 96，含8次preflight | 24000，含5760次preflight |
| 资源增长包络 | 记录静止样本，不作长稳包络接受 | 固定前16周期预热后判定包络 |
| 小时证明 | 无 | 同一实例第240周期且满3600秒留下checkpoint |

每周期同时发普通JSON、普通SSE、strict JSON/SSE交替三请求；全部
成功后进行真实`docs/MODEL.md`读取和带引用回填两请求。请求ID和
取消凭据不复用。周期起点间隔15秒，慢周期顺序继续，不突发追赶。
每周期还进行preflight、metrics、live/ready；检查累计成功数恰好为
5×周期，grammar恰好3×周期且全部回收，owner/queue归零、slot可用。
整个运行期间后端PID/start不变；任何失败保留原件、停止阶段，不扩样。

生产controller内gpu_exclusive从模型加载前到最终清理持续持有原锁。
竞争/监控失败ENV_ABORT，仅清理本单元，不终止外部业务或删除锁文件。
监督HTTP另用`4*(floor(GPU上限/5)+3)`记保守上限，不冒充实际请求数。
单元RuntimeMaxSec限制driver意外死亡后的最长残留时间；正常异常路径
立即按本单元身份清理，不声称driver被SIGKILL也能即时执行finally。

## 长记录与资源边界

生产guard原两代4MiB轮转保持，独立只读采集保留每代inode直到读完，
再切换到当前文件。超过一代未观察轮转、初始缺段、截断、inode变化、
写盘失败或容量上限均否决完整证据，不把拼接成功等同无损。完整副本
必须含同一lease起止、无竞争记录、时间顺序和≤10秒观察间隔。
每条复制流≤1GiB；资源流≤2GiB/90000样本；整机磁盘保留12GiB，
检查间隔1秒。它是采样安全边界，不是文件系统总量硬配额。

ready后每秒独立读父/子RSS、FD、线程、专用unit cgroup计量/OOM与
MemAvailable；停止前终止该资源采样，停止排空仍由guard/terminal
记录。未知、换PID/cgroup、OOM或超过10秒采样空档均拒绝接受。
整机MemAvailable低于20GiB安全线停止本次测试；不向真实OOM边缘施压。
各计量有重叠，不能相加为独占物理RAM；memcg仍不能代表全部CUDA。

day沿用既有工程包络：固定16周期预热后，静止父RSS+64MiB、memcg
anon+128MiB、FD+2、线程+2。逐轮检查，非测试后选择有利区间。short
不足16轮，不用其平稳曲线冒充包络或小时证明。一次24小时也不证明
任意网络/长期负载、无限期无泄漏、吞吐SLO或物理RAM硬上限。

## 验收与交接

先统一CPU验证实际轮转/UTF-8分割、缺段、截断、容量/观测失败、资源
包络、时间与计数门槛、short/day隔离及临时unit语法；再提交/冻结。
本轮short需要3路并发与真实工具全部完成、完整日志副本、正常stop、
无复起/清理、GPU/原锁释放。所有原件和首轮失败保留，针对性修复后
只重验受影响项。day只准备入口和清单，明确未运行。

通过short后交付运行说明、检查点和停止方法。用户运行day时，仍必须
核对GPU环境与冻结身份。后续代码/默认身份变化时拒绝沿用旧计划，
不覆盖已有execution、不自动重置预算。长稳接受结论等真实day结果，
工业化目标继续保留实际部署策略、物理RAM边界等未完成项。
