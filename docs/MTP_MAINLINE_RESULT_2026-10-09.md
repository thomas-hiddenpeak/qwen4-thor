## 正式入口与支持边界

| 入口/能力 | 本阶段结论 |
|---|---|
| 普通`serve` / `--no-mtp` | 默认保持普通生成 |
| `serve --mtp` | 选择sequential MTP；草稿真实运行、接受/拒绝，target复用普通scheduler B1算术 |
| 显式`--mtp-verifier sequential` | 与上述入口相同；既有115请求按来源/依赖复用，本轮补验单列 |
| 显式`--mtp-verifier t4` | 仍实验；本轮修复完成/终止状态错误，未获得全链路数值等价资格 |
| CLI generate、多序列、媒体MTP | 不在支持范围，入口拒绝；不能从底层API推断正式支持 |
| 精度、模型与硬件 | 既定Qwen3.8 checkpoint、NVFP4/BF16与Thor；配置匹配日志不认证任意权重 |
| 配置 | 文本greedy、S1/slot0/k3、max_len=208896、max_prefill=8192；实验算术覆盖不随正式路径获准入 |
| 性能 | 五档均完成；sequential decode低10.057%–12.032%，未取得相对普通生成提速 |

启动方式：

```sh
./build/q4t serve --mtp --mtp-verifier sequential \
  --max-seq 1 --max-prefill 8192 --max-len 208896
```

退出该功能使用`--no-mtp`。未改变text-v1部署包，不自动激活服务、
升级已有部署或删除工作分支。代码集成回退可使用合并前main提交；
具体主线提交与合并方式须在实际合入时记录。

## 本轮已解决的问题

- 正常MTP入口与已验收的sequential一致；旧日志缺verifier仍按原T4解释。
- prefill停机与入队在同一锁内裁决；已接受的工作必须完成再释放借用资源。
- 共享草稿位置复制接受实际host/device来源，维持流内次序与数据值。
- verify自有上传源活到完成；T4所有提交后的Status出口检查GPU完成，
  失败结果无效、请求进入Failed，禁止沿部分推进状态回退普通生成。
- T4首可达stop作为未消费预测返回，恢复正确前缀，不再extend；
  两类verifier共用输出/上下文尾部规则，保留最后允许输出未被消费。
- 正式控制测试进入常规入口；历史研究失败保留为显式诊断，未改断言。
- foundation独有文档/证据与原日志已合入同一分支；无重复实现和新分支。
