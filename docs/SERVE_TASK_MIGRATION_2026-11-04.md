# SRV-11c：显式任务源码升级与同客户端Key轮换

任务绑定整个执行实现及私有Key指纹；升级后原任务会拒绝继续。工业
运行需要保留历史和预算的明确迁移入口。本批不自动迁移、不更新
旧meta/响应/工具结果，也不借迁移重放未知模型或工具。

## 合同

- 本地可信操作员使用新profile生成私有迁移计划，再携带计划内容的
  SHA256显式apply。计划绑定原store路径/dev/inode/store_id、任务ID、
  revision、完整任务合同、已用次数和全部原文件SHA；过时计划拒绝。
- 仅登记已经验收的SRV-11（0f8418e9）与SRV-11b（dc2c18d0）精确
  运行源码集合到当前实现，或当前实现的同客户端Key轮换。未登记
  源码不通过用户提供任意摘要绕过，必须审查并增加适配/验证。
- 仅可更新运行源码、Key指纹，以及旧任务启用budget-v1逐轮预检。
  client_id、TLS origin/IP/CA、模型/protocol/template、问题、流模式、
  输出上限、模型/工具预算不变。Key对应的服务器client映射由可信
  运维配置负责，单凭本地profile不声称获得远端身份凭据证明。
- apply独占原任务锁，单次SQLite事务追加migration事件；旧meta及
  历史事件/响应/结果不改。迁移前后计数、阶段及未知状态保持。保存
  的预检批准仍在resume时重新检查；旧任务后续生成也先做预检。
- plan/apply不发HTTP、不执行工具、不启动服务；apply可重复确认同一
  receipt，不再次追加。迁移提交前后进程死亡可分别按旧状态/已提交
  事件继续，不自动猜测模型执行结果。每任务最多8次迁移、仍256事件。
- inspect/submit/resume/resolve使用事件链推导的有效合同；原Key绑定
  不能继续调用新绑定任务，相同业务键与新有效合同仍返回原任务。
  任务容量与预算不因升级重新计数，不复制成新任务绕过幂等键。
- 适配有界历史格式，不保证任意版本通用迁移；未来源码仍需登记。
  不声明断电/硬件故障耐久、零停机Key轮换、CA/模型/协议迁移或多机
  数据库迁移。撤销Key的实际方式仍为准备新网关包、停止旧网关、再
  显式运行新包；不删除或修改既有验收包、Key文件和用户day。

## 验收

先成组CPU：实际旧账本/响应来源重建、旧/新格式迁移、已保存结果
复用、未知状态不重放、终态/幂等键、预算/客户端/模型/CA不变，
未知源码拒绝、过时/篡改计划、独占冲突、有限迁移次数、提交前后
真实SIGKILL与新进程核对，以及原411/263原件独立离线重建。

通过后冻结一次短验：1模型、2依次运行的TLS网关；真实旧实现各
启动1任务并在保存工具结果后SIGKILL。旧SRV-11任务同时升级/轮换
alpha Key，旧SRV-11b beta64任务升级源码。旧网关停止后启动仅轮换
alpha测试Key的新包，旧Key须401；两个原任务迁移后各只生成最终
答案，复用原工具结果和预算；重复迁移/submit不追加执行。

最多4生成、2真实工具、2应用SIGKILL、3预检、4成功capabilities加
1次旧Key拒绝，64父控制；GPU420秒/总480秒。同一生产guard持锁，
先停应用/网关再停后端，保留失败原件。业务质量仍为真实MODEL架构
值与来源引用；不改问题或放宽预算，不作性能优化结论。三份day不跑。
