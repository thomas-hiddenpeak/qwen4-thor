# GRRead down/up 暂存迁移候选

日期：2026-09-21。状态：已接受；完整 HTTP、数值、布局及时间线检查通过。
直接父版 c8e8331；固定性能参考 fcb5925。

## 改动与生命周期

主层每次 GRRead 的 down/up 从临时 cudaMallocAsync 分配迁移到模型
共享 workspace 中的视图。与 normed 一起借用 MoE 区域：Read 时三个
视图互不重叠，MoE 开始时才允许覆盖整区。HC GEMM scratch、mixed、
residual、combined 和 gate 都在此区域之外。原有辅助 stream join 不变。

容量与 forward 使用同一布局构造，lowrank 取 attention/MLP 两组实际
权重的最大值。公开容量 API 的默认值仍为目标模型的 320，模型加载路径
显式传入真实 lowrank。head/MTP 保留默认动态分配路径，本轮不声明其
独立 E2E 验证完成。

HyperConnectionMixScratch 不拥有指针。调用者负责存储有效期与不重叠；
混合函数检查空指针及容量，不释放借用存储。gate 仍由 GatedResidualFrame
持有，跨子层有效，Write 后释放；未引入借用 gate 或额外所有权标志。
数学 kernel、运算与舍入顺序不变，但仍须独立数值验证。

## 资源变化与结论边界

主层 48 层、每层两次 Read、每次两个临时数组，预计每步减少 192 对
异步分配/释放。先前时间线为每步各 554 次，本轮实际确认降至 362 次。
编译容量核对证明共享 workspace 不增长；吞吐按持平理解，
没有整机峰值测量。该接口增加借用/拥有分支，不能直接宣称净复杂度下降。

## 时间线与接受决定

4K HTTP 的 prefill 分配/释放各 554→362；255 个 decode forward
各 141270→92310，即每步各少 192 次。prefill 的 87703 个 kernel 和
decode 的 442935 个 kernel、逐 kernel 调用数均不变。计数 D2H
prefill=48、decode=0 保持不变。

profile 窗口 prefill 3033.324→3007.320 ms，decode
14470.138→14438.551 ms；采集受 profiler 影响，不用于宣称正式性能提升。
完整门禁支持保留此阶段，固定参考仍为 fcb5925。候选增加了暂存借用
接口与检查，同时把主层 down/up 生命周期纳入统一布局，不把接口数量
增加本身算作复杂度改善。下一阶段单独处理 gate 的跨子层存活期，
不得把 gate 放入会被 MoE 覆写的区域，仍需全套独立 HTTP。
