# 同一token的router与MoE合成参考

## 结论

原4K错题中，固定prefill最后一个token（索引4095），沿48层核对
router投影、top-k、专家分组索引、十个路由专家加权和及共享支路
合成。正式运行时2392f6b1及源码未改。

| 边界 | 实际核对范围 | 结果 |
|---|---|---|
| router checkpoint投影 | 24576个BF16 logits | 15个相邻BF16值不同于FP64参考，均未被选中 |
| top-k选择 | 48层×10个专家 | 独立排序相同；选中logits也同投影参考 |
| 分组行索引 | 480个槽位 | 独立从专家列表/offset重建，全部相同 |
| 路由加权和 | 122880个FP32分量 | CPU逐槽fmaf参考逐位相同 |
| 最终MoE合成 | 122880个BF16分量 | CPU按原归约顺序重算全部位同；FP64参考有1项不同 |

没有把15项或1项差异隐藏为零，也没有设置新的容忍百分比。
本样本未发现路由映射或合成偏离现有计算规则。输入是实际捕获的
上游张量，不能由这些结果宣称整个MoE、整模型或最终答案正确。
原4K答案仍600440，而独立正确答案是360284。

## HTTP先行与采集

独立观测库零警告构建后第一项为tools/evalscope HTTP。
无观测→有观测→无观测各一次，全文均600440，4096输入/7输出，
stop；三个服务0，质量驱动因既有错题均1。MTP关闭、单流greedy，
max_prefill=8192、max_len=208896。不是质量全通过或性能验收。

只读拦截RouterTopkKernel、BuildRowOfFlatKernel、CombineGroupedKernel
及MoECombineKernel，限定T=4096、token=4095、k=10、hs=2560、
48层。保存对应logits/ids/权重、offset和十份专家token列表、
十个实际down输出、routed合成前后、共享down/input/gate和最终输出。
没有捕获整个序列或写设备输入，额外同步时延不用于性能比较。

48份最终metadata全部成功，启动阶段没有采集。层号按路由调用
顺序标记；共享gate向量逐层同checkpoint比对，48个向量的摘要
互不相同，实际向量全部匹配对应层。HTTP核对完成后才做CPU分析。

## 独立计算方法

router投影直接只读checkpoint的BF16 gate.weight，用所捕获的
BF16 MoE输入作FP64点积，再经FP32舍入到BF16。top-k按logit降序、
同值expert id升序独立排序，不使用项目路由函数。
15个投影差异均为相邻编码，均不在top-10内；对应高精度值距两者
中点最多为一个BF16步长的0.000738305。这个观察不是误差阈值，
也不是精确复现cuBLAS内部FP32累加的证明。

softmax单列与FP64数学参考的差异：权重最大绝对差
5.239227487963127e-8，实际权重和范围
0.9999998658895493–1.0000001788139343。未声称CUDA __expf逐位
等于高精度exp；已选中logits一致，未发现本样本的专家选择差异。

对每个槽位，独立在对应专家token列表中找flat=4095×10+slot，
要求唯一命中，再加该专家offset得到分组行。全部同实际row_of_flat；
所有层routed合成前为零。用系统libm的CPU fmaf按槽0–9顺序累加
实际router权重与BF16 down值，得到122880个与实际位同的FP32值。
进入共享合成时的routed仍逐位相同，未出现边界之间的数据变化。

共享合成分别计算FP64门控点积/sigmoid参考，以及按记录的256线程
顺序用CPU fmaf和float32树形相加重算的参考。后者的exp经CPU
计算再舍入，不是直接调用项目kernel或假定等价CUDA __expf。
最终结果转为BF16并比较位模式。

## 高精度参考唯一合成差异

位置为第46层、分量2436：

- 实际BF16为-0.004669189453125；FP64参考舍入为-0.00469970703125。
- FP64合成前值-0.004684451259655338，BF16中点
  -0.0046844482421875，距离约-3.01747e-9。
- 门控点积FP64为-2.2849823111391743；按原FP32树重算为
  -2.284982204437256。
- 只把点积换成后一个值，sigmoid和合成仍用FP64，结果成为
  -0.004684447083674756，已越过该中点并舍入为实际BF16。

因此这个具体差异可以由点积归约精度变化复现，不需要假设未知
误差或放宽门禁。不能把这项具体说明泛化为所有输出差异的解释。
初次细节提取辅助脚本发生NumPy标量位移类型提升错误，保留错误
说明，改用显式uint32数组后读取原数据；未重跑推理或改变参考。
