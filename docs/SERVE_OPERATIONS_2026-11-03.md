# SRV-12 本地运营能力开发与验收合同

长期目标保持“持续推进完善serve到工业水准”。上一轮02d给出约646秒
同PID压力/64轮业务证据，本轮补运营告警、只读诊断与日志/诊断包留存。
不重新定义工业化完成，不把本轮当长稳/整机RAM硬保护/网关鉴权交付。

## 开发范围

保持198运行时/当前默认84d16983/c5203331、protocol aeb66adc不变。
运营能力由标准库Python外置工具、固定Prometheus规则及运行手册组成。

- 固定指标投影：整数不经float损失精度，有限值/标签/缺失/重复与内存
  one-hot检查；未知扩展不导出，观测未知不能当0或健康。
- 只读诊断：只接受直接127.0.0.1端口，依次GET五个控制入口；无代理/
  重定向/自动重试/生成/取消/重启。单HTTP硬截止2秒，全组HTTP10秒、
  16KiB头/256KiB体；记录非原子性质。
- 身份：本地PID/start ticks/boot ID、网络命名空间/监听socket归属、
  executable SHA、发布pair和capabilities/config协议双边核对。跨PID/
  重启/计数减少、前份包无效或超过1小时，不计算计数差值；不伪造0。
- 私有诊断包：目录0700/文件0600、不可覆盖、SHA自校验；不导出任意
  模型名/路径、HTTP头、原始响应或日志。日志尾部最多2MiB，最多512
  个固定字段事件；ID按单包HMAC匿名关联，密钥不保存，不能跨包关联。
  原始服务日志不承诺自动脱敏，仍属于受控运维数据。
- 留存：专用journald namespace模板（256MiB磁盘/64MiB运行态/14天）；
  诊断包默认14天/100份/100MiB，默认只列计划，显式apply仅删除完整、
  本用户拥有的私有诊断包。未知目录/额外文件/符号链接/变化拒绝清理。
- Prometheus固定17告警/2记录规则：失联/缺失、指标未知、GPU、内存、
  非内存未ready、明确禁用、准入、编译、输入及业务错误、接收/写失败、
  owner回收与执行进展。按job/instance分开，正常忙/显式取消不被当成
  GPU故障或资源泄漏；不相加重叠计数，不把错误率/延迟阈值冒充SLO。
- 运维手册覆盖所有规则、信号口径、固定错误code处置、只读取证、受控
  日志访问、未知工具结果不能自动重放；不安装后台监控或发送通知。

## 成组验证与冻结

先完成全部工具与CPU夹具，再以固定版本官方promtool3.5.0 ARM64运行
真实规则解析/时序单测，覆盖触发、for边界、恢复、缺失、禁用、正常忙、
取消、counter reset和多实例隔离；工具只在.q4t-work，未全局安装。
参考[官方告警规则](https://prometheus.io/docs/prometheus/latest/configuration/alerting_rules/)
及[promtool规则单测](https://prometheus.io/docs/prometheus/latest/configuration/unit_testing_rules/)。
版本是本轮固定验证工具身份，不声称为最新部署推荐。

Python测试覆盖边界/未知/身份变化、HTTP慢滴/截断/大小、敏感字段投影、
文件权限/篡改/符号链接/留存拒绝，模型与HTTP均不在CPU夹具中启动。
冻结后一个GPU lease内：实际安装模型普通1次+真实工具2次；三个诊断
包（业务前、业务后与服务停止后），实际敏感ID进入原日志而不会进入
诊断包。临时本机Prometheus加载规则并抓取该服务，验证健康无误报和
服务停机后TargetDown实际触发；此进程只监听loopback、无通知接收器。

计划3生成/0负例/1模型启动，硬限4/2/2/1800秒（first lease至finalize），
不自动重试或扩预算。模型/Prometheus均只清理本阶段创建的进程，最后
GPU释放；CPU/数值与完整64轮证据按原身份复用，不重复完整推理。
通过后封存可核验证据、更新矩阵与日志、阶段commit/push；无需替换
推理binary/sidecar。更长持续运行/重启回退依SRV-13另冻结。
