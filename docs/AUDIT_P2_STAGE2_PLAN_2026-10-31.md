# 审计P2第二阶段：容量准入与执行进度

沿用[总计划](AUDIT_P2_FIX_PLAN_2026-10-31.md)，本阶段是A5/A6正确性
与可靠性修复，无算法、调度策略或性能优化主张。第一阶段权重/驻留
运行时和接受证据按不变源码复用；A8独立留到工具阶段。

## 合同

- A5：普通decode每个活动序列需要一行forward工作区。显式max_seq
  超过有效max_prefill时，在加载tokenizer/模型前拒绝；max_prefill=0
  取ModelConfig的真实默认2048。no-budget、startup-plan off/auto/
  required均不能绕过。独立预算API也拒绝不支持的显式组合，自动
  序列数受forward行数约束；原MTP的B×(k+1)约束保持。
- A6：新增执行完成边界计数，只有成功完成prefill、draft或decode
  工作才增加，使用已有同步边界。请求结束累计generation tokens
  保持原语义。监督器使用执行计数，不能因长请求尚未结束而误杀；
  排队取消/拒绝不能掩盖执行停滞；旧backend缺少该指标时明确失败。
- 直接检查采用真实选项校验/预算API，以及生产supervise循环的
  时钟/进程替身；覆盖超过1260秒持续进度、真正停滞、取消干扰、
  空闲转活动、指标缺失。真实HTTP同时采集在途指标，证明请求完成
  前生产者已上报执行进度。时钟替身不冒充21分钟真实长跑。
