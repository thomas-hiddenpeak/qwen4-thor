和 DN 输入仍用原 per-stream scratch。失败时先 join 已提交的
extra stream 再释放，预算明确增加同等临时费用。

## 冻结验证与数值边界

必要构建后按质量 11 → 有限直接检查 → 正式 15 的顺序执行，
全部首次通过，没有 warmup、额外推理探针、k 扫描或有利重采样。
本 Goal 新 HTTP 共 67 条：前述诊断 41，加本候选 26。

- 固定质量 11/11，含 200K，reference 文字与 prompt exact；
  实际 MTP、正式容量和 batch 预算/路径均成立。
- 10 组 host 开关/形状/counts/布局门禁、3 组预算合同通过。
  batch+v1 在模型加载前按预期拒绝；该预期 exit 1 属测试通过。
- 真实 layer 2 权重、三套路由旧/新各一次，共 6 次正常 forward。
  分别覆盖 40 个 M1、10 个 M4、混合 h1/h2/h3/h4=18/4/2/2，
  包含 expert 0/511、正负/零 BF16 输入和非二进制路由权重。
  有效 GU packed/SF/BF16、DN packed/SF/BF16、最终输出及
  combine、实际 GEMM key/算法/alpha/workspace 均 exact，guards
  通过。按实际 token-list 还原 canonical(token,slot)，不把
  atomic 物理行序或未初始化 padding 当数学值。保存 76 个
  payload 共 28,469,552 B，加 manifest 为 77 文件、28,472,201 B。
- 固定一次 mixed 故障注入，在 extra batch 已提交后返回失败，
  join/free 与后续原计划 mixed forward 复用通过；总共 7 次尝试，
  未注入 CUDA fatal error，也未追加重试。
- 短 k3 保留 16 自然+1 强制步骤，接受 0/1/2/3 draft 全覆盖，
  123 个旧 raw、46,300,139 B 逐字节一致。实际 batch 调用
  1,680 次、提交 6,720 次。该 raw 没有完整跨历史版本
  recurrent/KV 状态，不能将输出一致扩大为完整状态 oracle。
- 8196-token 长初始化保留两次主 prefill(8192+4)、共 10 actual
  k3 steps 与两个固定 probe。Full/batch-off 与 Skip/batch-on
  在内存比较初始化、输出、recurrent 和 MTP KV/indexer/位置
  状态 exact；实际 batch 调用为 0/336。90 个历史 raw 共
  42,733,425 B 逐字节一致，但历史文件只承担其保存的输出范围。
  main 完整 KV 没有全量比较，中间 draft-head logits 未保存；
  draft IDs 与既有输出/状态合同有检查。

数值新增容差为零。以上有限同形和固定 k3 轨迹不能补足普通/MTP
跨形状等价，也不代表所有输入、并发或整模型任务质量已验收。

## 收尾决策与后续方向

本阶段以一个候选收尾：诊断、有限数值和严格性能已形成
可回退边界，第二个候选不是必须名额。跨专家 SwiGLU batch
需要保留多专家 GU 输出并改变提交/排队关系，资源所有权和状态
验证也要扩大；候选开启后没有新的分段证据支持其净收益，因此
本 Goal 未实施它，也不沿用旧 18%–19% gather 区间预测下一收益。

候选原始证据独立复核与最终保护审计均已通过，结果在原工作分支
形成阶段提交。代码实现、第一轮质量/数值记录和最终接受报告分开
保留，不覆盖此前失败记录，也不改冻结协议来迁就结果。
后续若继续性能研究，应先为 batch 路径建立真实且有界的分段
计时合同，再判断剩余主验证调度或草稿路径优先级。默认启用是
另一项工作，仍需处理普通/MTP 跨模式数值与整模型质量边界。
既有 NO_GO 保留，当前有限性能 PASS 不授权 merge 或部署。
