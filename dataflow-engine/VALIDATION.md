# 验证与原型路线

## 1. 先固定语义，再比较速度

保存 checkpoint/源码/构建指纹、环境开关、输入 token IDs、位置、
参考输出与运行条件。当前 runner 保留为对照，另用匹配的参考实现
交叉确认。其历史日志、注释、报告中的硬件加速比都不能替代基线。

报告的 7.6×/4.9× 是特定长上下文 attention 实验，不是 Thor
端到端指标。CUDA Graph 删除 host 提交工作也不保证 GPU 更快：若 GPU
原本没有空闲，价值可能主要在 CPU 占用或后续组合能力。

### 采纳原则：复杂度降低是独立收益

用户于 2026-09-20 确立：**保持当前精度、不造成性能回退时，即使
无法获得性能提升，能够降低系统本身复杂度的改进也可以采纳。**
适用于现有 runner 的演进和新引擎，不把吞吐提升作为唯一工程目标。

采纳需要同时提供三项证据：

1. 保持当前精度与行为合同：覆盖输出、路由、状态演进和错误处理。
   不为简化实现而放宽原有精度阈值、削减功能或绕开边界情况。
   E0/E1/E2 是变更分类，不能仅凭分类或 dtype 相同宣称精度保持。
2. 性能不回退：在变更影响的代表性形状与端到端负载上配对比较。
   包括适用的 TTFT、TPOT/尾延迟、吞吐和内存/容量约束；不以某项
   改善抵消另一项实际退化。预先记录测量方法、重复性和噪声范围，
   报告差值及不确定性。统计上“未显著变差”不自动证明无回退；
   证据不足时保留待验证，不事后扩大容忍范围来通过验收。
3. 复杂度有具体净减少：列出前后状态种类、重复路径、所有权关系、
   分配/同步协议、特殊分支、依赖或配置数量的变化，并说明删除了
   哪些需要长期维护的不变量。新增机制也计入，不能只报删除行数。

可接受的例子：用一个明确的状态提交协议替代多处分散回滚；合并
重复的执行路径；通过明确生命周期删除临时缓冲和配套清理分支。
封装相同复杂度到新类、把显式同步改成隐式同步、把分支搬到配置层，
都不足以单独证明系统更简单。更短代码也不一定更容易维护。

验收结论可为“精度保持、性能持平、复杂度降低：采纳”，并明确不宣称
加速。与之不同，早期新架构允许暂时更慢仅指保留研究原型，不能据此
把有性能回退的版本替换已验收执行路径。

## 2. 数值模式

| 模式 | 允许变化 | 验收 |
|---|---|---|
| E0 | 保持 dtype、舍入点、归约顺序，仅改变生命周期/元数据流向 | 针对对应参考路径做 bitwise 检查；无法满足则明确原因 |
| E1 | 布局、分区/块算法引起归约顺序变化，dtype 不变 | 逐算子误差、长状态误差、router/top-k/greedy 分歧与任务验证 |
| E2 | FP8 residual、FP8 shadow 等表示变化 | 独立质量/性能实验，不与 E0/E1 混报 |

初版以 E0 为目标；split-QSA、GDN chunk 很可能属于 E1。
测试同时给绝对/相对误差、近零处理和 argmax margin。阈值依据匹配
参考的噪声分布制定，当前不杜撰“统一 l2_rel 合格线”。
逐步 greedy 验证能保证基于目标 logits 的接受规则，却不能掩盖
batched target 与单 token target 在有限精度下的差异。

## 3. 必测不变量

| 范围 | 用例与断言 |
|---|---|
| GR | 提前 inject 与原实现对齐；4 分支、zero-centered gain；down/4 在 SiLU 前 |
| GDN | chunk=1/3/4/5/31/32/33 与连续执行；长串状态、conv 原值历史、head 分片 |
| QSA | L%4=0/1/2/3；长度 2047/2048/2049、8191/8192/8193；精确完整块集合与 tail |
| QSA split | 空分区、少于512块、512块以上；softmax 合并、padding、同分 tie |
| index 生命周期 | 缩小压缩表后评分范围不越界；跨 chunk/epoch raw tail 无污染 |
| MoE | 热专家偏斜、全部 token 同专家、稀疏专家；per-expert scale；slot 归约确定 |
| PLE | EOS 历史、跨页行、重复行、冷/热缓存、迟到完成、取消/slot 复用 |
| Head | 最后一行结果；greedy ties；完整 logits 请求不能误走 token-only |
| 多序列 | seq_id 不等于 batch 行号；不同 L；重排、退出、slot 重用、generation |
| MTP | k=1/3/5；a=0/1/k；跨四元组边界；draft/main shifted alignment |
| MTP 事务 | SSM、两种 conv、KV/index、raw tail、历史和 cursor 一起提交/恢复 |
| 取消/失败 | I/O 失败、epoch 取消、已提交主干但 draft 修复失败、无法恢复的 GPU 错误 |
| 输出结束 | EOS/stop/max_tokens 在候选中间；pending 与 sent cursor 不重复/遗漏 |

GDN rank-one log 单独测试：记录实际更新值，从基点逐步重放，与每个
完整 checkpoint 比；先测状态再测输出。不得只测 a=k（该场景不用恢复）。

## 4. 工作负载矩阵

| 计划 | 首轮实验维度 |
|---|---|
| D | B=1；N=128/8192/32768，262144 在准入预算通过后再跑 |
| P | N=8192/40000/200000；C=128/512/1024/2048/8192；纯 prefill 与混合服务 |
| S | B=1/2/4，真实 seq_id 打乱；k=1/3/5；异长上下文与不同接受率 |
| 混合服务 | 一个长 prefill + 多个 decode；慢客户端、慢 PLE、请求取消 |

所有点均受真实内存预算约束，不要求一次性全部运行。大形状先从
资源模型审核；不通过则标为容量不支持，不用 OOM 作为探索手段。
预热、时钟/功耗、温度、后台负载、I/O 缓存状态记录齐全。
共享机器上的性能测试须在可解释的负载窗口运行。

## 5. 原型路线与继续/停止条件

### R0：合同与可复核资源账（当前文档阶段）

三份计划推演完成。下一步把节点输入输出、数值边界和 live ranges
做成可机读的计划清单；对基线采集匹配的 trace。此处不先选宣传性的
吞吐目标，也不把现有同步次数换算成虚构加速。

### R1：GRFrame 执行合同

最小闭环：GRRead 提前输出 inject、子层可先复用现有计算、GRWrite
消费 frame。down+inject 合并先做数学与舍入对照；scratch 由 arena
管理。目标是证明所有权和生命周期，随后测 GRWrite→下一 GRRead
融合。验收：不保留跨子层的 normed；资源量可解释；正确性通过。

若为追求单 kernel 导致并行度下降，保留多 kernel 的高效映射。
“frame 已变短”是结构成果，但不能直接算端到端加速。

### R2：两个高价值子图分别试验

QSA 微块布局/紧凑 index + decode split；GDN prefill chunk 状态流。
不在同一实验同时切换精度。每项以旧子图为对照，检查时间、字节、
状态和长上下文质量。如果 extra staging/reduction 抵消收益，记录
适用 shape 或撤销该映射，保留模型级合同。

### R3：GPU MoE 工作列表

构建精确活跃专家描述符，比较 descriptor/grouped/persistent 执行
与现有库映射。既检查 host 退出逐层路由的结构目标，也检查端到端
关键路径是否改善。硬件 FP4 路径、scale swizzle、instruction cost
和 occupancy 必须一起测。手写与库都可作为后端，以实测选取。

### R4：完整三计划与调度

D/P 先完成端到端，S 先用完整 checkpoint。混合负载验证 chunk
边界让出、公平性和 I/O 背压。再独立引入更新日志、MTP Selection
复用、FP8 residual。每个实验有单独开关、参考结果和预算变化。

首次新引擎不要求超过旧 runner；要求没有未解释的额外整张量拷贝、
逐层动态分配或无界队列，且数值与状态合同可检查。性能落后要用
trace 说明原因和可证伪的下一步；没有改善证据的复杂度不继续累积。
改善证据包括按上述原则验证的复杂度净减少，不限于速度提升。
