# Serve logits 容量：消费者与验收合同

2026-09-21。父版 5d560f5，候选证据
`.q4t-work/e2e/serve-logits-capacity-20260921/`。当前未接受。
代码决定行为；本文件记录本轮范围，不是已经完成的验证结论。

## 消费者核对

共享 `d_prefill_logits_` 的所有 forward 和 D2H 均受 `model_mu_`
串行保护。调度器停止/销毁顺序保持，缓冲不借给请求线程异步持有。

| 调用路径 | head 写入需求 | host 消费 | 候选行为 |
|---|---|---|---|
| 单序列短 prefill 调度 | 一行 | 行 0 | 保持已接受末行模式 |
| 多序列短 prefill 调度 | B 行 | 按打包顺序读取行 b | 保持已接受每序列末行 |
| 长文本 chunk 调度 | 仅末块一行 | 行 0 | 保持已接受末块模式 |
| 内联短 prefill | 一行 | 从旧 T-1 改为行 0 | 显式末行模式 |
| 内联长 prefill | 仅末块一行 | 从旧末块尾行改为行 0 | 中间块不计算 head |
| 图像/视频 prefill | 一行 | 行 0 | 主干/视觉注入不变，仅选择 head 行 |
| MTP 主模型 prefill | 一行 logits，另需全行 trunk | 行 0 与独立完整 trunk | 不裁剪 trunk，不修改 draft/verify logits |
| 调度器不可用时普通 decode | 一行 | 行 0 | 保持原实现 |

MTP draft/verify、调度器 decode 的 logits 缓冲不是这块缓冲，不能
从本轮主模型 prefill 行需求推导它们的容量。非 serve 模型 API 默认
全行语义保持；`LogitsRows`/`PrefillBatchLogitsRows` 仍显式选择输出。

## 容量与预算

令 V 为 vocab，P 为 max_prefill，S 为有效 max_seq。原共享容量
`P*V*2`，候选 `S*V*2`；正长度批量中的 B 不大于 S，所有单请求
路径只写一行。8192/248320/1 时，4068474880→496640 字节，
差额 4067978240 字节（约 3.789 GiB）。这是分配请求大小，尚未
测量整机峰值、实际驻留页或 CUDA 内存账，不将静态差额当作实测。

预算器移除旧固定 prefill logits 项，在每序列池计入两份词表行
（scheduler 与 prefill）和一个 int32 GPU argmax token，取代旧
scheduler 的 500000 字节估计。其余旧 workspace/MTP/状态估计
保持；本轮不宣称完整预算准确。固定测试配置必须核对没有被截短；
自动推导容量的变化需要 HTTP 门禁后独立检查算术和实际分配。

不增加高水位扩容或特殊全行回退缓冲。这样每个消费者的行需求
直接约束常驻容量，但也要求覆盖所有新改为末行模式的请求路径。

## 验收顺序及覆盖

1. 必要零警告构建后第一项为默认 MTP 关闭的真实 evalscope：
   质量 11 题、五档各三次性能，对直接父版及固定参考检查范围。
2. 真实 B=2 组批、长短交错及生命周期。父版已经输出所选行，
   组批观察器须显式使用 parent-selected-rows，不能沿用旧全行间距。
3. 内联短请求、调度器不可用的短/长请求、单图/双图/视频帧、
   MTP 短/长请求，各按父版→候选→父版三次 HTTP 对照。默认纯文本
   通过不能代替这些路径。所有推理均使用 tools/evalscope。
4. 全部 HTTP 后才进行数值、实际容量与预算算术、时间线核对。
   修改 M 维的路径不能仅凭请求成功判定精度保持。

调度器不可用通过独立 preload 合成一次分配失败，并确认日志确实
命中 scheduler logits 分配且未启动调度线程；不是制造真实 OOM。
仅 Q4T_NO_BATCH_PREFILL 不会关闭长文本 chunk 调度，不能覆盖该路径。
MTP 必须观察实际 MTP scheduler step，初始化/分配失败退为 plain
不能算 MTP 覆盖。视觉使用已有 PNG 原文件与完整 messages JSON，
保留 payload、实际 usage 和文本。固定请求回归不是全面视觉质量证明。

任何失败均保留原记录，停止下游验证；不拼接有利样本，不临时设
容忍百分比，不用数值/profile 覆盖 HTTP 失败。当前质量 11/11
已通过、服务退出 0；完整五档 HTTP/输出通过，但 4K decode 相对
直接父版不利范围分离，旧→新→旧 HTTP 复核后 TTFT/decode
与两侧范围均重叠，异常未重现。原始结果保留，标准门禁已通过，
下游 HTTP 恢复，数值/profile 未运行，候选尚未最终接受。

## HTTP 后的数值与容量证据要求

以下尚未运行，须等待全部消费者 HTTP 通过：

- 内联长文本对照必须复现旧首块/末块全行 head 与新仅末块末行
  head 的实际策略，逐块比较完整 trunk，并用固定下一 token
  比较后继输出，避免 greedy 近分差异掩盖状态问题。MTP 消费完整
  trunk，不能只比较最后一行 trunk 来证明该消费者输入保持。
- 视觉对照使用真实图像/视频 processor 和视觉塔输出，经同一
  多模态展开及 MRoPE 进入完整主模型，比较全行与末行模式。
  现有两层注入 smoke test 仅证明机制，不代替该数值检查。
- 若 logits 非逐位一致，保存共同输入与 head 中间值，沿用已接受
  的同 BF16 权重 CPU FP64 参考方法解释差异；不能仅由 argmax
  相同或临时设一个误差阈值宣称精度保持。
- 容量记录要区分 cudaMalloc 请求大小、实际设备分配与整机峰值。
  预算检查要覆盖 max_seq 的变化和自动推导配置；其余旧预算常数
  不在本轮被隐含认证为准确。时间线需覆盖本轮实际改变的内联
  分块和视觉/MTP 主模型 head，不只复用普通调度路径的旧捕获。
