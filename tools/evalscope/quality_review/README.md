# 有界配对质量评估

本轮比较原版2392f6b1与完整编码修复a984c284，固定120条新合成
工程记录题（8任务/五档/中英文与JSON、自然语言），旧26题另列。
不是通用质量基准或真实业务语料。规则在首条推理前提交6eed24b，
原始退出值及所有损失保留，不能因旧HTTP工具要求全对而混淆
“驱动返回1”和此轮独立配对质量筛查结论。

- prepare.py：新目录生成，不推理。初稿保存；v2改善语言/表示
  组合与版本顺序分配，全部发生在看到任何新题输出之前。
- validate.py：从最终prompt解析每条记录，用独立SQL计算120个
  答案，验证146条精确分词长度及两个原版子集互斥/完整。
- frozen_plan.json：首请求前计划摘要、二进制/数据/工具SHA。
- run.py：复核冻结数据和二进制，依次原版74/修复146/原版72；
  使用现有tools/evalscope HTTP，单服务，不修改部署版本。一个
  工作日截止，超时终止自有进程组，记录未完成而不接受。
- analyze.py：完整配对后才评分，报告全部得失和任务/长度分组。
  总分、8任务、5长度均不降且结构完整才能进入性能验收。中英文/
  表示为预定诊断分组，不事后改变门槛。不声称总体统计非劣性。
- repeat.py：仅主筛查未满足且有损失时，按预定规则选最多8条，
  每版重做一次，不更换原结果、不修改提示词或继续找通过样本。
- finish.py：等待指定collector真实终态后运行分析、必要复查和
  封存；日志始终在prepared父目录，封存时不绑定仍在写入的日志。
- seal.py：逐条复核原始SQLite/SSE请求、全文、usage和stop，核对
  部署未改变，全部来源和最终文件摘要封存。只反序列化本轮自己
  生成的本地evalscope数据库，不用于不可信外来数据库。

各脚本有固定本轮路径并拒绝覆盖冻结目录；新一轮须新目录和新计划。
本轮不自行部署修复、不据质量请求耗时作性能结论。正式性能保持
五档真实E2E要求。详见../../../docs/QUALITY_REVIEW_2026-09-27.md。
